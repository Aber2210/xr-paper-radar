# Signal Scaffolding：解锁轻量自监督单目深度模型的潜力

## 一句话结论
不改架构、不加数据，仅用三阶段 Signal Scaffolding 训练课程，1.5M 参数的 ReForgeDepth 在 KITTI 640×192 上把 Abs Rel 从 0.110 降到 0.102，并在 iPhone 12 上达到 34 FPS。

## 要解决的问题
轻量单目深度长期卡在一条很窄的精度带里：想再往上走，通常只能加参数或加数据（如引入语义分割数据集），这违背轻量化的初衷。作者观察到预训练对轻量网的收益远小于大模型，而主流解释（容量不够）无法解释为什么同为 2–3M 参数的模型精度高度聚集。他们提出另一种归因：瓶颈在「先预训练再直接微调」这套为大冗余网络设计的训练流程，低冗余学生只能吸收其中很小一部分信号。

## 方法详解
整体是 DepthNet（编码器 + 轻解码器）与 PoseNet 联合自监督训练，PoseNet 只在训练期存在。
GMD 把三个连续膨胀卷积块及其 FFN 合并为一个残差块：三条并行深度可分离膨胀卷积分支用各向异性 5×3 核（纵向更长，贴合道路竖直结构），权重由输入门控 g=σ(PW₂(ReLU(PW₁(GAP(X)))))∈ℝ^{3C} 给出并 reshape 成每支 g_j，门控头零初始化使初期三支等权；X̂=X+DropPath(γ⊙FFN(LN(Y)))，Y=ReLU(Σ_j g_j⊙Y_j)，γ 为 LayerScale。
每 stage 末接 DCGI：取局部块输出 L 与下采样 stage 输入 S，用无参池化取带符号高频残差 Ĥ=L−AvgPool₃×₃(L)（不整流，保留双极性），DW-PW 精修得 H，U=L+a⊙H+b⊙S；注意力用 cross-covariance attention（XCA），在通道协方差上做，代价 O(C²)，Q̂/K̂ 为 LN(U+p) 的 ℓ2 归一化投影，τ 可学习；Ẑ_i=L+β·A+DropPath(γ⊙FFN(LN(L+A)))，β 零初始化。
解码器刻意简单（卷积融合 + 双线性上采样 + Sigmoid，输出 1、1/2、1/4 三尺度）。RGB Boundary Residual 把 RGB 转亮度后过固定 Sobel 得 G=(G_x,G_y,√(G_x²+G_y²+ε))，DW-PW 编码为 E，与上采样解码特征 D̃ 拼接融合得 F，Δ_B=σ(W_g F)⊙W_r F，disp₀=σ(u₀+Δ_B)。
自监督目标沿用 Monodepth2：pe=α/2(1−SSIM)+(1−α)‖I_a−I_b‖₁（α=0.85），逐像素取源帧最小以抗遮挡，配 auto-masking 与边缘感知平滑，L_base=Σ_{s∈{1,½,¼}} μ⊙L_p+λL_smooth（λ=1e-3）。
SS 为三阶段课程：① ImageNet 初始化（或从零）；② 光度自监督，先适配目标域；③ 冻结教师蒸馏。蒸馏在 log 反深度域做、先按中位数对齐 q̃=q/median(q) 消除每图尺度，多尺度 k∈{0,1,2}：ℓ_KD^k=mean√(r_k²+ε²)，r_k=log q̃_stu−log q̃_tch，w_k=2^{-k}；L=L_base+λ_e L_KD，λ_e=η·min(1,e/5)，η=0.1，e 为第三阶段轮次（从零线性 warm-up）。训练用 AdamW（wd 1e-2），从零 60 epoch @5e-4 cosine，或 30 @1e-4（ImageNet）+ 30 @5e-5（教师冻结），drop-path 只加在 GMD/DCGI。SS 不引入任何参数、数据或推理开销。

## 实验与结果
- KITTI Eigen 640×192：1.5M 参数、3.6 GFLOPs，Abs Rel 0.102、Sq Rel 3.094、RMSE 6.995、RMSE log 0.160，为轻量组（<5M）最好。
- 同规模对比：Lite-Mono（3.1M）0.107、Lite-Mono-small（2.5M）0.110、MViTDepth-tiny（1.8M）0.111；本文比 LEDepth / PuriLight 的 0.106 低 0.004，用不到 Flex-Small（6.1M）25% 的参数超过它，仅 Flex-Medium/Large 仍在前。
- 1024×320 上仍取得轻量组最好 Abs Rel；Cityscapes 416×128 达 0.091，轻量组最好，除 Flex-Medium/Large 外超过所有高容量基线。
- 跨数据集：KITTI 训练模型直接迁到 Make3D（134 张，无微调），优于所有轻量方法。
- 端侧：MacBook Air M2 17.28 ms / 58 FPS，iPhone 12（A14）29.80 ms / 34 FPS，为同表最高 FPS；Monodepth2（14.3M、8.0 GFLOPs）在 iPhone 上 30.47 ms / 33 FPS，说明 FLOPs 不能预测端侧延迟。
- 三角色消融（Abs Rel）：只做 ImageNet 初始化 0.120；只做光度自监督 0.110；三阶段 + Flex-Large 教师 0.102；无 ImageNet 时 0.117/0.115。
- 教师选择：Flex-Large 0.102 < Lite-Mono-8M 0.104 < DepthAnything V3-Small 0.114，跨域教师反而更差。
- η 敏感性：常数 η=0.1 最好（0.106/0.104），η=0.025 欠拟合（0.108/0.106）；把蒸馏推迟到第 5 epoch 变差；从 0 warm-up 最优（0.104/0.102）。
- SS 增益随学生规模递减：Lite-Mono-tiny 提升 0.005 Abs Rel，Lite-Mono-8M 只有 0.001。

## 创新点与贡献
- 把「训练信号如何组织」当作独立于容量与数据的第三个变量，提出三阶段课程（预训练 → 光度自监督 → 域匹配教师 + 线性 warm-up），不增参数不增数据。
- 蒸馏损失设计为 log 反深度 + 中位数对齐 + 多尺度几何衰减权重，与光度目标并联而非替换，避免教师上限锁死学生。
- GMD（并行多膨胀 + 输入门控 + 各向异性 5×3 核）与 DCGI（带符号高频残差 + XCA 全局通道交互）在约一半参数、少 25% FLOPs 下匹配 Lite-Mono 的 CDC/LGFI。
- 给出可迁移的实证规律：SS 增益随学生规模单调递减、域匹配比教师容量更重要，为轻量模型训练流程提供可检验的假设。

## 局限与风险
- （作者承认）光度一致性在运动物体周围会退化；缺 GT 深度本身封住了精度上限。
- （作者承认）主文只给精简结果，完整表格在补充材料，部分对比（LEDepth、Flex-Medium/Large）的数值在主文不可见。
- （我在正文发现）绝对提升很小：Abs Rel 0.107→0.102 约 4.7%，且仍落后 Flex-Medium/Large；「SOTA」只成立于「<5M 参数」这一子集。
- （我在正文发现）核心论断「增益主要来自学生自身潜力而非教师」只有间接证据（换教师、换学生规模的曲线），没有容量探测、线性探针或损失曲面分析。
- （我在正文发现）端侧延迟只测了 Core ML Float32，没有 INT8/量化、没有功耗与发热，实时性结论不能直接推到量产部署。
- （我在正文发现）无代码与权重发布，复现依赖 Lite-Mono/Flex 官方实现、KITTI Eigen 划分细节与教师 checkpoint，训练随机性对 0.002 量级的差距影响未被讨论。

## 与文献库的关系
Monodepth2 提供最小重投影、auto-masking 与边缘感知平滑，本文的自监督目标基本沿用；Lite-Mono 的 CDC/LGFI 是 GMD/DCGI 的直接对照，作者报告在约一半参数、少 25% FLOPs 下匹配或更好；Flex-Small/Medium/Large 既是对手也是教师，Flex-Large 蒸馏给出最好的 0.102；MViTDepth 与 PuriLight 代表另两条轻量路线（混合 token、频域特征净化），后者 FLOPs 不高但因频域算子在手机上支持差而延迟翻倍；DepthAnything V3-Small 作为跨域教师被证明更差（0.114），支撑「域匹配 > 教师容量」的论点。

## 可复现性（代码/数据/硬件）
数据全公开：KITTI Eigen（39,180 训练三元组 / 4,424 验证 / 697 测试）、Cityscapes（58,335 / 1,525，416×128）、Make3D（134 张，仅测试）。超参写得完整：AdamW、wd 1e-2、60 epoch @5e-4 cosine 或 30+30（1e-4 / 5e-5）、λ=1e-3、α=0.85、η=0.1、w_k=2^{-k}、drop-path 仅在 GMD/DCGI。教师 Flex-Large 权重公开，硬件 RTX 5080（48 GB）。论文未声明代码发布，许可 CC BY 4.0；复现的主要成本在数据预处理与教师对齐。

## 行动建议
若在头显/手机上跑单目深度，可把 SS 当作零成本训练改造先试：固定现有轻量网，只把「直接微调」换成「光度自监督 → warm-up 蒸馏」，用 0.002–0.005 的 Abs Rel 增益判断是否值得。别指望它替代容量提升——增益随模型变大迅速衰减。部署前必须自测 INT8 延迟，论文的 34 FPS 是 Float32。

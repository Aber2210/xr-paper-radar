# OverSeer：超越智能体所见的多智能体世界模型

## 一句话结论
多智能体世界模型 OverSeer：固定位姿辅助相机视图作世界中心状态代理，δ-VAE 仅编码相对参考图变化，MAC-Bench 一致性命标大幅领先基线。

## 要解决的问题
视频世界模型扩展到多智能体时，需要生成多条 agent 特定视频流，并要求时间上与 agent 间双维度一致；agent 视角会因位置微小变化而剧变，模型难以维持对共享世界状态的记忆——当 agent 分离后又重聚时，同伴必须出现在先前观测过的空间位置。缺少一种简单高效的方式，为多智能体世界模型引入持久的世界中心参考。

## 方法详解（含关键公式/架构，保留原文术语）
OverSeer 在多智能体视频世界模型中联合生成两类流：各 agent 的 egocentric 视图 + 若干 fixed-pose 辅助相机视图（论文示例为六个）。核心思想：辅助视图在空间中固定，其变化直接映射世界状态的局部变化，因而可作为 world-centric 状态表示的轻量代理（proxy），对模型施加跨视图一致性与时间一致性约束。由于辅助视图冗余且半静态，用 δ-VAE（delta-VAE）编码：仅编码相对一张静态参考图像的变化，大幅减少处理这些视图所需的 token 与计算开销。模型以初始视觉观测 + 多智能体动作轨迹为条件做未来帧 rollout；并设计消融考察辅助视图数量与 δ-VAE 压缩率对合成质量与开销的影响。

## 实验与结果（表格化关键数字）
主评测在 Minecraft。基准一 Solaris（五项多智能体能力，VLM 判分脚本问题，episode 内须全答对）；基准二自建 MAC-Bench（Reunite at Start / Reunite Far / Dynamic Event，5 次运行平均）。Table 1（VLM accuracy %↑ / FID↓）：Solaris 五项 OverSeer 59.1/18.27、91.7/11.33、87.5/12.95、41.7/32.50、60.4/26.47 vs Solaris 基线 68.8/22.38、66.7/14.92、20.8/47.11、22.9/76.01、56.3/68.42（第二项落后）；MAC-Bench OverSeer 60.2/13.99、37.9/12.79、40.5/17.61，而 Solaris 仅 0.0/17.06、6.2/20.23、12.5/26.52、γ-World 0.0/23.83、0.0/25.71、8.3/31.72。Doom revisit 任务 digest 未含数值；真实多相机数据仅定性；辅助视图数与 δ-VAE 压缩率消融 digest 未含数值（原文有表）。

## 创新点与贡献
- 提出以固定位姿辅助相机视图作为 world-centric 状态的轻量代理，把「世界一致性」转化为可学习的跨视图约束；
- δ-VAE 只编码相对静态参考图的变化，显著降低辅助视图生成的 token 与计算开销；
- 在 Minecraft / Doom + 真实多相机数据上验证，方法不绑定游戏引擎；
- 构建 MAC-Bench（Reunite at Start / Reunite Far / Dynamic Event）专门度量多智能体世界/agent 一致性。

# CrossPressor：可扩展的跨视图融合前馈 3D 高斯泼溅

## 一句话结论
CrossPressor 针对 ZPressor 式 anchor 融合的 representation–fusion mismatch，提出 training-free 的 coverage-cycled evidence routing：在 MVSplat–ZPressor 上 256 视图时 cross-view fusion 从 125.28 ms 降至 4.80 ms（26.12×）、端到端 1.43×，QK 交互仅保留 1.85%，渲染质量几乎不变（PSNR 23.1203 vs Exact 23.1204，p5 ΔPSNR 仅 -0.0063 dB），fusion 峰值内存降 73.8%。

## 要解决的问题
前馈 3DGS 扩展到长多视图序列时，表示规模与跨视图计算都难以 scale。ZPressor 用固定数量 anchor 特征图限制 decoder-facing 表示，但 anchor 固定后每个 anchor 需聚合越来越多的 support views，support 侧 K/V projection 与 cross-attention 随视图数持续增长——即 representation–fusion mismatch：限制了解码端表示规模，却限制不了构造它所消耗的 support evidence。Learned token reduction 需任务特定训练或微调、破坏与已发布 checkpoint 的兼容性；Spark3R 式非对称削减中 anchor queries 已被结构性限制，剩余挑战是控制增长的 support 侧 K/V 序列，同时保留所有 support 视图的证据。

## 方法详解
CrossPressor 只改 ZPressor 的 support-to-anchor 融合阶段，无任何可学参数、无需重训。（1）View-normalized support length：路由目标 N_KV^max = β_KV·T（默认 β_KV=1.5，T=HW 为单视图 token 数），按 cluster 从 {1,2,4,8,16,32,64} 选空间 stride s_c，取满足 m_c·⌈H/s_c⌉·⌈W/s_c⌉ ≤ N_KV^max 的最小 stride；支持视图增多则 stride 自动变粗，每视图保留更少空间位置。（2）Coverage-cycled evidence routing：采样 offset p_{c,v}^ℓ = (r_c(v) + κ·ℓ) mod s_c²（L=6 融合层，κ=5），跨 support 视图递进 1、跨融合层递进 κ，使不同视图与层采样不同空间位置；每个 support 视图仍保留 T/s_c² 个 token，缩减是空间式而非视图式。（3）Pre-projection routing：routing 作用于 K/V normalization/projection 之前的原始 support 特征，被丢弃 token 完全省去归一化、投影与注意力计算。（4）Joint context packing：6 层的 routed context 一次性 Pack 成 [L, Ñ_c, C] 张量，再逐层做各自 K/V 投影与 cross-attention，投影结果不跨层共享。s_c=1 时逐 token 精确恢复 dense ZPressor 计算。

## 实验与结果
在 ZPressor 官方发布的 MVSplat–ZPressor（256×256 输入、6 个 anchor clusters、393,216 个输出高斯）与 DepthSplat–ZPressor checkpoint 上直接推理、不重训；RE10K 1,034 场景 × 8 目标视图（共 8,272 renders），上下文 V∈{36,64,128,192,256} 嵌套协议；ACID 599 场景跨数据集。256 视图主对比（Table 1/6）：Exact/ZPressor PSNR 23.1204、SSIM 0.81310、LPIPS 0.18285、cross-view 125.28 ms、E2E 432.16 ms；+ToMe 保留 QK 1.56% 但 cross-view 317.50 ms（0.40×，反而更慢）；+Zero-TPrune QK 1.60%、6.91 ms（18.12×）但 p5 ΔPSNR -0.1666 dB、worst -1.5052 dB、536/418/334 个场景低于 -0.01/-0.03/-0.05 dB；+CrossPressor QK 1.85%、4.80 ms（26.12×）、E2E 303.18 ms（1.43×）、p5 ΔPSNR -0.0063 dB、worst -0.0478 dB、失败场景 21/2/0。Scaling：cross-view 加速从 36 视图 3.85× 增至 256 视图 26.12×，E2E 1.08×→1.43×；fusion 峰值内存 653.0→170.8 MiB（-73.8%），全模型峰值几乎不变。DepthSplat 迁移：各上下文 p5 ΔPSNR 不低于 -0.011 dB，cross-view 1.06×→2.95×（256 视图 dense fusion 占 MVSplat/DepthSplat E2E 的 29.0%/7.1%）。ACID：p5 -0.0079 dB、worst -0.0410 dB、125.15→5.02 ms（24.91×）、E2E 1.43×。β_KV 敏感度（200 场景子集）：0.5→QK 0.57%/p5 -0.0137；1.0→1.46%/-0.0072；1.5→1.86%/-0.0059；2.0→2.28%/-0.0049；3.0→3.85%/-0.0025。Routing 分解（256 视图，同 token 数同 QK）：Fixed p5 -0.0204/worst -0.1055/N<-.05=10；View-only -0.0064/-0.0640/1；Layer-only -0.0154/-0.1071/2；View+Layer -0.0063/-0.0478/0。36 视图下 optimized packing 与参考路由零差异。

## 创新点与贡献
['识别并命名 representation–fusion mismatch：decoder-facing anchor 表示有界，并不意味着构造它的 support-to-anchor 融合有界', '提出 coverage-cycled evidence routing：offset 跨 support 视图与融合层双维循环，把保留的空间证据分布到所有视图与层，每个 support 相机不被丢弃', 'pre-projection routing + joint packing：routing 前置于 K/V 投影使被丢弃 token 零投影零注意力，6 层 context 一次性打包，实测 26.12× fusion 加速', '完全 training-free、无新参数，s_c=1 时逐 token 精确恢复 dense 计算，可直接挂到已发布 ZPressor checkpoint 上']

## 局限与风险
['加速集中在 cross-view fusion：E2E 仅 1.43×，encoder、几何估计与高斯预测占大头；DepthSplat 上 fusion 仅占 E2E 7.1%，系统级收益更小', 'β_KV 受 power-of-two stride 离散化影响，QK 保留呈阶跃变化，stride 网格可能欠利用预算', '全模型峰值内存几乎不变（fusion 外组件主导）；路由元数据仍随 support 数增长，特征提取等 per-view 操作未改', '评测限于 RE10K/ACID 前向场景与两个 ZPressor 宿主；κ=5 并非扫描中最优，仅作固定选择；更长序列与非 ViT 骨干未验证']

## 与文献库的关系
属前馈/通用 3DGS 效率线，直接承接 ZPressor（NeurIPS 2025）的 anchor 压缩，与 Spark3R 的训练无关非对称 token 削减及 ToMe/Zero-TPrune 互为基线；与库内 pixelSplat/MVSplat/DepthSplat 主干和 3DGS 压缩/加速工作互补——它不动表示与预测管线，只治 support 侧融合的长上下文可扩展性。

## 可复现性（代码/数据/硬件）
project page 为 https://yuhsihu.github.io/CrossPressor （全文未明确代码与权重发布承诺）；实验用单张 NVIDIA RTX 4090（24G）、batch 1，5 个进程 × 20 次交替循环取中位数计时；MVSplat 特征图 64×64、C=128、T=4096，DepthSplat 32×32、C=128、T=1024，均 6 anchor、6 融合层。

## 行动建议
部署长序列 feed-forward 3DGS 的团队应把评估口径从 QK 交互数改为实测 wall-clock 与 lower-tail ΔPSNR，并直接以 β_KV≈1.5 的 View+Layer routing 挂到现有 ZPressor checkpoint 验证；若 fusion 非系统瓶颈（如 DepthSplat 占比 7.1%），收益预期需相应下调。

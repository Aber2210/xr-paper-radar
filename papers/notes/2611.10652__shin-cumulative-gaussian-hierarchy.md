# SHIN：增量式 3D 高斯泼溅的可扩展层级表示

## 一句话结论
用一个可复用 Base 加增量增强层构建 3DGS 层级，SHIN 在 Mip-NeRF360 上以 61/111/200 MiB 三个操作点取得 27.08/27.68/27.75 dB PSNR，Base 到 E1 只需追加 50 MiB（1 Gbps 下 431 ms），且消融显示替换共享排序 BD-rate 恶化 28.6%、改用固定 SH 阶数恶化 63.9%–178.4%。

## 要解决的问题
3DGS 资产要适配不同存储容量与随时变化的带宽，但现有做法假定部署预算事先已知：为每个预算单独维护资产会重复存储，迁移客户端又需传输替代表示。层次细节能从一个共享表示暴露多个渲染状态，却不要求这些状态构成可累加的传输序列，操作点之间移动时已交付数据可能被丢弃。更难的是高斯数量只是存储的一个维度，每个高斯还带球谐系数：给已有高斯更丰富外观就少了字节给新增空间支撑，反之亦然。而已传记录会被所有后续前缀复用，各阶段不能独立优化，构成持久分配问题。

## 方法详解
把 3DGS 模型转成可复用 Base 与可加增强层。每个源 Gaussian i 分配层号 ℓ_i∈{0..T} 与保留 SH 阶数 d_i∈{0,1,2,3}，一旦传输其层、几何与保留 SH 系数固定，只有 opacity 可更新。层级 H_t={i:ℓ_i=t}、累积前缀 P_t=∪_{k≤t}H_k，满足三条累积约束：R_t^G=Σ_{i:ℓ_i≤t} b(d_i) ≤ B_t^G、P_{t−1}⊆P_t、ϑ_i^{(t)}=ϑ_i^{(ℓ_i)}（∀t≥ℓ_i）。关键技术：共享多尺度 Gaussian 序，在多图像尺度上测位置-尺度敏感度，使早期前缀建宽场景结构、后期补细节，全阶段共用同一序以保证嵌套；Layer–Degree Allocation 把结构分数与外观分数校准到“每字节”可比尺度，每阶段在“加下一个 Gaussian”与“多保留一档 SH”之间分配预算；轻量 opacity 更新在新 Gaussian 改变透射率后修正已有前缀的合成权重，几何与 SH 不重传；每阶段 5k 迭代无致密化的 layer refinement，再由 Decode_i 解出可渲染记录。

## 实验与结果
['1) 数据与协议：Mip-NeRF360、Tanks&Temples、Deep Blending；从 30k 迭代的 3DGS 模型出发，Base/Base+E1/Base+E1+E2 的 Gaussian payload 分别为源模型的 10%/18%/32%；体积按 PLY 实测，FPS 在 RTX 6000 Ada 上测。', '2) Mip-NeRF360 三点：27.08/27.68/27.75 dB，SSIM .8032/.8173/.8202，LPIPS .2396/.2169/.2104，规模 61/111(+50)/200(+88) MiB；同点基线 MGS 24.24 dB/56 MiB、FLoD 24.22/119、CLoD-GS 26.92/450、LapisGS 21.31/578、GoDe 26.90/56。', '3) Tanks&Temples：22.63/23.37 dB @43/78 MiB；Deep Blending：29.72/29.84 dB @59/107 MiB（同点 MGS 27.86/28.55、LapisGS 26.25）。', '4) 传输成本（Mip-NeRF360 @1 Gbps）：Base→E1 追加 50 MiB，本地 9 ms（含 0.4 ms opacity delta），总计 431 ms；E1→E2 88 MiB、11 ms、750 ms；对比 MGS 477/955 ms、GoDe 680/665 ms、FLoD 2247/4680 ms、CLoD-GS 1911/1914 ms、LapisGS 3746/3376 ms。', '5) 在三个数据集、100 Mbps–1 Gbps 下，每次跃迁总延迟均进前二，Base→E1 全部第一。', '6) 消融 BD-rate（以 SHIN 为锚）：PUP 式单尺度排序 +28.6%；固定 SH0 +63.9%、SH1 +94.4%、SH2 +123.6%、SH3 +178.4%；Gaussian-first 顺序分配 +100.1%；endpoint-first 截断 +14.3%；去掉分数校准 +88.7%（PSNR 掉 0.29–0.52 dB）；去掉 opacity 更新 +14.4%（delta 仅占体积 1.2–2.0%、<1 ms）。', '7) 结构演进：Base→E2 的粗尺度占比 56.4%→45.8%、细尺度 35.1%→43.2%；SH 分配集中在 SH0 与 SH3，高阶在后期层更常见。']

## 创新点与贡献
['把累积式 3DGS 构建形式化为 persistent allocation problem：Gaussian 的加入时机与其保留 SH 阶数联合决定一串可复用操作点，早期决策被后续前缀继承，无法逐阶段独立优化。', 'Layer–Degree Allocation：共享多尺度序保证嵌套，校准后的“每字节”分数在空间支撑与外观容量之间做联合预算分配，避免 Gaussian-first（+100.1%）与 endpoint-first（+14.3%）两种极端。', '只更新 opacity delta 即可在新增 Gaussian 后修正合成权重，几何与 SH 零重传——这让增强层真正可加而非替换，是“累积复用”成立的关键机制。']

## 局限与风险
['我发现：方法前提是已有训练好的 3DGS 模型（30k 迭代），层级构建本身仍需每阶段 5k 精修，属离线预处理，不能在线适配任意新预算。', '我发现：SH 阶数只允许 {0,1,2,3} 四档且一旦传输不可再改，后期补高阶 SH 收益极小（+E2 追加高阶 SH 仅 +0.11 dB 而体积约翻倍），等于放弃部分可扩展性。', '正文未设独立 limitations 小节；消融显示任一固定 SH 阶在序列上都不最优，且分配策略依赖校准质量（去校准 +88.7%），对分数分布敏感。', '我发现：Base 质量已明显高于多数基线（27.08 dB @61 MiB vs MGS 24.24 @56 MiB），但 FPS 随层从 326 降到 216，实时预算紧的场景需权衡层数。']

## 与文献库的关系
与 MGS（有序高斯前缀、连续 LoD）、LapisGS（Base + enhancement 层、允许前序 opacity 自适应）、GoDe（梯度掩码分配渐进层）、L3GS（按视口与带宽调度层）、Octree-GS/FLoD/LOD-GS（层级 LoD）、PRoGS（渐进加载）直接竞争；与 LightGaussian、PUP、Compact3DGS、HAC、ContextGS、RDO-Gaussian 等压缩工作的区别是那些只产出单一操作点；与 FlexGS、CLoD-GS 的“随时改预算”不同，SHIN 强调可累加传输。

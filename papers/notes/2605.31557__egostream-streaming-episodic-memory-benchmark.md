# EGOSTREAM：第一视角流式情景记忆的诊断基准

## 一句话结论
EgoStream 用 2,250 道题 + Answer Validity Window 扩展成 8,528 次评测，在统一 Qwen3-VL 框架下发现最强流式记忆机制准确率仅约 45%，且全部慢于实时（>1 s/帧）。

## 要解决的问题
现有第一视角 VideoQA 基准是离线的，证据与提问的时间距离不受控，评测也不区分「该记什么、要记多久、答案何时失效」，导致记忆质量差异被平均准确率抹平。已有的在线/流式基准多只测响应速度或聚合精度，无法诊断不同记忆管理策略在语义维度与保持时长上的取舍。

## 方法详解
基准构建：从 5 个第一视角数据集（Multi-Hop EgoQA 578、Ego4D 498、EgoLife 433、EgoTempo 425、HD-EPIC 316）出发，经 LLM 生成干扰项 + 两轮 human-in-the-loop 标注（人工修正 847 题、Gemini 2.5 Pro 自动打标后再人工核验）得到 2,250 道四选一题，丢弃 85 题。题目按 7 个认知维度组织：detail、spatial、temporal、event、social、causal、prospective。核心概念是 Answer Validity Window（AVW）：标注答案在被后续事件推翻前仍然成立的时间跨度，把同一题在 instant / short / S-Mid / Mid / ML / long / ultra 等 recall regime 下重复评测，得到 8,528 次条件化推理，从而把「真遗忘」与「世界状态已变」解耦。评测侧实现统一流式 MLLM 框架：固定 Qwen3-VL 骨干与统一 prompt，把 KV-cache 记忆管理拆成帧内 reducer（INTRA-COS 余弦冗余、INTRA-PA 伪注意力显著性、INTRA-VN value-norm、INTRA-CS sink 引导）与帧间 reducer（INTER-COS、INTER-PA），组合出 sliding window、attention sink、merge、prune、offload 五类共 18+ 种配置，并记录每帧处理时间。

## 实验与结果
主结果为 18 种以上记忆配置在 7 个语义类别 × 7 个 recall regime 上的准确率矩阵。FIFO 滑窗最弱（Avg 29.53%）；StreamVLM（FIFO+SINK）Avg 44.74%；CaM 式 merge 41.87–43.42%；StreamMem prune 42.39%；InfiniPot-V 44.52%；纯 INTRA-COS prune 达 45.63%（最高）；StreamTOM 45.19%。整体天花板约 45%，接近随机 25% 与纯文本基线 25.42% 之间的水平，说明视觉记忆利用极不充分。处理时延：最快的 INTRA-COS prune 2.28 s/帧，滑窗 1.05 s/帧，merge 类 2.3–2.9 s/帧，混合 prune+merge 达 5.3–5.7 s/帧，全部远超实时（>1 s/帧）。诊断结论：token pruning 在细粒度细节与时间结构上明显优于 token merging；量化 offload（ReKV）能救回 ultra-long 召回但整体 Avg 仅 40.99%；长时程（ML/long/ultra）普遍比 short 掉 20–30 个点。

## 创新点与贡献
- 提出 Answer Validity Window，把「模型遗忘」与「场景状态演化导致答案失效」分开度量，使 recall horizon 成为可控变量。
- 按 7 个认知维度切分 episodic memory，并给出可复用的两轮人机协同标注与干扰项生成流程。
- 提供统一骨干、统一 prompt 的流式记忆管理对照框架，首次系统比较 merge/prune/offload/sink 在语义与时间两个轴上的差异化退化。

## 局限与风险
- 基准题目由既有数据集改写与 LLM 生成干扰项而来，仍受源数据域（室内日常）与 LLM 偏差影响。
- 只固定 Qwen3-VL 一个骨干，结论对其他 MLLM 的可迁移性未验证。
- AVW 部分区间（尤其 HD-EPIC）依赖 Gemini 3.1 自动推导后人工复核，标注一致性存在残余噪声。
- 仅四选一准确率一种主指标，未评估答案置信度、拒答或时序定位质量。

## 与文献库的关系
与 Ego4D、EgoLife、EgoTempo、HD-EPIC、Multi-Hop EgoQA 等第一视角 VideoQA 数据形成互补，方法侧对标 StreamVLM、StreamMem、InfiniPot-V、ReKV、CaM、StreamTOM 等 KV-cache 记忆管理族；定位是「诊断工具」而非新模型。

## 可复现性（代码/数据/硬件）
提供匿名 GitHub 仓库与项目页（saroo25.github.io/Egostream），标注、代码与评测脚本声明共享，硬件与配置在附录 C.1，可复现性较好。

## 行动建议
做可穿戴助手或长时程第一视角记忆时，应把 EgoStream 当回归测试集，优先选 token pruning 而非 merging，并正视 >1 s/帧 的实时性缺口。

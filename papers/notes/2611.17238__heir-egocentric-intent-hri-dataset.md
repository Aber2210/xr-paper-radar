# HEIR：利用自我中心意图的人机交互数据集与基准

## 一句话结论
发布 HEIR：17 名被试、300 个 session、38.56 小时、1836 个 episode、6416 个导航-操作子任务，把人的自我中心视频+注视+语音与机器人四路视角+遥操作轨迹按请求级配对；加入人视角与注视后意图理解 Plan EM 从 63.51 升到 78.11，但四组件串联的真实机器人端到端 episode 成功率仅 18.52%。

## 要解决的问题
现有具身智能数据与基准基本是任务中心的：机器人执行给定指令，人是环境中的旁观者甚至障碍物。要研究「以用户为中心」的具身智能，就需要同时记录人如何感知、表达、与机器人交互的数据。已有的 HRI 数据集大多在受控桌面场景、短时程、只覆盖单一交互环节；自我中心视觉虽已被用于机器人学习，但很少有人研究人视角的意图线索（注视、指向、措辞）如何补充机器人自身观测。缺的是这样一个资源：真实家庭环境、长时程连续 session、人机双视角配对、并且把人的意图与机器人的导航-操作执行在标注层面打通。

## 方法详解
采集硬件：人侧用 Pupil Labs Neon 眼动眼镜，记录自我中心视频、语音与实测注视；机器人为 Galaxea R1 Lite（2025 版）移动双臂平台，记录四路视频（两个顶部相机 + 两个腕部相机）、双臂与夹爪动作、以及臂/夹爪/躯干/底盘的状态量；场景用 MID-360 LiDAR 扫描作几何基准。底盘平面轨迹由 MapAnything 的视觉估计与遥操作时的时间戳轮式里程计融合得到，再与机器人视角视频、导航标注逐帧对齐；用刚性安装在机器人顶部的 HTC VIVE Tracker 做验证。
数据组织是三层嵌套：session（一次连续的 household 交互）→ episode（一次自然语言请求及其后续执行）→ subtask（连续的导航段或操作段；一个操作子任务可含多个物体或双臂）。同一 session 内的 episode 共享持续变化的物理环境，因此后续请求可以指代先前交互涉及的物体或位置——这正是长时程指代与状态跟踪的来源。任务场景覆盖日常生活、厨房活动、家庭办公三类，把取物、递物、搬运、协同操作编排成请求序列；同一场景重复录制时目标不变，但物体位置在同一大致区域内变动、措辞与时序也可变。
标注协议：人工标注者先基于录像做时间定位标注，再用 VLM 辅助丰富、精炼为结构化指令与子任务描述；标注内容含任务意图、目标物体、目的地、名义计划（nominal plan）、以及实际实现的导航/操作阶段。
评测被组织成四级层次：① 人的意图理解——输入文本指令 / 机器人视角 / 人+机器人视角 / 加 center prior / 加注视，输出 Slot F1（指代槽位）、Location Accuracy（目标位置）、Plan EM（计划完全匹配）、RV F1（机器人视角可见性）；同时消融交互历史（真值历史 / 无历史 / 用前序预测作历史）。② 子任务规划——给定机器人观测、意图标注与执行历史，判断「继续/切换」并预测下一子任务类型，指标为 Acc、Macro-F1、Next Type、Core、Completion F1（Completion F1 用独立的 Codex 复核做一对一终态事实匹配）。③ 导航——NaVid / StreamVLN / InternVLA-N1 用 LoRA（rank 32、α 64、dropout 0.05）微调，预测动作与 STOP。④ 操作——DreamZero、π0-FAST、π0、π0.5、FastWAM、Lingbot-VLA2 微调，报首步与 action chunk 的关节 MSE、末端位置/旋转误差。真实机器人系统里 planner 采用事件触发而非定频查询：当底盘 20 s 内移动 <0.01 m 且所有关节偏离 <0.05 rad 时判定静止，才重新查询规划器。

## 实验与结果
- 数据规模：17 名被试、300 个 session、20 类日常任务、38.56 小时、1836 个 episode、6416 个执行子任务；平均每 session 7.71 min、6.12 个 episode、每 episode 3.49 个子任务；60 个 session 留作测试（导航划分 202/38/60，操作划分 220/20/60）。
- 轨迹验证：HTC VIVE Tracker 参考记录 16,323 帧，融合轨迹的平面位置 RMSE 为 8.55 cm；76 个 1 s 窗口（净位移≥5 cm）局部端点误差均值 1.63 cm、95 分位 3.50 cm；105 个窗口的方向余弦相似度中位数 0.9992。
- 意图理解输入消融（Gemma-4-31B，Slot F1 / Loc Acc / Plan EM / RV F1）：纯文本 59.52 / 20.47 / 30.27 / N/A；仅机器人视角 71.22 / 54.86 / 63.51 / 60.33；人+机器人 74.85 / 71.13 / 72.43 / 57.71；加 center prior 74.91 / 71.39 / 75.14 / 61.61；加注视（完整）77.18 / 77.69 / 78.11 / 64.09。
- 交互历史消融：真值历史 81.25 / 80.31 / 82.70 / 64.88；无历史 76.69 / 77.17 / 76.22 / 63.13；用前序预测作历史 77.89 / 79.27 / 81.08 / 63.51，说明跨请求的状态依赖真实存在。
- 子任务规划：微调后决策准确率提升 25–37 点、下一子任务类型准确率提升 25–55 点；Qwen3.5-4B 综合最佳（Acc 83.46、Macro-F1 84.33、Core 61.06、Completion F1 36.85）；Cosmos3-Nano 预训练几乎恒判 Continue（Next Type 0.00，Core 0.00）。
- 导航：InternVLA-N1 微调后动作准确率 90.69、Macro-F1 91.00、STOP F1 76.98（原模型 49.08 / 45.41 / 31.48）；在 32 个导航子任务上子任务级成功率 81.25%。
- 操作：六个 VLA/WAM 微调后 Lingbot-VLA2 最优（首步 joint MSE 0.000316 rad²、EEF 位置 0.310 cm、旋转 0.539°）；20 个 pick-and-place 任务×3 次真机试验成功率 68.33%（Lingbot-VLA2）、60.00%（FastWAM）、36.67%（π0.5），排序与离线动作预测一致。
- 端到端真机：27 个 episode（含纯导航、取送、纯操作、与人协同铺床单等），由 2 名换装过的原被试发出请求；四个组件串联后 episode 级成功率仅 18.52%，暴露出长时程误差累积。

## 创新点与贡献
- 首次把「人的自我中心视频 + 实测注视 + 语音请求」与「机器人四路视角 + 遥操作导航-操作轨迹 + 底盘/臂状态」在同一时间轴上按请求级配对，并保持跨请求的连续 session，使长时程指代与状态变化可被建模。
- 给出会话→请求→子任务的三层结构与对应的细粒度标注（意图、目标物、目的地、名义计划、实际阶段），把「人的意图」与「机器人的执行」在同一标注体系里连接起来。
- 设计并验证了一整套四级层次化基准（意图理解 / 子任务规划 / 导航 / 操作）+ 真机闭环，使「人视角线索是否真的被用上」这一问句可被定量回答。
- 用输入消融把「人视角」和「注视」的边际价值单独量化：人视角相对纯机器人视角把 Location Accuracy 从 54.86 提到 71.13，注视再提到 77.69，且优于 center prior 这一常用替代。

## 局限与风险
- （作者承认）所有 session 在同一间布置房间录制，训练与测试共享同一房间，只评估家具重摆、物体位置、措辞与时序的变化，不评估未见环境泛化。
- （作者承认）端到端真实机器人 episode 成功率仅 18.52%，组件误差在长时程下累积严重。
- （作者承认）真机评测只有 27 个 episode、2 名被试，规模不足以支撑细粒度结论。
- （我在正文发现）机器人侧轨迹由「拥有全局场景视角的独立操作员」用手柄遥操作产生，策略偏置与该操作员的习惯绑定，与发出请求的人的真实意图之间存在系统性错配，正文未讨论这一混杂。
- （我在正文发现）意图标注是「人工先标 + VLM 辅助丰富」，但正文未报告标注者间一致性（IAA）或 VLM 介入前后的一致率，无法判断标签噪声。
- （我在正文发现）底盘轨迹是 MapAnything + 轮速融合的估计值，8.55 cm 平面 RMSE 对精细操作参考偏大；导航成功率的评估因此部分依赖估计轨迹而非独立真值。

## 与文献库的关系
与 HRI / 具身数据集的差别可以按表 1 的七个维度看：Gaze2Act（653 段）有人机双视角、注视、语音与意图标注，但不覆盖长时程、也不含导航+操作；HABIT（38,412 子任务）规模大但只有机器人视角、无注视无语音；HARMONIC（480）有注视但无语音、无意图标注、非长时程；NatSGLD（1,143）有语音与配对演示但非真实长时程交互；RoboVQA（61,153）是机器人视角的中时程视频-文本推理数据，缺人视角与注视；RoboCasa365（55,000）与 TEACh（11,176）在仿真中做长时程家务，缺真实人机共处；EDITH（280）有人机双视角+注视+语音，但既不覆盖长时程也不含导航+操作。HEIR 是表中唯一在七个维度上全部打勾的条目。与自我中心视觉用于机器人学习的前作（[60,13]）相比，本文不把自我中心视频当作额外的观测源去训策略，而是把注视当作「人在指什么」的直接证据，接到意图理解与规划上。

## 可复现性（代码/数据/硬件）
数据集已公开（HuggingFace: Anonymous-HEIR123/HEIR-Dataset）并有项目页 https://heir-project.github.io/，含演示视频。硬件为商用件（Pupil Labs Neon、Galaxea R1 Lite 2025、MID-360、HTC VIVE Tracker），采集协议、标注协议与质量审查流程在附录 B，轨迹重建与验证的数值（8.55 cm / 1.63 cm / 0.9992）可核对。训练超参给得较全：LoRA rank 32 / α 64 / dropout 0.05、冻结主干与视觉编码器、5 epochs、30 Hz 动作流、seed 42，批大小见 Table 10。主要不可复现项是真机闭环（需同款 R1 Lite 与同一布置房间）以及标注者的人工判断。

## 行动建议
适合作为「以用户为中心」的 HRI 评测基座：四层接口（意图 / 规划 / 导航 / 操作）清晰，能分别定位失效环节，尤其适合检验「加了人视角与注视到底有没有被模型用上」这类消融问题。使用时要注意三点：单房间、仅 2 名评测被试、端到端 18.52%，因此它是诊断工具而非泛化基准，跨场景结论需另建数据。做意图理解时建议把 center prior 作为必须的对照——本文显示注视优于 center prior，但差距不大（Plan EM 78.11 vs 75.14），若不控这个对照容易高估注视的贡献。

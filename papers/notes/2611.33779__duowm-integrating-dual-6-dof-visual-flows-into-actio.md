# DuoWM：把双 6-DoF 视觉流注入动作条件无人机世界模型

## 一句话结论
把 6-DoF 相机指令逐帧画进画面（中心 + 三轴端点投影、按对数深度取灰度）做 action flow，使每一帧都能精确控相机——Sekai-game FVD 65.99（Captain Safari 69.83）、AUC@30 0.5719（0.5003）、AUC@15 0.3747（0.3088），真实域 FVD 191.77（231.67）、LPIPS −21.6%。

## 要解决的问题
动作条件视频世界模型要从首帧与相机轨迹生成未来观测，但相机指令与画面动态常对不上，且多数运动表征只覆盖 3-DoF 平移，无法表达完整 6-DoF 刚体变换；已有方法又多依赖首帧引导向后续帧传播，缺少逐帧的精确控制。在 Sekai-game-drone 上，此前最强的 Captain Safari 的 FVD 为 69.8325、AUC@30 仅 0.5003、AUC@15 0.3088；真实域 FVD 231.6737、LPIPS 0.1594，说明「按指令飞到该看的视角」仍是瓶颈。

## 方法详解
给定首帧 $I_0$、文本 $y$ 与目标相机轨迹（$C_t\in\mathrm{SE}(3)$、内参 $K_t$），生成 121 帧视频。Action flow 把相机指令画进每一目标帧：相对位姿 $C_{t\to j}=C_t^{-1}C_j=[R_{t,j}\ \mathbf{d}_{t,j};\ 0\ 1]$，取中心与三个局部轴端点 $\mathbf{q}\in\{0,\ell e_1,\ell e_2,\ell e_3\}$，投影 $\mathbf{p}_{t,j}(\mathbf{q})=\pi(K_t[\mathbf{d}_{t,j}+R_{t,j}\mathbf{q}])$；中心固定 50 像素半径，灰度按对数深度 $g(z)=220-140\gamma(z)$ 编码远近（$z_{\text{near}}$/$z_{\text{far}}$ 取参考深度 5%/99.5% 分位），RGB 三色分别表示 $x/y/z$ 轴，远时段的标记先画以保证近端可见。Object flow 把首帧几何前向泼溅到目标视角：MoSE3 预测深度 $D_0$，以每域标定的尺度 $s_d$ 得 $\bar{D}_0$，投影 $\mathbf{p}_t=\pi(K_t[I_3\ 0]C_t^{-1}C_0[\bar{D}_0(\mathbf{p})K_0^{-1}\tilde{\mathbf{p}};1])$，用深度缓冲取最近点，得到 warp 图 $W_t$ 与覆盖掩码 $M_t$；再由 MoSE3 追踪表面锚点，按局部 $R^{\text{loc}}_{t,k},\mathbf{d}^{\text{loc}}_{t,k}$ 变换位置与坐标架，在重建相机下投影并叠加彩色轴与短拖尾。Transform-aware pretraining 先把训练帧的标记像素替换为几何轴 $I_t^{\text{geo}}=(1-B_t)\odot I_t+B_t\odot\Gamma_t$ 重建 300 步，再切回无标记 RGB 训练（game 5 epoch / real 2 epoch），Object flow 在预训练期不含拖尾。注入方式为通道拼接：$H^{(0)}=P_\theta([z_\sigma;c_0;z_A;z_O;m])+\mathcal{A}_{\text{cam}}(r)$，两路流各 48 通道、加 1 通道掩码共 197 通道，保留原 Plücker 射线相机适配器与文本 cross-attention；只训新增投影列与 rank-32 LoRA，VAE/文本编码器/相机适配器冻结，目标为 flow matching $\mathcal{L}=\mathbb{E}[w(\sigma)\mathrm{MSE}(v_\theta,v^\star)]$，$v^\star=\epsilon-z$。

## 实验与结果
- Sekai-game-drone：FVD 65.9881（Captain Safari 69.8325）、LPIPS 0.2593（0.2606）、MEt3R 0.2994（0.3000）
- Sekai-game-drone 轨迹：AUC@30 0.5719（0.5003，+14.3%）、AUC@15 0.3747（0.3088，+21.3%）、CosSim 0.3595（0.3325）
- Sekai-real-drone：FVD 191.7696（231.6737，-17.2%）、LPIPS 0.1250（0.1594，-21.6%）
- Sekai-real-drone 轨迹：AUC@30 0.5409（0.5218）、AUC@15 0.3709（0.3521）、CosSim 0.3110（0.2675）
- 数据规模：game 5118 训练 / 474 测试视频；real 4368 / 402；121 帧、1280×704、24 FPS
- 相对 Wan2.2-Control-Camera：game FVD 75.6100 → 65.9881（-12.7%）
- 预训练收益：game FVD 70.3296 → 65.9881（-6.2%），real -5.1%，real MEt3R -3.9%

## 创新点与贡献
- 相对 EnerVerse-AC（只把末端位置与朝向轴画成动作图）、PoseTraj（把投影 3D 框当临时监督再撤掉）、DualCamCtrl（双分支生成 RGB 与深度），DuoWM 的两路流分工明确：Action flow 负责「相机该在哪」，Object flow 负责「首帧表面在该视角下怎么变」，后者把 MoSE3 的稠密 SE(3) 估计变成可被生成器读取的外观+局部轴条件
- 预训练的新意在于轴标记不是临时监督而是持续条件，与 RGB 训练阶段共享同一几何语义，因此外观与刚体运动的对应关系被显式建立

## 局限与风险
- 作者自述：只做 121 帧开环生成，长时程自回归与与飞行策略的闭环交互留作未来工作
- 我们另看出：Object flow 依赖 MoSE3 的单目深度与位姿，且每域尺度 $s_d$ 需用训练视频的 Huber 重投影误差标定、假设域内平移单位一致，跨域或尺度漂移会直接污染条件
- game 域 FVD 仅比 Captain Safari 低 5.5%，提升主要集中在轨迹指标，视觉质量优势有限
- 短预训练预算下多个指标反而变差，说明增益对日程敏感
- 无代码，复现依赖 Wan2.2-Fun-5B 与 MoSE3 的具体版本

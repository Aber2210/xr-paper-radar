# Zing-1.0：构建于可控渲染之上的可玩世界系统

## 一句话结论
首个与实现无关地把「可玩世界系统」形式化为四项职责及其接口，用引擎生成的 proxy 视频把确定性控制接到生成式渲染：832×480 稳态 23.82 FPS（提升 26%）、首帧 0.70 s（对半）。

## 要解决的问题
交互式视频世界模型让指令直接条件化下一帧观测，缺少独立的状态演化步骤，画面可以视觉上合理但隐含的状态转移违反世界规则，长程交互难以兼顾规则一致与视觉连贯。

## 方法详解
提出 Controllable Rendering 原则：状态演化交给可执行引擎 WorldKit，视频模型只渲染玩家所见。WorldKit 供编码智能体构建可执行 proxy 世界并输出 proxy 视频；渲染侧把 MiniMax-H3 改造为 block-causal 自回归流式生成与增量解码，用 proxy 约束结构与运动、文本加场景/主体参考约束外观，并蒸馏到少步采样；交互运行时负责流式调度、跨块联合执行、帧对齐稀疏注意力与压缩 KV、低延迟条件更新。

## 实验与结果
- 流式稳态吞吐 = 23.82 FPS @ 832×480（Dense BF16 18.88 FPS，提升 26%）
- 首帧时间 TTFF = 0.70 s（Dense BF16 1.39 s）
- OpenVE = 3.90，LongV2VBench = 3.44
- StreamEval 指令编辑 = 57.86，参考编辑 = 54.06
- 指令编辑 Stability = 47.80（Vidu S2 Editing 13.94）

## 创新点与贡献
- 首个与实现无关地把「可玩世界系统」形式化为四项职责及其接口，并用引擎生成的 proxy 视频把确定性控制接到生成式渲染上

## 局限与风险
- 长程渲染中生成历史与 proxy 冲突会累积偏差
- 引擎与渲染器之间该指令到什么粒度仍未定
- 交互延迟还受执行、传输与显示制约

# Motion Mamba 2.0：面向长时程人形控制的自回归扩散 Mamba

## 一句话结论
把「远历史可读」与「低延迟」拆成两个问题分别解决（Mamba 递归状态 + PCM 映射成注意力键值）：HiPHI 18.72 s Root/End CE 2.87/8.45 cm 对 MotionStreamer 6.17/18.93 cm，MuJoCo + Unitree G1 共 100 次试验。

## 要解决的问题
长时程、实时可控的运动生成要求智能体在移动中响应变化的指令与空间目标，而离线文本到运动的前提（开始生成时已知完整指令序列）在交互场景不成立。自回归扩散逐步生成虽提供了在线接口，但受两重限制：有界注意力缓存只能看到最近历史，无界缓存又使存储与计算随序列增长；重复去噪带来大量 kernel 启动与访存开销，即使单次评估很小。这两点彼此独立——减少采样步数不扩展可用历史，压缩历史状态也不消除去噪开销。

## 方法详解
把生成按窗口切分（C 个 token/窗，52 帧 ≈ 2.08 s，25 Hz），条件为文本 $s_t$、空间目标 $g_t$ 与有效性掩码 $v_t$，并按窗口因子化 $p_\theta(x_{0:T}|s,g,v)=\prod_t p_\theta(x_t|s_t,g_t,v_t;\mathcal{M}_{t-1})$。运动表示沿用 ARDY 的混合形式：显式 root（位置 + heading）与因果 motion codec 压缩的 body latent，$x_i=[r_i;b_i]$，使轨迹可直接受空间条件约束而articulation维度被压缩。去噪为两阶段：每个扩散步先由 root 网络 $\mathcal{F}^r_\theta$ 预测全局轨迹，其局部特征再条件化 body 网络 $\mathcal{F}^b_\theta$，故 root 在每个去噪步都被刷新，两者在整个采样过程中耦合。每层是 DiT block 加混合序列 mixer：注意力取最近 W 个已接受窗口的 key/value 与静态 sink token，Mamba-3 则从已接受前缀恢复 SISO scan 状态（含累积相位旋转、梯形更新 $H_i=\alpha_iH_{i-1}+\beta_iu_{i-1}\tilde B_{i-1}^\top+\gamma_iu_i\tilde B_i^\top$），两路输出经逐层学习门相加。PCM 解决「状态不可被注意力读取」：对已接受 recurrent matrix 池化得 summary $\bar s_t$ 与其差分 $d_t$，用文本 embedding 经 LN+MLP 产生 FiLM 参数 $(\gamma_t,\beta_t)$ 调制 $d_t$，拼接 $[\bar s_t;\tilde d_t;e_t]$ 投影为候选内容 $Z_t$，写门 $w_t=\eta\sigma(f_w([j_t;\mathrm{vec}(P_{t-1})]))$，$P_t=(1-w_t)\odot P_{t-1}+w_t\odot Z_t$，$\eta$ 限制单步写入量；读出用增广注意力 $A_P$（slot 插在 sink 之后），$Y=A_0+\tanh(\rho)(A_P-A_0)+\sigma(\zeta)M$，$\rho$ 初始化为 0 使初始输出与原生 mixer 完全一致。历史仅在窗口被接受后提交（cache append、recurrent 替换、PCM 写入三者同步），去噪期间读不可变快照。推理侧做状态保持式优化：只读执行、Mamba A/ΔT 预处理融合 kernel、root 与 body 各自 CUDA Graph 捕获三条 CFG 分支。损失 $\mathcal{L}=\lambda_{hyb}\mathcal{L}_{hyb}+\lambda_{body}\mathcal{L}_{body}+\lambda_{goal}\mathcal{L}_{goal}+\lambda_{FK}\mathcal{L}_{FK}$，codec 冻结。

## 实验与结果
- HiPHI 18.72 s：Root/End CE 2.87/8.45 cm vs MotionStreamer 6.17/18.07、ARDY 8.15/11.06
- HiPHI 39.52 s：Root/End CE 7.55/13.64 cm，Root CE 比 MotionStreamer（7.78）降 3.0%，End CE 比 ARDY（14.84）好 8.1%
- HiPHI 39.52 s：Cmd. 46.05%、R@3 23.68%（MoLingo 41.34%、OMG 19.61%）；L2-FID 0.409（8.32/18.72 s 为 0.401/0.402）
- 推理（RTX 4090，完整窗口）：p50 1685.35→276.14 ms、p95 2471.65→345.82 ms，中位配对加速 6.138×（95% CI [6.094, 6.290]）
- 执行剖面：host launch 83,777→5,519（-93.4%）、GPU kernel 86,849→44,877（-48.3%）、sync 10,194→1,330；四个 100 窗 rollout 输出与提交状态 bitwise 一致
- Unitree G1 真机：T1 18/20（90.0%）、T2 19/20（95.0%）、T3 29/30（96.7%）、T4 28/30（93.3%），合计 94/100 全任务成功、0 摔倒
- 交互控制：速度 RMSE 0.041/0.045 m/s、朝向 MAE 4.6°/5.1°、物理响应 p50 351/360 ms、1.5 s 内完成 296/300（98.7%）与 292/300（97.3%）、stance slip 1.5/1.7 cm/s
- 状态模型 10 min rollout：位置误差 0.717±0.254 m（20 m×20 m 场景）、速度 0.463 m/s、朝向 3.3e-4

## 创新点与贡献
- 把「远历史可读」与「低延迟」当作两个独立问题分别解决：Mamba recurrent state 提供与序列长度无关的压缩历史，PCM 再把 state summary、状态差分与文本条件映射成注意力可读的 slot（并且不替换 recurrent 分支），从而在有界缓存下保留远历史
- 同时用 CUDA Graph 重放把重复去噪的 host 调度开销压掉约 6 倍，且保证输出 bitwise 不变

## 局限与风险
- 作者承认框架只面向人形运动生成、尚不处理物体操作，未来才做 whole-body loco-manipulation
- 正文可见：状态模型不使用任何视觉反馈，长 rollout 会累积漂移（10 min 位置误差 0.72 m），作者也承认 NPC 位置/朝向偶有偏差
- 训练依赖大规模重定向数据，真机只在 G1 一种平台验证
- PCM 只保证「可用的运动上下文」，不保证恢复被驱逐的具体事件
- 真机部署为远端 4090 + ZeroMQ/SSH，并非 onboard 推理

# EgoUseBench：在演化第一人称上下文下评测计算机使用智能体

## 一句话结论
把第一视角 computer-use 从「一次性给全视频」改成在线流式：观测 / 需求 / 站点状态三流异步演化 + 三类信息更新机制——693 任务 / 74 h，Online 63.4% 比 Computer-Use 86.1% 低 26.3 点而 token 少 16.4–38.0%，最强模型 87.0%，93 个组合任务上 77.4% vs 40.9%。

## 要解决的问题
智能眼镜等第一人称设备让计算机任务可以源自用户正在进行的物理活动，但第一人称观测受佩戴者视角限制，证据不完整且会随新画面前后变化，智能体必须修订对场景与意图的理解并判断此前操作是否仍有效。现有基准要么只给显式指令（Computer-Use），要么在執行前一次性提供预录第一人称视频（Offline Ego Use），无法评测执行中的流式更新。作者为此提出 Online Ego Use，并发现六个先进模型在该设定下平均成功率为 63.4%，比 Computer-Use 的 86.1% 低 26.3%，说明「边看边改」远未解决。

## 方法详解
构建 693 个可执行任务：293 个 Online Ego Use（其中 200 个单机制任务、93 个组合任务）、200 个 Offline、200 个 Computer-Use，三者共享网站与最终目标以便配对比较。环境是 Amazon、YouTube、Google Maps 的本地仿真站点，支持搜索、加购、收藏，检索用 BM25，每步只允许一个 JSON 动作。异步状态演化把第一人称观测、用户需求、网站状态拆成三个独立演化量：观测按回放时间表每决策步推进 8 秒源视频（1 fps 采样，通常 4 帧拼一图），需求按预定时间点到达，网站状态只随智能体动作变化。三类信息更新机制：Graft 改写需求（Refine/Augment/Replace/Drop），Refresh 用后到画面使早先选择失效（Replace）或仍有效（Retain），Clarify 让智能体主动提问并由人工审定的固定回复消解指代歧义（Position/Sequence/Variant）。形式化地把任务写成 $(x,\mathcal{G}^{-})\to(x,\mathcal{G}^{+})$：网站状态 $x$ 不变而可接受目标集合随证据/需求改变；成功判定为 $\mathbf{1}[\exists g\in\mathcal{G}:N(x_T)=N(g)]$，归一化忽略展示顺序并把包装等价折算为需求单位。视觉历史有三种策略：Full、Compressed（隔帧保留，默认 0.5 fps）、Summarized（旧批次换成动作模型生成的文字摘要），开口批次与最近两批始终完整保留。每任务最多 20 步，组合任务 30 步；另设并发到达与唤醒到达两种交付模式。

## 实验与结果
- 数据规模：74 小时以上真实第一人称录像，693 个任务（293 Online / 200 Offline / 200 Computer-Use）
- 设定差距：平均成功率 Online 63.4%、Offline 64.2%、Computer-Use 86.1%，Online 低 26.3%
- 模型范围：六个模型总体成功率 39.0%–87.0%，GPT-6.1 Terra 最高 87.0%，Kimi K2.6 最低 39.0%
- Token 成本：Online 比 Offline 少 16.4%–38.0%
- 组合更新：93 个组合任务上 Gemini 77.4%、DeepSeek 40.9%
- 失败分析：604 条失败轨迹；Computer-Use 中 Linking 占失败 90.2%
- 失效时机：14.6% 的 Graft/Refresh 更新到达时，网站已满足初始请求但需为修订目标改动
- 任务质检：40 个分层抽样任务中双评审均接受者占 90%

## 创新点与贡献
- 相对 Mind2Web、WebArena、OSWorld 等只看显式指令与数字反馈的 Computer-Use 基准，首次把「第一人称观测」作为任务证据源
- 相对 Ego2Web、EgoBench 这类离线第一人称基准，新意是把观测、需求、网站状态建成三个异步演化状态，并在执行中注入 Graft/Refresh/Clarify 三类更新，从而能测「新证据推翻旧选择」而非只测一次性 grounding
- 据作者所述是首个定义并系统评测 Online Ego Use 的工作

## 局限与风险
- 环境是三家网站的本地仿真而非真实互联网，商品/视频/地点目录受限，结论对开放网页的迁移性未知
- Clarify 的回复是人工固定的，不随提问质量变化，因此只测「是否发问」不测追问能力
- 评分只看终止时网站状态，Refresh–Retain 任务无法从分数判断智能体是否真的用了后到画面
- 任务由少量标注者与 Coding Agent 构建，40 例质检虽达 90% 接受率，但 693 例的整体语义正确性仍有长尾风险

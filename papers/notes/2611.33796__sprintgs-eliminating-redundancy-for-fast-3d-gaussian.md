# SprintGS：消除冗余以加速 3D 高斯泼溅训练

## 一句话结论
在 FastGS 上按训练日程削减固定开销：tile 剔除阈值随训练收敛、损失按 batch 摊销、kernel 启动合并——13 场景均值 80 s（FastGS 172 s，2.15×）且 PSNR 27.38（27.31），DL3DV 141.8→63.3 s，与 Taming-3DGS 组合 345→125 s（2.76×）。

## 要解决的问题
3DGS 渲染是实时的，但逐场景优化仍要几十秒到几分钟，用户在现场想立刻检查刚拍的场景仍得等。FastGS 已把时间压到几分钟（13 场景均值 172 s），可作者剖析后发现紧凑模型里仍有两块浪费：光栅化占训练时间 64%（反向传播单独占 41%），且损失按像素计算、不随高斯数缩小，其占比从 4% 升到 23%。也就是说，模型越紧凑，损失与 kernel 启动等固定开销越突出。

## 方法详解
在 FastGS 之上做四处削减。F-A scheduled tile culling：把固定阈值 $\epsilon=1/255$ 换成随训练变化的 $\tau(t)$，按 $d_i^2\leq\delta_i(\tau)=\max(2\ln(o_i/\tau),0.15\delta_i^{\text{full}})$ 决定高斯进哪些 tile，下界 0.15 防止不透明度重置后高斯落不到任何 tile 而拿不到梯度；日程为 $\tau_c\to\epsilon$ 的分段函数，前 $T-2\Delta$ 步保持 $\tau_c=0.1$，随后 $\Delta=T/10$ 内按 logistic 在 log 尺度下降，最后 $\Delta$ 步固定 $\epsilon$，测试时始终用精确足迹，故只影响训练。F-B convergence-aware pruning：在致密化期间每 $K=500$ 步（从 3000 步起、跳过不透明度重置后的 K 步）剪掉 $\mathcal{P}=\{i\mid o_i<\theta_o\ \wedge\ v_i\leq Q_q(v)\}$，$v_i$ 是位置梯度二阶矩（Adam 第二动量）之和、$\theta_o=0.1$、$q=0.5$；下次克隆/分裂时把 $\lfloor\rho|\mathcal{P}|\rfloor$ 个预算（$\rho=0.4$）转给高误差但未过梯度阈值的高斯。F-C shuffle-efficient backward：splat-parallel 反向里每步只在线程间传 $T_i$ 与标量 $s_i=\mathbf{r}_i\cdot\mathbf{g}$ 两个值（原为 9 个），$\mathbf{g},T_{\text{fin}},i_{\text{last}}$ 从共享内存读；由 $\partial L/\partial\alpha_i=T_i(\mathbf{c}_i\cdot\mathbf{g})-\mathbf{r}_i\cdot\mathbf{g}/(1-\alpha_i)$ 代数改写为 $s_i=s_{i-1}-\alpha_iT_i(\mathbf{c}_i\cdot\mathbf{g})$、$\partial L/\partial\alpha_i=T_i(\mathbf{c}_i\cdot\mathbf{g})-s_i/(1-\alpha_i)$。F-D fused loss：因 $\partial L/\partial\ell_p=1/M$ 为常数，图像梯度只依赖前后向都可见的渲染图与真值，故在前向用三个 kernel 直接算 $L$ 与 $\partial L/\partial\mathbf{C}$，省掉 loss map、mean reduction、常量梯度图与全部损失反向 kernel。F-E 移植 Faster-GS 的四项实现优化并扩展两项：融合激活并把梯度直接交给优化器、单次 kernel 完成全参数 Adam、在反向 kernel 内累计致密化统计、异步训练循环（每 500 步才读一次 loss）。

## 实验与结果
- 13 场景均值：SprintGS-Base 80 s 对 FastGS-Base 172 s，加速 2.15×，PSNR 27.38 对 27.31 dB
- 高质量档：SprintGS-Big 156 s 对 FastGS-Big 283 s，加速 1.81×，PSNR 27.78 dB（全表最高）
- DL3DV-10K 1K 子集：141.8 s → 63.3 s（>2×），PSNR 28.51 对 28.42，LPIPS 0.182 对 0.184
- 时间构成：光栅化 64%、反向 41%、损失 23%（FastGS 中损失占比由 4% 升至 23%）
- 逐项移除代价：w/o F-A +12%、w/o F-B +2%、w/o F-C +23%、w/o F-D +31%、w/o F-E1 +14%、F-E2 +5%、F-E3 +8%、F-E4 +6%
- 与其他方法组合：Taming-3DGS 345→125 s（2.76×）、DashGaussian 334→193 s（1.73×）、SkipGS 161→76 s（2.12×）
- 动态场景 Neu3D：804→637 s（1.26×），PSNR 30.83→31.36（+0.53 dB）

## 创新点与贡献
- 相对 FastGS（固定收缩足迹 $\beta=0.5/0.7$、每 3000 步才剪一次、9 值 shuffle）与 Faster-GS（只做 kernel 级融合），SprintGS 的新意有三点：把 tile 足迹做成随训练退火的日程并在末期恢复精确足迹，从「近似渲染」变成「只改训练」
- 把损失的梯度搬到前向，利用 $\partial L/\partial\ell_p$ 为常数这一结构消掉整条损失反向链
- 把每步 shuffle 从 9 值压到 2 值且保持代数等价
- 三者都作用在 3DGS 系列共用的步骤上，因此能外挂到 Taming-3DGS/DashGaussian/SkipGS

## 局限与风险
- 作者自述：F-A 的粗足迹会在训练中引入偏差（移除后 PSNR 略高），依赖末期恢复精确足迹
- 动态场景加速有限，因为形变 MLP 未优化
- 我们另看出：$\tau_c,\theta_o,q,K,\rho$ 五个超参在正文只给单组取值（0.1/0.1/0.5/500/0.4），敏感性放在补充材料，跨数据集是否需逐场景调参不明
- 时间只在单张 RTX 3090 Ti 上以 5 次均值测，未报方差与不同 GPU 的绝对加速
- 全部增益是系统级工程优化，不改变收敛性或重建上限

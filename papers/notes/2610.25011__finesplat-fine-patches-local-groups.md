# FineSplat：细粒度 patch、局部分组、细节泼溅

## 一句话结论
FineSplat 把前馈 3DGS 的 token 粒度推进到 4×4 patch（M=NHW/p² 个细粒度 token）：Stage 1 用 MVP 多视图金字塔做 view-wise 分组注意力控制成本，Stage 2 将 token 提升到 3D 做空间分组以跨视图组交互，并用渲染输入视图的误差图直接反馈更新 token，配合每 token 更少高斯的紧凑生成，在支持未知相机位姿的 N 视角输入上实现细粒度前馈重建。

## 要解决的问题
前馈 3DGS 要在多视图上做强交互才能保证跨视图一致性，但细粒度 token（如 4×4 patch 级）会使全局多视图注意力计算量爆炸；固定视图分组又会留下跨组盲区。如何在保持细粒度视觉信息的同时控制多视图推理成本并跨视图组交换信息，是本文要解决的问题。

## 方法详解（含关键公式/架构，保留原文术语）
两阶段前馈框架（N 个 context views，可有/无已知相机位姿）。Stage 1 view-wise token grouping：每视图切 4×4 patch，采用 multi-view pyramid architecture（MVP，Kang et al., 2026b）——小组视图内做细粒度注意力、跨所有视图经更粗的全局 token 交换信息；编码器为三级金字塔 F1（最细）到 F3（最粗），融合公式 z(0)=fuse(up(fuse(up(F3)+F2))+F1)，得 M=NHW/p² 个 token。Stage 2：3D spatial token grouping——先把 token 解码成初始高斯集、渲染回 context views，用所得误差图（error feature maps）更新 token；token 提升到 3D 后，不同视图组中空间相邻的 token 可交互，弥补固定分组盲区；Compact Gaussian generation 每 token 预测比 pixel-aligned 方法更少的高斯，保持紧凑 3DGS 表示；direct error feedback 把输入视图重建误差用于进一步精化 token。附录含相机位姿估计器、遮挡测试（frustum test/depth test）用于误差特征聚合、场景尺度归一化等实现细节。

## 创新点与贡献
① 4×4 细粒度 patch 加三级金字塔 MVP 的 view-wise 分组注意力，使细粒度多视图推理成本可控（局部细节保留加全局粗 token 交换）。② 3D spatial token grouping：token 提升到 3D 后跨视图组交互，解决固定分组盲区。③ 渲染输入视图得误差图并直接反馈更新 token 的 error-feedback 机制，含视锥/深度遮挡测试做特征聚合过滤。④ 每 token 更少高斯的紧凑生成，兼顾细粒度与 3DGS 表示紧凑性。⑤ 支持有/无已知相机位姿的 N 视角输入。

## 局限与风险
digest 未提供任何定量结果，性能增益与相对基线定位无法核实。细粒度 token 的显存/时延虽经分组控制，端侧实时性未验证。误差反馈依赖初始高斯渲染质量，失败案例可能反馈放大误差。MVP 架构与组大小选择引入新超参（附录 C.1 专门分析），迁移到新场景需调参。

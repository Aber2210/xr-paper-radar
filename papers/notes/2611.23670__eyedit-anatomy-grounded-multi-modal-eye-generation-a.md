# EyeDiT：以解剖为根基的多模态眼睛生成与仿真

## 一句话结论
首个把 OCT、解剖点云与近眼图像压进同一 latent 的 3D 眼睛生成与仿真模型，纯合成数据训练的眼动 E50 降到 3.53°（oracle 2.59°）。

## 要解决的问题
AR/VR 的眼动追踪要估注视方向、瞳孔位置与瞳孔半径，这些量支撑注视点渲染与凝视交互；但训练可靠追踪器需要覆盖多样注视、瞳孔尺寸与受试者的大规模近眼数据，采集昂贵费工，而且每换一版相机配置的头显原型就要重采一轮。合成眼数据本是可扩展替代方案，可现有近眼数据集与合成生成器（NVGaze、UnityEyes 2、Lin et al.、ControllableGaze、GazePrior、GazeGaussian）几乎都是以图像为中心：只给带注视标签的图像或二维标注，不建模图像背后的三维解剖（虹膜与角膜）。后果是控制维度被限制在注视方向，无法输出角膜面、瞳孔位置与半径、光轴等解剖读数，而这些恰是注视点渲染与光学标定需要的量。从图像反推解剖之所以困难有两层原因：角膜透明且折射，其曲率与虹膜真实形状在图像中并不直接可见；AR/VR 设备只用少数固定位置的相机观察眼睛，三维结构严重欠约束。能直接测解剖的是眼科 OCT，它像扫描 LiDAR 一样逐点测深，可建角膜、虹膜、瞳孔的精确三维体；但 OCT 设备通常只能在受控环境操作，无法用于智能眼镜或头显，且前节 OCT 只覆盖角膜附近、不含眼周区域，所以 OCT 极少与近眼图像结合。GazePrior 虽把全局眼结构学成先验、只从少量视图适配个体差异，但其先验仅来自图像，抓不到角膜与虹膜这类图像无法揭示的内部解剖。

## 方法详解
问题设定：学习条件分布 p(I_v, O, P | C, I_ctx)，输出任意相机视角 v 的近眼图像、前节 OCT 体 O、带四个标签（角膜前表面、角膜后表面、虹膜前/后表面）的解剖点云 P；条件 C = {p, r, d, τ, s} 分别是瞳孔位置（mm）、瞳孔半径（mm）、过角膜顶点与瞳孔中心的光轴单位向量、录制光照色调与受试者身份；新受试者只给一张或几张上下文图像。第一阶段 多模态解剖 VAE：OCT 体视为 D_o 张 B-scan 堆叠，用带步长的 3D 卷积下采样到 latent 网格分辨率，在最后一个 block 前按 OCT 设备标定在各 latent 单元的扫描位置采样，得 z_oct ∈ R^{G×d}；点云按标签分组，每组用共享 MLP 嵌点、加可学习标签嵌入，再用可学习 query 与多头注意力池化成 K 个 token，得 z_pcd ∈ R^{4K×d}，对点序不变；图像把每个 patch token 加上由标定算出的 Plücker 射线嵌入，使 token 具备三维感知、按几何而非视角编号区分视图，得 z_img ∈ R^{N_v T×d}。融合：拼成 [z_img; z_oct; z_pcd] 后，用每个 latent 网格单元一个可学习 3D query 做交叉注意力，再在 query 间自注意力，得排布在覆盖眼区三维网格上的 z_fused ∈ R^{G×d}，按标准 VAE 从预测高斯采样并以 KL 正则。解码是双路的：若干相机特定的 2D 解码器（学习 2D 网格 query，隐式把 3D 眼 token 投到该相机的 2D token 网格，再用 2D 卷积出图）与一个 3DGS 解码器（借鉴 TokenGS，用与像素布局无关的 3D Gaussian query，经 MLP 出高斯供任意光栅化器渲染）。作者发现只训 3DGS 头在少视角下不稳，必须与 2D 解码器同训才能让共享 latent 收敛。OCT 用 3D 上卷积出三维特征，再按设备标定在每个扫描体素采样得 Ô；点云用每个标签一组可学习 anatomy query 交叉注意力到三维特征，MLP 解码出该标签的点，最后用 RANSAC 拟合球面与平面读出生物参数。第二阶段 Eye Latent DiT：在冻结 VAE 的 latent 空间采样。条件编码把 p、d、r、τ 各过一个两层 MLP，身份 s 用 subject codebook 里的可学习嵌入 e_s，连同时间步嵌入 φ_t(t) 相加成 z_cond ∈ R^512，经 adaLN-Zero 调制每个 block。上下文编码器 E_ctx 用 VAE 图像编码器初始化，训成把上下文图映到接近目标 latent：L_ctx = ||z_ctx - z_fused||²；去噪时把 W_ctx z_ctx 加到输入 token 上（输入级条件），ŷ = f_θ(z_t + W_ctx z_ctx; z_cond)，预测干净 latent。总损失 L_VAE = L_oct + L_pcd + L_img + L_GS + L_KL（图像与 OCT 用 L1 + LPIPS，点云用对称 Chamfer，高斯项在视场掩膜内对渲染算 L1 + LPIPS）；L_DiT = E_{t,ε}[w_t ||ŷ - z||²] + L_ctx，w_t 按 velocity loss 加权。训练时随机把 I_ctx、e_s 与瞳孔条件 (p, r, d) 替换为可学习空嵌入，使一个模型既能只靠条件、也能只靠上下文或两者并用生成，并在采样时对预测的干净 latent 做 w = 1.25 的 classifier-free guidance。

## 实验与结果
- 新视角合成（单张上下文视图）：OCT-Cam-2V 上 24.89 dB PSNR，优于 GazePrior 20.23、ControllableGaze 21.81，也高于 MVSplat / DepthSplat / TRELLIS / ViewCrafter 等通用方法（均 < 20 dB）
- OCT-Cam-4V 上 1 视图 29.23 dB vs GazePrior 27.13、ControllableGaze 19.24
- 图像模态重建与生成（OCT-Cam-2V，test-seen）：重建 PSNR 26.30 dB / LPIPS 0.077，对比 ControllableGaze 18.62 / 0.354、GazePrior 17.30 / 0.442、Lin et al. 17.36 / 0.440
- 生成分布 Fréchet 距离 79.07，对比 ControllableGaze 250.01、GazePrior 335.85
- 多模态重建（VAE，test-unseen）：OCT-Cam-2V 图像 25.82 dB、OCT 25.08 dB、点云精度 0.081 mm、瞳孔位置误差 0.118 mm、光轴误差 0.93°、角膜前表面半径误差 0.039 mm
- DiT 生成降到 25.40 dB、光轴 1.11°、瞳位 0.139 mm，说明从条件生成几乎不掉保真度
- 下游眼动训练（Aria ET，OCT-Cam-2V，E50/E75/E95）：瞳孔位置 0.61 / 0.85 / 1.33 mm，优于 ControllableGaze 3.20 / 4.32 / 6.44、UnityEyes 2 10.55 / 12.37 / 16.69、GazePrior 18.96 / 21.17 / 24.46，接近真实数据 oracle 的 0.64 / 0.80 / 1.12
- 光轴 E50 4.17° vs 9.36°（ControllableGaze）与 2.84°（oracle）
- 跨设备泛化（Nymeria / Project Aria）：仅用合成数据训练时注视 E50 3.53°，优于 GazePrior 8.41°、UnityEyes 2 10.18°，接近 oracle 2.59°
- 合成 + 真实混训进一步把 E50 从 2.59° 降到 2.28°，OCT-Cam-2V 瞳孔位置从 0.64 mm 降到 0.44 mm
- 消融（test-unseen OCT-Cam-2V）：去掉 OCT 设备 warping，OCT LPIPS 从 0.247 恶化到 0.435、光轴从 1.11° 到 3.33°
- 去掉辅助 2D 解码器，图像 PSNR 24.76→22.27、半径误差 0.139→0.269 mm
- 去掉条件 dropout，无上下文生成时光轴误差达 5.12°

## 创新点与贡献
- 新意在于把「解剖」从监督信号提升为生成目标：OCT B-scan、带标签的解剖点云与近眼图像被压进同一个 z_fused，因此一个 latent 同时描述眼内部结构与眼周外观，解码后可直接从点云 RANSAC 读出光轴、瞳孔位置与半径、角膜面，而不是像 GazePrior 那样只能从模糊图像里猜
- 这让合成数据的控制维度从「注视」扩到注视 + 瞳孔半径 + 身份 + 视角四轴，且各条件解耦（扫一个条件只变一个因素）
- 第二个新意是身份的两条通路：已见受试者用 codebook 嵌入，新受试者用上下文编码器一次前向把上下文图映到 latent，无需像 GazeGaussian 那样 test-time 微调、也不必像 GazePrior 那样 few-shot 优化，这是首个 feed-forward 的一次性新眼仿真
- 第三是工程性的双路解码：少视角下只训 3DGS 头会让 latent 的三维一致性变差，与相机特定 2D 解码器同训才稳，这条经验对同类少视角 3D 生成也有参考价值

## 局限与风险
- 最硬的限制来自数据而非模型：训练依赖同步采集的近眼相机 + 前节 OCT，需专用设备与受控环境，自采 OCT-Cam-2V（78 人、7,931 体）与 OCT-Cam-4V（50 人、8,265 体）都是实验室数据，普通头显或智能眼镜无法复制这套采集，因此方法的可迁移性受制于能否获得 OCT 监督
- 跨数据集能力也有限：LightDome 没有 OCT 与瞳孔/光轴标签，DiT 无法在其上训练，只能靠 VAE 先验迁移，该集上 1 视图 PSNR 仅 18.08 dB，明显低于 OCT-Cam 系列
- 生成质量相对重建仍有落差：OCT 生成 PSNR 21.64 vs 重建 25.08 dB（OCT-Cam-2V），点云精度 0.223 vs 0.081 mm，说明解剖分支的生成保真度弱于图像分支
- 此外正文未给出代码仓库，仅项目页
- 眼动验证只覆盖 Aria ET 一个架构与两台设备（OCT-Cam 自采与 Aria/Nymeria），未验证到其他厂商头显的相机布局，也未报告合成数据在真实闭环追踪延迟、遮挡、眼镜反光等工况下的表现

# MatrixSplat：面向 GPU 的矩阵并行、特征可扩展 3D Gaussian Splatting（3D 高斯泼溅）渲染

## 一句话结论
Mip-NeRF 360 上端到端达 599.9 FPS（3DGS 156.0、3DGS+TC-GS 295.1），LERF 702.6 FPS、3D-OVS 510.9 FPS，最高为 3DGS 的 3.8×、TC-GS 的 2×；特征维 D=256 时渲染核时间降 36.7×；替换四个快速渲染器的混合核再获 1.69–2.84×，而 PSNR 30.35 dB 不低于 3DGS 的 30.12 dB。

## 要解决的问题
3DGS 已成实时新视角合成与重建的主流表示，但其渲染流水线与现代 GPU 算力结构错配，在语义特征场景下被急剧放大。首先，深度排序的 alpha 合成引入强 per-pixel 串行依赖：透射率更新 T_{j+1}=T_j·(1−α_j) 形成 loop-carried 的 read-after-write 链，warp 内无法跨迭代重叠指令，wait stall 主导而 Tensor Core 完全闲置。其次，语义 3DGS 需在百万级 Gaussian 上累积高维特征，一旦维度超过 128，特征向量无法驻留 shared memory，只能回落 global memory，性能断崖下降。第三，已有加速各只覆盖流水线一段：FlashGS、Speedy-Splat 优化剔除/排序但每像素仍串行标量循环；Sort-Free、Duplex-GS 去掉排序却仍用标量 FMA；TC-GS、GEMM-GS 把 alpha 计算搬到矩阵单元但混合循环仍顺序相关。缺口是：尚无工作利用顺序无关把特征累积本身表达为矩阵乘法。

## 方法详解
瓶颈定位（4.1）。剖析 LangSplat：渲染占 77% 延迟，RenderCUDA 核占 51.3%（排序 14.3%、解码 19.2%）；停滞以 wait 为主、short scoreboard 仅 10.2%，说明受依赖限制而非纯带宽限制。

顺序无关特征混合（OIEFB，4.2）。把 RGB、语义特征 f_i^l 与可选深度拼成统一嵌入 e_i^T = concat(c_i, f_i^l, [d_i])，维度 D = 3 + C [+1]（式 6）；不做深度序合成，而对每像素做归一化加权累积 E_p = (Σ w_{p,i} e_i + w_bg e_bg)/(Σ w_{p,i} + w_bg)（式 7）。权重用 LC-WSR 形式 w = α_i·max(0, 1 − d_i/σ)·v_i（式 2），σ、v_i、w_bg 可学并与高斯参数联合优化；附录 A 给出全梯度，论证端到端可微。加权累积可交换，故每个高斯贡献可独立求值——矩阵化的前提。

warp 级 MMA（4.3）。沿用 16×16 tile，再切 4×8 像素组、每组一个 warp（32 像素）。先算掩码 m = 1(α_{p,g} ≥ ε) 与 w̄ = m·w（式 9），32 像素上全零的高斯跳过；凑满 K_mma=16 个后构造 W ∈ R^{32×16} 与 E ∈ R^{16×D}，用 mma.m16n8k16（FP16）累加 Y = Σ_t W^(t) E^(t)（式 11）。同 warp 像素相邻、有效高斯集相似，零投票跳过率高；发射 MMA 时 warp 同时把后续高斯搬到寄存器，实现准备与执行重叠。

高维可扩展（4.4）。特征维按 8 通道切块（C_mma=8，与 MMA 输出 tile 对齐），第 q 块计算 Y_{:,8q:8q+7} = Σ_t W^(t) E^(t)_{:,8q:8q+7}（式 12）。每次 flush 只加载 8 维切片、下一片预取，故 shared memory 占用与 warp 占用率不随 D 增长。

## 实验与结果
- 数据集与指标：Mip-NeRF 360（配 GAGS 分割标签，PSNR/SSIM/LPIPS）、LERF 与 3D-OVS（mIoU 与 LocAcc）；主实验在 RTX 4090、沿用 3DGS 原设置，另在 RTX 6000 Ada 与 H100 复验；FPS 用端到端协议（预热 + 前后 GPU 同步多次计时），与加速方法比较时用 FlashGS 的 kernel-isolated 协议。
- 主结果：Mip-NeRF 360 上 599.9 FPS（3DGS 156.0、+TC-GS 295.1）、PSNR 30.35（30.12/30.14）、LPIPS 0.178（0.181/0.183）、mIoU 0.541（0.536）、LocAcc 0.730（0.698）；LERF 702.6 FPS（237.9/310.3）、mIoU 0.445（0.419）、LocAcc 0.679（0.632）；3D-OVS 510.9 FPS（162.0/294.8）、LocAcc 0.985（0.937）。
- 与顺序无关方法比较（kernel-isolated，D=8）：3D-OVS/LERF/Mip-NeRF 360 上 521.8/891.9/660.0 FPS，为 3DGS 的 2.48×/2.50×/2.37×，比 Sort-Free（240.3/256.1/215.7）快 2.2–3.5×，比 Duplex-GS（319.1/332.9/127.9）快 1.6–5.2×；Duplex-GS 的 PSNR 最高（3D-OVS 25.40）但 MLP 求值带来开销。
- 与快速渲染器组合：仅替换 FlashGS、GEMM-GS、Speedy-Splat、AdR-Gaussian 的混合核（保留其剔除/调度/排序）再获 1.69–2.84×，PSNR 变化不超过 0.24 dB；跨架构加速为 RTX 4090 2.37×、RTX 6000 Ada 2.36×、H100 2.33×。
- 组件消融（两数据集场景平均，低分辨率）：D=8 时 253.8→OIEFB 423.5→+MMA 741.1→+warp packing 830.5→+lazy fetching 830.8；D=256 时 2.3→2.1→38.0→35.7→72.1；D=512 时 1.1→1.2→17.4→22.4→41.1。OIEFB 单独在 D=8 给 1.67× 但随 D 衰减，MMA 是主增益，warp packing 在 D≤64 加 12–22%，lazy fetching 在 D≥64 加 1.6–2.0×；整体 D≤128 比 3DGS 快 2.1–3.3×、D≥256 快 31–37×。
- 特征维度可扩展性：混合核时间低维平均降约 3×、D=256 时降 36.7×；对照显示降精度不能解释——3DGS 改用 FP16 特征后速度变化不超过 17%，而本文核在相同场景仍快 2.2–4.8×（附录 D）。
- 质量与代价：保真度依场景而变，teatime 上 PSNR 降 0.23 dB（多重半透明重叠需精确顺序），counter 升 0.73 dB（避开视角相关排序误差）；停滞分析显示 wait stall 与 barrier stall 各降约 10%。

## 创新点与贡献
- 识别出「alpha 合成的顺序依赖」正是高维特征累积无法矩阵化的根因，并用顺序无关加权累积（式 7）把语义特征渲染改写为可交换求和，把计算原语从标量 FMA 换成稠密矩阵乘。
- 给出 warp 级、像素×高斯的打包式 MMA 映射：W ∈ R^{32×16} 与 E ∈ R^{16×D} 两次矩阵乘（mma.m16n8k16，FP16），配合 warp 内有效性零投票跳过，把可见性不规则转为打包效率问题。
- 提出 lazy channel-batched 特征取数（C_mma=8，与 MMA 输出 tile 对齐），只驻留当前 8 维切片并预取下一片，使 shared memory 占用与 warp 占用率不随 D 增长，这是 D=256/512 时 31–37× 增益的直接来源。
- 证明该优化与流水线级加速器正交：只替换混合核即可在四个既有渲染器上叠加 1.69–2.84×，为「改混合原语」与「减少工作量」两类优化提供可组合范式。

## 局限与风险
- （作者承认）顺序无关累积只是对深度序合成的近似，保真度依场景而变：极端多层半透明重叠会退化（teatime −0.23 dB），且为 alpha 合成调好的阈值需重新调参。
- （作者承认）只加速前向渲染；训练也变快但幅度更小，因反向仍依赖 scatter 梯度更新与原子操作。
- （作者承认）tile binning + radix sort、逐高斯预处理、warp 级打包扫描仍是非矩阵阶段，混合被加速后它们成为端到端加速的上界。
- （作者承认）只针对 NVIDIA Tensor Core 的 warp 级 MMA，未评估 NPU 等其它矩阵单元。
- （我在正文发现）正文仅承诺「will release our CUDA implementation and evaluation scripts」，抓取时无仓库链接，故 3.8×/36.7× 暂不可独立复现；Sort-Free 亦用第三方实现，基线的实现质量存在差异。
- （我在正文发现）质量评估集中在 PSNR/SSIM/LPIPS/mIoU/LocAcc 均值，缺少对顺序无关近似在连续视角切换下是否引起闪烁/popping 的评估，而这正是该近似的典型风险。

## 与文献库的关系
本文属 3DGS 渲染加速中「改计算原语」的一支，与「减少工作量」的流水线加速器互补。横向对照清晰：FlashGS（Feng 2024）、Speedy-Splat（Hahlbohm 2025）、AdR-Gaussian、HiGS 优化剔除/调度/排序但保留逐像素标量累积；TC-GS（Lee 2025）与 GEMM-GS 把 alpha 计算搬到 Tensor Core、ORANGE 搬到 NPU，但混合循环仍顺序相关；Sort-Free（LC-WSR）、StochasticSplats、Duplex-GS 去掉排序却仍以标量 FMA 累积——Table 1 把这三类与本文的「Accumulation (TC) / Order=None / Dim=Native」区分开。特征侧针对 LangSplat、LangSplatV2、Feature-3DGS 的「先压缩再渲染」路线，主张在原生维度直接渲染；本质是把 weighted-OIT（McGuire 2013）在语义 3DGS 上重新落地并硬件化。

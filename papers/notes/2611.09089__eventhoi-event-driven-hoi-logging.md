# EventHOI：智能眼镜上事件驱动的手-物交互低功耗记录

## 一句话结论
在 50 小时 Nymeria（97 人）基准与 19.8 小时自采真机数据上，EventHOI 将常开后端功耗降低 5.8–10.4×、上行带宽降低 2.9×（降至 <130 kbps 以适配 BLE），而 HOI 识别精度仅下降 1.2%。

## 要解决的问题
智能眼镜做全天候第一视角 hand-object interaction（HOI）记录时，连续 RGB 采集（200–600 mW）与无线回传（720p/15 FPS 需 2–5 Mbps）远超其能量与带宽预算，Wi-Fi 回传外加约 0.4 W、续航仅约 0.7 小时；BLE 虽低功耗但吞吐可低至 0.3 Mbps，不足以承载保精度的 RGB 流。已有的低功耗触发方案（如 EgoTrigger 用音频、THOR 用热成像约 150 mW）仍依赖周期性 RGB 抓拍或本身功耗偏高，无法同时解决「何时采」与「采多少/传多少」两个问题。

## 方法详解
核心思路是用超低功耗 event camera（<10 mW）同时决定「何时需要 RGB」与「哪里必须保留细节」。先用 IMU 做 egomotion cancellation：一个 2 层 LSTM 平移检测器（6 轴 IMU、50 Hz、0.5 s 窗口，37k 参数）以 0.5 m/s 为阈值门控掉行走等大位移段，剩余以头转动为主的分量用陀螺仪积分并从事件帧中消去，抑制背景事件。残余 HOI 运动经稀疏 LK 光流聚合得到 HOI motion detector，超过阈值（默认 5% 面积）即触发 RGB 抓拍，并保留 0.1 FPS 兜底采样兜住近静止交互。HOI-aware encoder 再按事件显著性生成 RoI、做空间裁剪（最小保留 75% 帧）与时间稀疏化，把上行压到 <130 kbps 走 BLE。系统在 Raspberry Pi Zero 上配合事件/单色相机、RGB 相机与 IMU 实现端到端原型，后端由 VLM（Gemini-2.5-Pro、GPT-5.2）完成 HOI 识别与时间定位。

## 实验与结果
1) 基准：Nymeria 50 小时、97 名受试者、覆盖多种日常场景，事件帧由 v2e 从 RGB 仿真（10 小时子集用于调参）。2) 真机 testbed：2 个家庭 + 1 间办公室 + 2 个开放工位，10 名参与者共 19.8 小时，按自然密度采集而非脚本化。3) 同等 0.5 FPS 有效帧率下，HOI 识别精度比均匀采样平均 +9.0%；在 0.12 Mbps 同等带宽下比 0.35 FPS 均匀采样 +12.2%。4) 细粒度：物体识别 +22.1%（手机、容器、衣架等小物体 >30%），手部动作 +17.8%（开门、舀食、挂衣等短动作 >35%）。5) 系统实测：后端功耗降 5.8×（对比连续 RGB）至 10.4×（对比端上 YOLO 1 FPS 手部检测），真机有效帧率 1→0.42 FPS（2.4×↓），日均省电 33%（Nymeria）/41%（testbed）。6) sim-to-real 校验：v2e 仿真与真实事件帧光流中位角误差 10–11°，所选帧 IoU 仍达 0.95、精度变化 −0.2%。

## 创新点与贡献
1) 把「事件触发」与「事件引导压缩」统一到一个事件域流水线，用同一路低功耗信号同时决定采样时刻与空间保真区域，而非两级独立模块。2) 提出基于「大位移时少有有效 HOI」先验的 IMU-only egomotion cancellation，绕开 VIO/SLAM 的像素级匹配开销，也避开 ZUPT 对头戴 IMU 不适用的缺陷。3) 首次把 egocentric HOI 日志的上行压到 BLE 可承载的 <130 kbps，并同时给出大规模仿真基准 + 多场景真机 testbed + 功耗/延迟实测的端到端证据链。

## 局限与风险
1) 触发器阈值（C=5%）与最小帧尺寸（S=75%）偏经验，>5% 后精度陡降，跨场景迁移需重调。2) 背景运动与高纹理是主要误触发源：电视动态内容多抓 3.8% 窗口、旁人/宠物 0.3%、窗帘/百叶/键盘/床单等纹理 1.7%，会在真实家庭中长期累积能耗。3) 事件帧主要来自 v2e 仿真，sim-to-real 仍有 10–11° 光流误差，作者以「对选择影响可忽略」论证但未做真实事件相机的大规模闭环。4) 真机仅 10 人、19.8 小时，长尾活动覆盖有限；且论文只给项目页与 demo 视频，未见代码/数据开源承诺，复现门槛高。

## 与文献库的关系
属于「低功耗传感器引导高功耗传感器」的系统族，与 EgoTrigger（音频触发）、THOR（热成像触发）、以及各类 event-based 可穿戴感知工作同线，但首次把触发与码率控制合到事件域；与 Nymeria、Ego4D、HD-EPIC 等 egocentric HOI 数据集是互补关系（借用其做基准，不替代其标注）；相对 Ego4D 系的纯 CV 方法，本文是新增的系统与平台方向而非模型改进。

## 可复现性（代码/数据/硬件）
项目页 https://eventhoi.github.io 与 demo 视频公开，论文未见 GitHub 代码库或数据集发布声明；硬件为自建原型（Raspberry Pi Zero + 事件/单色相机 + RGB + IMU），需自行搭建；基准依赖 Nymeria 授权访问。整体可复现性中等偏弱。

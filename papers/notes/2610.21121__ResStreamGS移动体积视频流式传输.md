# ResStreamGS：残差敏感双流高斯泼溅，移动端体积视频流式传输

## 一句话结论

把场景高斯按「时间稳定性」分成静态流与残差流：静态高斯在 GOP 级复用一次编码，仅对残差敏感高斯做帧级视频编码，在 Neu3D/MeetRoom 全场景体积视频上比 V³ 式基线 PSNR 高 7.51–8.35 dB、payload 降低至多 56.5%，并在商品移动硬件上跑到 30.883 FPS。

## 要解决的问题

移动端自由视点体积视频受带宽与算力双重约束。V³ 一类系统把全部高斯属性按时变信号用商品视频编解码器编码，但全场景内容中大部分高斯时间稳定，「一视同仁」的帧级编码既浪费码率又因帧级自适应损伤复杂全场景的重建质量。已有流水线缺乏对「哪些高斯该保持帧级自适应」的判据。

## 方法详解

ResStreamGS 是一个残差敏感的双流框架，核心是把高斯的时序行为作为划分依据：

1. **轻量探针自适应（probe adaptation）**：先做一次轻量的帧级自适应探针，获得高斯随时间的变化证据，避免直接对全量高斯做代价高昂的帧级编码。
2. **多属性残差敏感度画像（multi-attribute residual-sensitivity profiling）**：不仅看位置位移，还综合 rotation / scale / opacity / color 五个属性的变化幅值，对每个高斯计算残差敏感度。
3. **质量感知比率选择（quality-aware ratio selection）**：按目标码率质量选择进入帧级视频流的动态高斯比例（如 8%）。
4. **双流编码**：静态高斯在 GOP（图像组）级复用，只编码一次；残差敏感高斯走帧级视频流，由硬件解码器解码。

划分在 GOP 内固定。消融显示：固定 8% 动态比率下，全属性排序比随机选择 PSNR 高 2.798 dB；仅用位置排序达 31.193 dB，逐一叠加 rotation/scale/opacity/color 分别再得 0.380/0.194/0.144/0.129 dB，五属性联合 32.745 dB（比单用位置高 1.552 dB 且 payload 接近），说明这些线索互补而非冗余。

## 实验与结果

- **数据集**：Neu3D（5 条全场景序列平均）+ MeetRoom，均为全场景（full-scene）内容，正是静态-动态混合最突出的场景。
- **Neu3D**：ResStreamGS PSNR 33.04 / SSIM 0.9425 / LPIPS 0.107 / DISTS 0.03756，payload 1.627 MB，支持移动端播放；对照 V³ 25.53 dB / payload 3.741 MB；未压缩参考 34.60 dB / 107.81 MB。4DGS 与 GIFStream 不支持移动播放。
- **MeetRoom**：ResStreamGS 33.04 dB 级、payload 1.627 MB 级（对照 V³ 25.38 dB / 0.304 MB）。
- **综合结论**：较受控 V³ 式基线 PSNR +7.51–8.35 dB；payload 最多降 56.5%；商品移动硬件 30.883 FPS。

## 创新点与贡献

1. 指出并验证「全高斯帧级编码」在全场景体积视频上的质量损伤，把问题重构为「哪些高斯该帧级自适应」的划分问题。
2. 多属性残差敏感度画像：位置不是唯一线索，五属性联合有互补增益（实验证据充分）。
3. GOP 级静态复用 + 帧级残差流的双流架构，兼顾硬件解码与码率。

## 局限与风险

- GOP 内划分固定，难以捕捉大幅或突兀的时序变化（作者自述）。
- 残差比率在视频编码前选定，未随内容显式联合优化。
- 在两个学术序列上验证；更多样的真实 capture 与更长时序的稳定性待考。
- 未报告与库内同期 3DGS 压缩/流式工作（如 MoQSplat、SAGA）的同基准对比，相对定位需谨慎。

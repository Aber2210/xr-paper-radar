# CueSplat：学习调度稀疏形变以实现边缘设备上的动态高斯泼溅

## 一句话结论
冻结 4DGS 主干、按预测可靠性与渲染贡献调度稀疏形变评估，Jetson AGX Orin 上取得 1.75–6.74× 加速，PSNR 仅降 ≤0.16 dB。

## 要解决的问题
基于形变的 4D Gaussian splatting 在每个时间步都要对所有 Gaussian 求解形变网络，边缘设备上代价极高——E-D3DGS 在 Jetson AGX Orin 上形变约占 GPU 流水线时间的 85%。现有加速依赖 Gaussian 剪枝、静动态分解或共享运动表示，但剪枝与限制运动表达会损伤重建质量，静动态划分在渲染期间固定不变，把动态 Gaussian 误判为静态会破坏运动重建。

## 方法详解
CueSplat 是 post-training 框架：冻结预训练 backbone 的 canonical Gaussian 与形变参数、保留完整 Gaussian 集合，只在其上做稀疏形变调度。其动机来自测量——五帧内 static/linear/quadratic 拟合可覆盖 N3DV 66.2%、Technicolor 68.8% 的 Gaussian-window 对，但 54.4% 采样 Gaussian 在某些窗口满足五帧拟合、在另一些窗口违反，说明局部规律存在而可靠性随 Gaussian 与时间变化。在线推理先用最近三个已接受状态做阻尼有限差分外推预测全部属性（位置 λ_v=0.85、λ_a=0.15；旋转用阻尼四元数增量；尺度保持；动态外观从同三帧滤波；静态属性取 canonical 值），再由轻量 MLP router（约 2.0k–2.6k 参数）依据冻结 descriptor、编码时间戳与运动/可见性/贡献/更新年龄等在线特征打更新分，取 TopK 作为精确更新子集，替换预测值后合并渲染。为降低路由开销，每 N=5 帧才重算特征与索引并在帧间复用，但被选中的 Gaussian 每帧仍做精确形变。离线先按 rendering-aware risk ρ=m_vis·o·πr²/(HW)·[log(1+e)]² 标定场景级预算 K_s（取标定帧提议的 90 分位并向上取档），经 oracle 闭环检查（代理 PSNR 均值 ≥40 dB、10 分位 ≥37 dB）通过后，用教师信号（五类属性误差按帧内中位数归一后由可见性、不透明度、投影半径加权）生成 top-k 二值标签与连续优先级，以 ranking + BCE + SmoothL1 三项损失训练 router，再做第二轮闭环验证，不达标就升档。为控制误差累积，用漂移信号 d_t=0.4Ē+0.2r̄+0.2m̄+0.2a 触发连续三帧全形变刷新（最小间隔 20 帧、连续两次帧级分数 ≥0.6 触发、最迟 s+40 强制），并把刷新所需的精确评估分摊到前 10 帧预计算以削平延迟尖峰。

## 实验与结果
- 12 组 backbone–dataset 组合（E-D3DGS / 4DGaussians / GaGS / SpeeDe3DGS × Technicolor / N3DV / NeRF-DS）在 Jetson AGX Orin 上取得 1.75–6.74× 加速，数据集平均 PSNR 下降至多 0.16 dB
- Orin NX 上 1.81–8.15×，A6000 上峰值 5.04×
- 代表点：Technicolor 上 GaGS 由 10.65 FPS 提升至 71.79 FPS（6.74×，PSNR 32.99→32.92）
- N3DV 上 E-D3DGS 15.64→38.24 FPS（2.45×，27.92→27.88 dB）
- NeRF-DS 上 4DGaussians 72.26→126.27 FPS（1.75×）
- 慢帧性能：GaGS/Technicolor 的 FPS P5 由 10.63 升至 52.58
- 加刷新预计算后 N3DV 上 FPS P5 由 17.68 升至 26.20（+48.2%），平均吞吐只降 0.3%（40.95→40.81 FPS）
- 执行计算量：服务端 profiling 显示每帧 GPU warp 指令减少 29.9%–90.7%，GaGS/Technicolor 由 8206.42M 降至 760.01M
- 对 DASH：Technicolor 上四个 backbone 的平均 PSNR 均优于 DASH-style 对照，E-D3DGS +0.37 dB、4DGaussians +0.26 dB、GaGS +0.22 dB（FPS 高 81.3%）、SpeeDe3DGS +1.19 dB（+26.3% FPS）
- 但与官方 DASH 复现（31.12 dB / 39.13 FPS）相比，SpeeDe3DGS+CueSplat 为 30.91 dB / 37.50 FPS，略低
- 消融（Technicolor 50 帧、四 backbone 平均）：学习路由比 motion-magnitude 排序高 1.44 dB（32.50 vs 31.06，LPIPS 0.0914 vs 0.1018）
- 时间外推比 hold-last 高 0.21 dB
- 场景级预算比统一 20% 预算高 1.22 dB
- 三帧刷新比单帧刷新 PSNR 27.50→27.88 dB（FPS 41.83→38.36）

## 创新点与贡献
- 把“选择性计算”引入冻结的 4DGS 形变网络：不剪枝、不改 Gaussian 集合、不做静动态硬划分，而是把每帧形变评估变成按预测可靠性与渲染贡献动态分配的预算，这是相对剪枝、分解、共享运动三条现有加速路线的实质差异
- router 由教师信号监督，并配合离线 oracle 与闭环质量门控的场景级预算标定，使加速比随场景风险自适应而非全局固定
- 漂移触发的三帧历史重建加上刷新预计算，补上了“预测-反馈”闭环里误差累积与延迟尖峰两个工程缺口

## 局限与风险
- 作者在结论中明确承认当前实现假定按均匀时间步顺序渲染（'The current implementation assumes sequential rendering at uniform time steps'），时间跳转（temporal seeking）与变速播放尚不支持，被列为未来工作
- 每个 scene–backbone–budget 组合都要单独训练 router，场景级准备在 RTX A6000 上需 1–2 分钟、预算升档再加约 1 分钟，部署前准备成本不低
- Technicolor 的 50 帧序列在初始化后直接禁用刷新，说明刷新机制在短序列上未经检验
- 与 DASH 官方复现相比 SpeeDe3DGS+CueSplat 的 PSNR 与 FPS 都略低，跨方法比较并非全面占优

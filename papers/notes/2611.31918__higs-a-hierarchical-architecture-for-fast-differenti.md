# HiGS：面向快速可微 3D Gaussian Splatting 的层次化架构

## 一句话结论
把 3DGS 的三个角色拆到不同粒度：8×8 tile 只做光栅化、64×32 macro-tile 做划分与排序、bounded batch 做独立工作与反向求导——1080p 2756 FPS / 4K 1533 FPS（相对 gsplat 5.1×/5.6×），负载不均视角上快 6.8×–20.0×，训练 61.5 s vs 194.4 s。

## 要解决的问题
标准 3DGS 让同一个屏幕 tile 同时充当划分单元、光栅化单元与并行工作单元，三者对 tile 尺寸的偏好相互冲突：划分要大 tile 减少 (tile, Gaussian) 对，光栅化要小 tile 减少无效像素求值。结果是在 4K 下每帧要对数千万对做全局 radix sort，且帧时间由最密 tile 的尾部效应决定，而不是由该视角的实际工作量决定；训练侧反向传播的 atomic 竞争与 Adam 带宽成为主瓶颈（FP32 下每 Gaussian 708 字节优化器状态）。

## 方法详解
HiGS 把三个角色拆到不同粒度：以 8×8 渲染 tile 为光栅化单元，把 M=32 个相邻 tile 组成 64×32 像素的 macro-tile 作为划分与排序单元，再以「(macro-tile, batch)」为独立工作单元，每个 batch 至多 B_r=1024 个 Gaussian 并按深度排序。分箱时以 B_p=8192 为一批，在线程组本地存储维护每 macro-tile 的直方图（1080p 约 1000 项、4K 约 4000 项），用分层前缀和算出写偏移，再直接写入 (depth, Gaussian-id) 对；由于 segment 已隐含 tile 身份，排序键从 64-bit 复合键缩成 32-bit 纯深度，记录从 12 字节降到 8 字节。排序是六段无主机同步的流水：四级 block radix sort 按 segment 规模分档，超出最大档的 segment 先切成 8192 的 run 排序再用 merge path 归并。光栅化在每个单元内分两阶段：协同加载 batch 时用不透明度阈值椭圆对 M 个 tile 做重叠测试，得到 P×M 位矩阵后转置，使每个 tile 获得 P 位可见性掩码；随后 worker group 从共享 tile 队列动态认领 tile，经容量 2B_d 的调度缓冲以 B_d=64 为粒度排空到固定速率的混合核，并在每像素透过率饱和时一致投票提前退出。跨 batch 用前向 alpha 混合的结合性做合成：C=Σ F_i C_i，F_i=∏_{h<i}T_h，保持与 3DGS 完全一致的前到后精确合成。数值上以 Σ^{-1}=LL^T 的 Cholesky 因子替代 conic 系数避免抵消，位置相对 macro-tile 中心降到 FP16 避免溢出，SH 用 YCoCg + 非均匀量化压到 32 字节。训练复用同一批单元：合成阶段顺带产出每 batch 的 F_i 与后缀色 S_i=Σ_{h≥i}F_hC_h，反向单元只需本 batch 加这两个边界量即可独立求导；Adam 融进反向投影（每 Gaussian 一线程，梯度留在寄存器），参数除位置外存 FP16、两个矩存 BF16（708→360 字节）并采用随机舍入；对被视锥剔除的 SH 系数用稀疏在线学习的闭式惰性更新 Δθ=-ηmΦ/(√v+ε_AΦ/Ψ)，按 32 个 Gaussian 一组记录最后更新步。

## 实验与结果
- 渲染 2756 FPS @1080p、1533 FPS @4K；相对 gsplat 快 5.1×/5.6×，相对近年优化光栅器快 1.5×–5.6×
- 负载不均的 120 个驾驶视角上快 6.8×–20.0×；最均衡到最不均衡视角间 HiGS 帧时间仅涨 1.6×，基线涨 3.0×–5.9×
- 重建比次快方法快 2.3×–3.0×、比 gsplat 快 5.9×–7.3×，显存比最省方案少 1.9×（Mip-NeRF 360：49.3 s / 2.02 GiB，gsplat 309.4 s / 3.87 GiB）
- 1080p 平均仅 1.51M、4K 2.21M 对，比 gsplat 的 16×16 不透明度感知包围盒少 2.7×/4.3×
- 深度排序 0.03–0.06 ms，gsplat 全局 radix sort 在 4K 为 0.44–1.10 ms；比通用分段排序快 4.6×–6.0×
- 训练 61.5 s vs 起始配置 194.4 s（3.2× 加速，显存少 34%），PSNR 差 0.01 dB

## 创新点与贡献
- 用一次分解同时解决排序规模、尾部效应与训练反向三个问题：macro-tile 分箱让排序变成互不相关的 segment 并把 tile 位从排序键中彻底移除，bounded batch 让任意稠密列表都能驻留片上存储
- 把「一个 batch 既是渲染单元也是反向求导单元」落实为可实现机制，合成阶段顺带留下的边界状态使 batch 间可完全独立求导，无需 per-tile 梯度缓存
- 优化器侧把 Adam 融进反向、状态降精度配随机舍入、并对被剔除的 SH 做闭式惰性更新，使显存流量随「视角看到多少」而非场景规模增长

## 局限与风险
- 并行性以显存和带宽为代价：每个 batch 都要预留并写出自己的输出，且即使被不透明前景完全遮挡仍会被光栅化，在「所有 Gaussian 都覆盖全屏」的退化场景下开销随遮挡层数线性增长
- 方法针对 commodity GPU 的 CUDA 实现，未覆盖移动/XR 端芯片，也未验证超过单卡显存的大场景
- SH 打包与 FP16 路径引入约 55.6 dB 的重建一致性误差，虽在指标上不可见但非比特精确

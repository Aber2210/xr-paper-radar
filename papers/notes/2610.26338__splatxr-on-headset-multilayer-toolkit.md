# SplatXR：基于端侧 3DGS 的多层 XR 工具包

## 一句话结论
SplatXR 是面向多层 XR 的 Unity 工具包（UIST '26 接收，DOI 10.1145/3830398.3830681），以 4 个 building block（Splat Renderer/Splat Physics/Splat Effects/Splat Blending）在 Meta Quest 与 Apple Vision Pro 端侧渲染 3DGS，支持 passthrough AR 与全沉浸 VR，splat 可投影阴影、与环境做刚体碰撞，并在 AR 中与物理场景混合。

## 要解决的问题
3DGS 内容进入 XR 应用存在工程断层：现有 splat 渲染器多为演示级，缺少物理交互（阴影、碰撞）、特效与虚实混合能力，且很少面向 standalone 头显的算力约束设计；开发者在 Unity 中组装 splat 化多层 XR 体验缺乏可复用工具。SplatXR 要提供一个经技术评估的模块化端侧 3DGS XR 工具包。

## 方法详解（含关键公式/架构，保留原文术语）
以 Unity package 形式分发，经 Package Manager 安装；提供嵌入 Unity Editor 的开发者 GUI（panels/scripts/materials/shaders），building block 可在 Editor 场景视图交互预览，操作直接增改项目资产与场景层级。四大 building block：B1 Splat Renderer——面向 standalone XR（Meta Quest、Apple Vision Pro）的 3DGS 渲染管线，Quest 上支持全沉浸 splat VR 与 passthrough AR 混合，可 untethered 或 tethered 运行，Vision Pro 受 Apple PolySpatial 平台限制 passthrough shader 功能受限，且渲染器兼容非 XR 应用；B2 Splat Physics——基于 mesh augmentation 程序，支持 splat 向环境投影阴影、splat/经典 mesh/环境间的刚体碰撞；B3 Splat Effects——可定制 shader 程序，实现物体消解-重组（dis- and re-integration）等视觉效果；B4 Splat Blending——AR 中物理场景与虚拟场景的混合。

## 实验与结果（表格化关键数字）
digest 未包含完整性能数字表；论文含技术评估（附录 A.2 Technical Evaluation）与 HCI toolkit 研究方法论讨论（引 DART、Remotelab、VR-pipe 2502.17078、Radiance fields in XR survey 2508.04326、InteRecon 等 CHI/UIST 文献），评估覆盖开发者工作流与 building block 功能正确性。

## 创新点与贡献
① 面向多层 XR 的系统性 3DGS 工具包，把渲染/物理/特效/混合四类能力模块化为可组合 building block。② B2 的 mesh augmentation 使 splat 在端侧具备阴影与刚体碰撞等物理交互，打通 splat 内容与 Unity 物理生态。③ 开发者 GUI 加 Editor 内交互预览，降低 splat XR 应用开发门槛。④ 在 Quest 与 Vision Pro 双平台验证端侧可行性，并诚实披露平台限制（PolySpatial 对 passthrough 的限制）。

## 局限与风险
digest 未报告帧率、显存、加载时长等关键性能数字（在附录 A.2，需查原文）。Vision Pro 上 passthrough 混合受 PolySpatial 平台限制，能力不完整。工具包绑定 Unity 生态，非 Unity 引擎项目难以受益。作为 UIST toolkit 论文，其评估深度可能不及算法类工作。

## 行动建议
① Unity 技术栈的 MR/AR 团队可以 SplatXR 为起点验证 splat 内容端侧可行性：B1 渲染加 B4 虚实混合做 passthrough AR 原型，Quest 优先（Vision Pro 注意 PolySpatial 限制）。② 需要 splat 物理交互（阴影/碰撞/消解重组）时，评估 B2/B3 的 mesh augmentation 与 shader 定制成本。

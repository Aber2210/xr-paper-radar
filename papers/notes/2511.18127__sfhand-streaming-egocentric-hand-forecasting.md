# SFHand：流式第一视角 3D 手部预测的预测式表征学习

## 一句话结论
SFHand 以自回归流式架构 + ROI 增强记忆实现语言引导的实时 3D 手部预测，ADE 由 HaMeR+In. 的 18.03 降到 12.65（-30%），33.4 FPS，下游 Franka Kitchen 成功率 79.9%。

## 要解决的问题
现有 3D 手部动作预测方法本质是离线的：必须先累积多帧观测再一次性预测，无法用于低延迟实时交互；同时它们是单模态的，只吃视觉输入，无法接受自然语言指令来表达任务意图。这使 AR 辅助、具身操作等需要「提前半拍」的场景缺少可用模型，且缺少带同步语言标注的大规模训练数据。

## 方法详解
把任务定义为流式自回归：每步输入文本指令 l、当前视频帧 v_t 与当前手状态 h_t（推理时用上一步自身预测），输出下一帧手状态 h_{t+1}，其中 h 含左右手类型、2D 检测框、MANO 参数化 3D 姿态与全局 3D 轨迹。三个独立编码器分别得到 f_l、f_v、f_h；视觉与手部嵌入拼接后进入 ROI-enhanced memory 层 M：以固定长度 FIFO 队列保存最近 N 个历史嵌入 [f_v; f_h]，当前嵌入作 query、队列作 key/value 做注意力，并在注意力分数上加一个由当前 2D 手框生成的二值 ROI mask 偏置，使历史检索聚焦手部区域。记忆增强后的嵌入与 f_l 拼接送入 DETR 风格 transformer decoder，用一组可学习 detection queries 一次回归出下一帧的手状态（框 + MANO + 轨迹）。训练在 8 卡、batch 256/卡、AdamW 2e-4 下完成，下游操作任务冻结编码器只训轻量预测头。

## 实验与结果
自建 EgoHaFL：247K 视频片段（约 90 帧/段，242K 训练 / 5K 测试）、3.95M 帧 3D 手部标注并配细粒度语言描述，是首个同步视频-语言-3D 手的数据集。在 EgoHaFL 测试集上：SFHand ADE 12.65 / FDE 13.08，对比 HaMeR+In. 18.03/17.13（约 -30%/-24%）、EgoH4 22.56/22.87、USST 49.15/55.20，JPE 3.38 也最低；FPS 33.4（HaMeR 105.1 但无记忆与语言），oracle 变体 SFHand* 达 58.8 FPS、ADE 10.39。记忆消融：无记忆 15.56/18.38，加记忆无 ROI 反而退化到 18.34/22.23，记忆 + ROI 12.65/13.08，说明 ROI 偏置是必要项。模态消融显示去掉视频对轨迹影响最大，去掉语言在轨迹指标上退化，去掉手输入在 ADE/FDE 上退化最明显。下游 Franka Kitchen 平均成功率 79.9%，Adroit 上同样领先，任务成功率最高提升 13.4%。

## 创新点与贡献
- 首个流式、语言可引导的 3D 手部预测框架，把「先攒帧再预测」的离线范式改为逐帧自回归。
- ROI-enhanced memory：用当前手部 2D 框生成注意力偏置，把固定长度 KV 队列的检索聚焦到手部区域，消融显示缺它反而比无记忆更差。
- 构建 EgoHaFL（247K 片段 / 3.95M 帧）并验证预测式手部表示可迁移到机械臂与灵巧手策略学习。

## 局限与风险
- 依赖 MANO 参数化表示，极端关节角与严重遮挡下泛化受限。
- 33.4 FPS 虽满足实时，但明显低于纯视觉 HaMeR 的 105 FPS，多模态编码器带来延迟成本。
- 自回归推理存在误差累积，长期预测（多帧外推）稳定性未系统评估。
- 语言条件是静态整段指令，不支持对话式、逐步变更的意图输入。

## 与文献库的关系
位于手部动作预测（HaMeR、EgoH4、USST）与流式时序记忆（StreamVLM、RoMem 一类 KV 记忆）两条线的交叉点；与 EgoVid/EgoHOD 等第一视角数据集工作互补，并衔接 VibBot、R3M 等具身表示学习。

## 可复现性（代码/数据/硬件）

## 行动建议
做 AR 手势预判或遥操作意图推断可直接复用其流式接口与 ROI 记忆设计；若追求更低延迟，应优先压缩文本/手部分支而非牺牲记忆。

# GaussianMamba：三维高斯基元的几何与关系感知状态空间扫描

## 一句话结论
把高斯基元的各向异性 support 写进 Mamba 序列构造，nuScenes-SurroundOcc IoU 29.83→32.41，代价是推理延迟 +31%。

## 要解决的问题
3D 语义占据预测需要建模场景的空间结构与上下文关系。3D 高斯基元是稀疏自适应的表示，Mamba 能以线性代价提供长程上下文，但高斯基元本身不规则且无序，没有预定义遍历顺序。按原始索引或坐标排序会引入不连续，并忽视基元的各向异性 support；仅靠空间邻近也无法刻画学习到的特征与语义预测之间的关系。单一扫描顺序无法同时保持几何邻域与特征-语义邻域。

## 方法详解
在 GaussianFormer / GaussianFormer-2 的迭代细化架构上，为每个高斯基元维护中心 mu、各向异性尺度 s、旋转 R（四元数，协方差 Sigma=R diag(s)^2 R^T）、不透明度 alpha、语义概率 p 与实例特征 f。核心量是 support-normalized separation：rho_i(n_ij)=||diag(s_i) R_i^T n_ij||_2 为高斯基元沿连线方向的一倍标准差投影，g_ij = d_ij / (rho_i + rho_j + eps)，g_ij<=1 视为两个椭球在该方向上接触。CGSS（Contact-Guided Spatial Sequencing）先用量化中心构造 3D Hilbert 初始遍历，再在互不重叠的局部窗口 W=32 内做相邻交换，邻接代价 c_ij=log(1+g_ij)+d_ij/d0+|h_i-h_j|/W，仅当总边长与最大边长增长分别不超过 5%/10% 时接受交换，窗口端点固定，两轮 sweep 后得到几何序。DRSS（Directional Relation-Aware Semantic Scanning）先用 XYZ 蛇形遍历构造初始序，按 S=128 个基元一组、K=8 组一个 macro-block，组描述子为归一化均值特征、仅取高置信基元（max prob>=tau_c）的语义描述子与均值中心；组间亲和度 A_uv = f_u^T f_v + m_uv p_u^T p_v - min(||mu_u-mu_v||/d_a,3) - |u-v|/(K-1)，在 macro-block 内从首组贪心选最高亲和未访问组，末组固定。随后做 support-weighted boundary correction：以总变差 t_ij=0.5*||p_i-p_j||_1 度量语义分歧，接触因子 eta_ij=sqrt(alpha_i alpha_j) exp[-0.5 max(g_ij-1,0)^2]，权重 w_ij=t_ij exp[-(d_ij/r0)^2] eta_hat_ij，对每个基元取最高分邻居 j*，令 Delta_r,i = w_{i,j*} [LN(f_i)-LN(f_j*)]，即把特征推离跨预测边界的邻居。两序分别送入独立参数的单向 Mamba，再经 GSDF（Gaussian Support-Discrepancy Fusion）融合：k_ij=exp(-g_ij)，xi_b,i 为沿该扫描路径的 support 加权局部特征变化，q_b,i 为平均亲和，校正 Y'_b,i = Y_b,i + lambda q_b,i (xi_b,i - xi_b',i)，lambda=tanh(theta) 初始为 0（即从纯拼接起步），最后拼接后线性投影。每个细化阶段后接一层扫描层（共 4 层），末段经 Gaussian-to-voxel splatting 输出占据栅格。

## 实验与结果
- nuScenes-SurroundOcc：GaussianFormer 从 29.83 IoU / 19.10 mIoU 提升到 32.41 / 20.55（+2.58 / +1.45），超过 SurroundOcc 的 31.49 / 20.30
- GaussianFormer-2 从 30.56 / 20.02 提升到 32.98 / 21.12（+2.42 / +1.10），为该表最高
- SSCBench-KITTI-360 单目设定：GaussianFormer 35.38 / 12.92 -> 37.87 / 13.95（+2.49 / +1.03）
- GaussianFormer-2 38.37 / 13.90 -> 40.57 / 14.80（+2.20 / +0.90）
- nuScenes 上 GaussianFormer-2 在全部 16 个类上均提升，GaussianFormer 提升 13 个类
- drivable surface 分别 +6.25 与 +3.14，terrain 亦一致改善
- KITTI-360 上 road/sidewalk/building/vegetation 提升 +2.2 至 +3.8，单类回退不超过 0.35
- 扫描策略对照（均双分支、拼接融合）：Hilbert+Hilbert 30.24 / 19.23，Hilbert+XYZ 30.48 / 19.42，CGSS+DRSS 31.82 / 20.25
- 同等双分支容量下比 Hilbert+XYZ 高 0.83 mIoU，代价为 7.6 ms 额外延迟
- 组件消融：单 Mamba 30.05 / 19.18
- +CGSS 30.88 / 19.48
- +DRSS 30.68 / 19.62
- 三者全开 32.41 / 20.55
- CGSS 与 DRSS 联合增益 1.02 高于各自增益之和（0.25 与 0.39）
- 融合与效率：GSDF 比拼接提升 0.30 mIoU，仅增 0.40K 参数与 2.0 ms
- cross-attention 参数为拼接的 4.7 倍却只多 0.04 mIoU
- 加入扫描后 144K 高斯延迟由 354.71 ms 升至 466.12 ms（约 +31%），25.6K 时 +30.61 ms，参数 +0.8M、显存 2.77->2.79 GB

## 创新点与贡献
- 首次把高斯基元的各向异性 support（尺度加朝向投影出的一倍标准差范围）显式写进 Mamba 的序列构造，而非沿用坐标排序或空间填充曲线
- 并据此派生统一的 g_ij，同时驱动几何排序代价、语义边界加权与双分支融合权重，形成一套自洽的度量
- 用「几何序 + 语义路由序」双分支刻意制造两套不同邻域，再以两扫描路径的局部变化差异做融合，而非简单拼接或 cross-attention，属于针对高斯表示特性的结构设计

## 局限与风险
- 作者明确指出主要局限是推理延迟上升，144K 高斯时约 +31%（354.71->466.12 ms），对实时车载部署不利，未来工作指向更高效的扫描
- 收益并不随高斯数量单调：GaussianFormer 在 25.6K 高斯时仅 +0.88 IoU / +0.97 mIoU，明显弱于 144K 时的 +2.58 / +1.45，说明方法依赖足够密的基元
- GSDF 带来的差异较小（0.02-0.30 mIoU），作者亦提示应谨慎解读
- 评测仅覆盖 camera-only 驾驶场景的 nuScenes-SurroundOcc 与 SSCBench-KITTI-360

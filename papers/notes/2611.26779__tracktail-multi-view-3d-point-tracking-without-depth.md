# Tracktail：无需深度输入的多视角 3D 点跟踪

## 一句话结论
首个完全不用深度输入的多视角 3D 点跟踪器，靠解码器内跨视角查询注意力与几何推导 scene scale 同时解决深度依赖与跨数据集尺度归一化：Panoptic AJ 86.5，已超带 GT 深度的 MVTracker（84.2）。

## 要解决的问题
多视角 3D 点跟踪通常依赖深度输入，而 VGGT、DUSt3R 之类的深度估计既昂贵又有噪声，会显著损害跟踪性能；现有方法还难以稳健处理不同单位与场景尺度的数据集，往往需要逐数据集任意缩放。

## 方法详解
Tracktail 把任务拆成「逐相机视频编码 + 逐查询解码」：预训练视频编码器对每个视角独立编码，解码器中做跨视角相机自注意力与跨帧时间自注意力，输出 2D/3D 位置、可见性、深度与置信度。跨相机注意力只在查询层进行，因此推理高效（10 视角 100 查询点下 7 FPS、<4 GB 显存）。提出由相机几何与查询点计算的逐相机 scene scale，用于跨数据集尺度归一化。在合成 Multi-View Kubric 与新提出的 Multi-View Point Odyssey（499 帧）上训练。

## 实验与结果
- Panoptic Studio AJ = 86.5 / δavg 95.5 / MTE 2.7（MVTracker+GT 深度 84.2 / 93.6 / 3.4）
- DexYCB AJ = 84.9 / δavg 93.8 / MTE 0.6（MVTracker+GT 深度 83.0 / 91.4 / 0.8）
- Multi-View Kubric AJ = 77.4（MVTracker+GT 深度 80.8，MVTracker+DUSt3R 51.5）
- 推理效率 = 7 FPS、<4 GB 显存（10 视角、100 查询点）
- 推理速度 = 比 MVTracker+DUSt3R 快 75 倍，比 ARROW 快 3.5 倍（4 视角 100 查询点）
- 相机自注意力消融 MTE = 5.1 → 2.8（Multi-View Kubric）

## 创新点与贡献
- 首个完全不用深度输入的多视角 3D 点跟踪器，靠解码器内的跨视角查询注意力与几何推导的 scene scale 同时解决深度依赖与跨数据集尺度归一化

## 局限与风险
- 作者自述不处理相机运动，移动相机数据集上跟踪困难（已生成移动相机版本拟后续支持）
- 长序列仍有漂移，Point Odyssey 上生存率有提升空间

# SplatTok：以场景级 token 数据驱动压缩 3D Gaussian Splats

## 一句话结论
把压缩从「编码给定原语」改为「在学到的场景潜空间里搜这个场景的码」，码长与原语数量解耦、解码器可自由生成更适合渲染的新原语：Mip-NeRF 360 上 27.93 dB @7.46 MB（比 HAC++ 的 8.61 MB 高 0.46 dB），28.09 dB @10.89 MB（比 18.48 MB 高 0.49 dB）。

## 要解决的问题
3DGS 场景动辄数百 MB 到 1 GB 以上，难以流式传输到头显或手机。per-scene 方法（HAC++、ContextGS 等）能到近百倍压缩，但需要训练图像、每场景几十分钟优化、每个目标码率重训，输出还常是非标准 splat 需要专用渲染器；post-training 与 feed-forward（FCGS）方法保持标准格式，却只有 10–45 倍压缩。此前没有方法能在「不要训练图像、不做 per-scene 表示训练、解码回标准 splat」三个约束下达到 per-scene 级压缩率。

## 方法详解
核心观点：一个 splat 只是场景的一种实现，不同原语排布可渲染出几乎相同的图像，因此可以在解码侧重合成。SplatTok 先把场景用 k-means 分成 A 个 anchor（数量正比于 N，每个 anchor 至多 K=640 个成员，边界处允许重叠），记录 anchor 位置 a_k 与中位半径 σ_k，位置用归一化偏移 (μ_i-a_k)/σ_k 表达。编码器把每个 Gaussian 的非位置属性嵌入，与 Fourier 编码的偏移合成 key-value token，再由 T=16 个共享 learnable query（按 log σ_k 平移）做 cross-attention，使任意成员数的 anchor 都压成固定 T 个 token；随后 12 层 transformer 前 4 层做 anchor 内自注意力、后 8 层在场景级与 anchor 内交替，全局层带 anchor 位置的 3D rotary position encoding。解码器用 M=160 个 query 对每个 anchor 的 token 做 cross-attention，经残差 MLP 回归 δ、log-scale、四元数、不透明度 logit 与 SH，位置 μ̂=a_k+σ_kδ；颜色在 BT.709 YCbCr 基下只在 luma 保留视角相关项、chroma 仅留 DC，损失 <0.1 dB。训练完全以渲染监督：L=(1-λ)MSE+λ(1-SSIM)，λ=0.2，不施加任何原语级损失、也不要求输入输出对应；在 9,101 个 DL3DV 场景上训 300 epoch，57.3M 参数，4×A100 约 6 天。存储时 token 按通道对称均匀量化到 b bit，用 rANS 编码，概率表按 (token 位置, 通道, 最近已编码 anchor 的符号粗分箱) 选取，表离线统计后固定、不传输；码率由 b 与 anchor 密度两个旋钮控制，同一模型覆盖所有码率。压缩时做量化感知的 latent search：冻结编解码器，仅对 Z 用 SGD 优化渲染损失，round 用 STE，目标是输入 splat 的渲染（无需训练图像），也可换成训练图像。

## 实验与结果
- Mip-NeRF 360：27.93 dB @7.46 MB，比 HAC++ 的 8.61 MB 高 0.46 dB；28.09 dB @10.89 MB，比 HAC++ 的 18.48 MB 高 0.49 dB
- Tanks and Temples 高/低码率分别高 0.51/0.44 dB 且体积小 25%/34%；Deep Blending 高 0.18/0.15 dB、小 29%/40%
- 无训练图像时以 FCGS 高码率的 PSNR 为基准，文件小 4–6.5 倍；相对输入 splat 压缩约 75–110 倍，仅掉 0.1–0.3 dB
- latent search 仅用 100 步即涨 3.7 dB，500 步收敛到 28.09 dB，而码字相对编码器输出只变 4%–10%
- 以输入 splat 渲染为目标时增益约 8 dB，等效消除编码器 84% 的平方误差，即至少 84% 误差属 amortization gap
- 解码 splat 含约 1.25× 输入 Gaussian 数，Garden 上 171 FPS（输入 184 FPS）；3.5M Gaussian 场景 latent search 672 s、编码 5.1 s、解码 0.44 s

## 创新点与贡献
- 把压缩从「编码给定的原语」改为「在学到的场景潜空间里找这个场景的码」，因此码长与原语数量解耦、解码器可自由生成更适合渲染的新原语集合
- 用 amortization gap 分析量化了 search 的作用（消掉 84% 平方误差、码只动 4–10%），为「短搜索即可逼近最优码」提供了可检验解释
- 单一模型跨数据集、跨码率、跨 anchor 密度复用，且输出是任何 3DGS 渲染器都能读的标准 splat，可与 compaction 方法串联

## 局限与风险
- latent search 是最慢阶段：百万级 Gaussian 场景接近 3 分钟，350 万级到 672 s，远慢于单次前向
- 编码器全局注意力需大量显存（400 万 Gaussian 约 30 GB），大场景受限
- 统一 anchor 密度使精细区域与平坦区域分到同样比特，粗 anchor 时 SSIM/LPIPS 掉得比 PSNR 多
- 计数式概率表几乎没利用跨 anchor 依赖，留出学习熵模型的空间

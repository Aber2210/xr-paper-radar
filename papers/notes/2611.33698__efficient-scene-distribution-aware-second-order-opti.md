# 面向三维高斯泼溅的高效场景分布感知二阶优化

## 一句话结论
给 LM-RS 补齐三阶 SH、场景分布化视角采样与 tile 分组多视累积，让二阶优化真正压过 Adam——Mip-NeRF 360 13 场景 PSNR 25.800 / 198.1 s（LM-RS 25.632 / 492.9 s、3DGS-Adam 25.698 / 457.5 s），checkpoint 微调 27.91 / 177.9 s，300 步 23.742 / 113.9 s。

## 要解决的问题
3DGS 的优化以单视图为单位更新数万次：在 Mip-NeRF 360 上，Adam 从稀疏 SfM 点云训 30,000 次需 7.6 分钟，从稠密预训练模型微调 10,000 次也要 6.8 分钟；而前馈管线预测高斯后还要 1,000–3,000 次精修，训练慢直接拖住整条链路。二阶方法能用更少次更新达到同等质量，LM-RS 用 64 视图 × 300 次更新就能逼近 30,000 次 Adam 的 PSNR，但 300 次二阶更新要 8.2 分钟，比 Adam 还慢。原因有二：按 K-Means 独立选视图会让两个几乎重复的视角进入同一批，浪费场景覆盖；每次更新对每个视图单独跑一遍累积，预条件子还要从第一个高斯重算 alpha 合成。

## 方法详解
保留 LM-RS 的采样 LM 框架（残差采样、matrix-free PCG、对角预条件、阻尼、自动步长），并补上 3 阶球谐系数一起优化。①Scene-Distributional View Sampling：沿相机轨迹均匀放置每批视图，若某视图与已选视图重叠则替换为邻近、较不相似的视图，所有批次在优化前一次性确定——只用位姿、无额外渲染或反传，目标是让每批的相机位置与朝向分布更接近全体训练视图，降低 $\hat{\boldsymbol{J}}^{\top}\hat{\boldsymbol{J}}$ 中重复行的冗余。②Tile-Grouped Multi-View Accumulation：把多个视图的采样 tile 打包进统一布局，一次累积就为整批视图构建 $\hat{\boldsymbol{J}}$，避免逐视图单独 pass。③Bucket-Prefix Jacobi Preconditioning：渲染时按射线把若干高斯处的透射率与累积颜色缓存下来，预条件子计算从这些前缀并行起步，而不是从第一个高斯重新合成。三项都不改更新规则，只改「选哪些视图」和「怎么执行」。所有对比固定同一组高斯、只更新参数，因此差异来自优化而非密度控制。

## 实验与结果
- SfM 初始化（Mip-NeRF 360，13 场景）：PSNR 25.800、198.1 s（LM-RS₆₄ 25.632 / 492.9 s；3DGS-Adam 25.698 / 457.5 s）
- 3DGS checkpoint 微调（50 步、9 场景 5 seed）：PSNR 27.9097、177.9 s（LM-RS₆₄ 27.8093 / 370.0 s）
- Taming-3DGS checkpoint：PSNR 28.1823、134.9 s（LM-RS₆₄ 28.0256 / 333.7 s）
- 3DGS-MCMC checkpoint：PSNR 28.4893、219.9 s（LM-RS₆₄ 28.3325 / 499.4 s）
- 消融（Tanks&Temples，300 步）：PSNR 23.481→23.742，时间 255.2→113.9 s（2.24×）
- 峰值显存 50.16 GB（Bonsai，64 视图批，50 步微调）

## 创新点与贡献
- 相对 LM-RS，本文把「每批视图冗余」与「逐视图重复累积 / 重算预条件」识别为两个独立开销，并分别用位姿层面的去冗余采样、以及与更新规则完全解耦的两项实现优化来解决
- 相对 3DGS-LM、3DGS²、TurboGS 等拆分系统或分参数求解的做法，这里保留全耦合系统与 3 阶 SH，使二阶更新既准又快

## 局限与风险
- 多视图批训练的内在显存开销无法消除：每个视图有独立的可见序、透射率与累积颜色，Bonsai 上 64 视图批峰值已达 50 GB，作者自述这是限制消费级硬件批大小的主因
- 精度增益很小（PSNR 约 +0.17 dB），主要收益是速度，属工程优化而非质量突破
- 固定高斯集合，未与 densification 联合
- 3DGS-LM 被迫用 16×4 子集以避免 OOM，比较不完全对等

# Fast-GSVC：更快、更小、更好看的 2D 高斯视频编码

## 一句话结论
不只做底层 GPU 加速，而针对 2DGS 优化的两个失效模式（覆盖慢、细化抖）设计初始化/EMA/渐进/光流引导，压缩端显式用时间相干性：UVG 50 帧编码 7.56 小时→34 分钟（13.4×），同 PSNR 下 bpp 降约 46%，同 bpp 下 PSNR +1.9 dB。

## 要解决的问题
2D Gaussian 已成为有前景的显式视频表示，但把 Gaussian 拟合到整段视频计算量巨大，编码时间过长。SOTA 的 GSVC 即使使用轻量 2DGS 与 H100，编码一帧 1080p 仍需数百秒，600 帧视频累计超过四天。作者定位到两个优化瓶颈：随机初始化导致早期覆盖阶段需要大量迭代才能填满未覆盖区域；后期细化阶段梯度波动大、画面闪烁，收敛慢。此外，现有量化微调没有充分利用帧间时间相干性，残差不够集中，压缩率次优。

## 方法详解
Fast-2DGS 从「优化有效性」而非仅 kernel 加速入手：Coverage-aware Initialization 按 90% 梯度引导 + 10% 均匀混合采样中心、平衡系数 α=32，使初始覆盖充分；EMA Parameter Averaging 对参数做 β=0.99 的滑动平均并设 2500 步 warmup，在保持激进更新的同时抑制短期波动；Progressive Training 以 m=32 级降采样由粗到细增加目标复杂度；动态 Gaussian 预算占 10%，锚帧每 100 步剪枝（0→4000），传播帧 500→1000。锚帧学习率 warmup 期 1e-3、之后升到 1e-2，传播帧固定 1e-3。视频编码侧：锚帧从零优化，传播帧继承上一帧 Gaussian；用半分辨率 CPU OpenCV DIS 双向光流（约 102 ms）做两件事——在光流无法解释的动态区域新增 Gaussian 以改善初始化，以及在优化中以 $\lambda_{\mathrm{flow}}=10^{-3}$ 的流先验把传播 Gaussian 沿估计运动引导。压缩侧保留时空相关性使残差集中，引入 Temporal-Aware Quantization（TAQ）；码本用 LBG 聚类确定性构造替代随机 K-means；量化区间下界设为初值的 5% 以避免过度截断；熵友好损失权重 1e-5/1e-4；全管线用 CUDA Graphs 降低 kernel 启动开销。

## 实验与结果
- UVG 50 帧 IPPPP：总编码时间 7.56 小时→34 分钟，13.4× 加速，编码时间下降 92.5%
- 同 PSNR 下 bpp 降低约 46%（38–51%）；同 bpp 下 PSNR 提升约 1.9 dB（1.5–2.2 dB）
- Ours（IP~，仅首帧 I、其余全 P）：bpp 降低 58%（51–63%），PSNR 提升 2.5 dB（2.2–2.8 dB）
- 平均迭代数：I 帧 23.7k、P 帧 6.2k；GSVC 为 100k
- 表示优化加速：锚帧 4.6×、传播帧 2.4×；量化微调 I 帧 7.4×、P 帧 29.4×
- Jockey 10k Gaussian 训练 4k 迭代时 34.2 dB，GSVC 仅 18.2 dB
- AIR 前馈初始化平均每像素 8.3 个 Gaussian（Fast-GSVC 为 3.9），同剪枝后 PSNR 低约 2 dB
- 加速比区间：锚帧 3.1–8.0×、传播帧 2.0–3.3×、I 帧 6.5–7.7×、P 帧 25.9–31.0×

## 创新点与贡献
- 不只做底层 GPU 加速，而是针对 2DGS 优化的两个失效模式（覆盖慢、细化抖）设计初始化/EMA/渐进/光流引导，使更少迭代达到更好率失真
- 压缩端把时间相干性显式用于量化与残差集中，并与 CUDA Graphs 结合，实现 13.4× 端到端加速的同时降低 bpp 或提升 PSNR

## 局限与风险
- 作者承认在 PSNR 与 VMAF 上仍落后 HEVC/VVC，只在较高码率下 MS-SSIM 接近
- 当前只用 L2 重建项，加入感知损失可能提升观感但会增加编码时间
- 收敛判据与迭代次数仍是速度–质量折中，更严格收敛可再提 PSNR 但更慢
- 前馈初始化尚未整合，AIR 初始化对剪枝敏感的原因待查
- 方法仍是逐序列离线优化，无实时编码

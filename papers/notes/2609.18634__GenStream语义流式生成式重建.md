# GenStream：不传像素，改传"语义指令"

> ⚠️ **路线提示（部分落后）**：本文核心的 **2D sprite 合成**路线已被作者自承为过渡方案（见 §6 Conclusion），且同期 MoQSplat（arXiv:2609.18624）与库内 DELUGE（arXiv:2609.19750）代表的原生 3D 表示流式已能端到端落地。但 **>99.9% 带宽削减**这一指标至今无替代方案，故论文级判定仍为 CURRENT。

## 一句话结论

把视频流式的传输对象从**像素**换成**结构化语义元数据**——骨骼关键点 + 相机视点参数 + 静态 3D 背景模型；客户端用生成模型重建逼真人物并合成进 3D 场景。在 2018 平昌冬奥花样滑冰素材上，**连续数据流从 HEVC 的 134 MB 压到约 110 kB，带宽削减 >99.9%**。

## 要解决的问题

传统编解码器的结构性浪费：

- **像素一视同仁**：AVC / HEVC / AV1 / VVC 在块级操作，**对场景语义无感知**。前景背景同等重编码。
- **长期重复模式无法利用**：分段独立编码 → 帧间预测只限于短时间窗；体育赛事中"运动员在静止场馆背景前运动"这类长时结构冗余被反复重编码。
- **边际收益递减**：AV1 / VVC 相对前代最多省 50%，但编码端算力代价陡增。

核心命题：当场景是**结构化的、以人为中心的**（体育、演出、交互媒体），且背景静止、运动只集中在少数显著主体时，传像素是根本性的浪费。

## 方法详解

### 服务端

**① 分割与背景重建**
- 提取带 mask 的 RGBA 背景层
- 对被运动员遮挡的区域做**上下文感知修复（inpainting）**，还原完整背景
- 用 SfM（COLMAP）从修复后的背景推断相机视点

**② 关键点提取**（三档空间密度对比）
| 方法 | 特点 |
|---|---|
| Canny 边缘滤波 | 检测高梯度边缘，勾轮廓 |
| 网格采样滤波 | 在边缘图上叠规则网格，从高细节区选代表点 |
| **YOLOv11 Pose 骨骼检测器** | 基于 body landmark 的骨架 |

关键点提取与分割阶段并行执行。

**③ 传输内容**
| 项目 | 大小 |
|---|---:|
| 骨骼关键点 | 64 kB |
| 包围盒 | < 4 kB |
| 相机视点参数 | 42 kB |
| **合计** | **≈ 110 kB** |
| 对照：HEVC 编码视频 | **134 MB** |

### 客户端

- **引擎**：Unity。因 Unity 用四元数 `q ∈ ℝ⁴` 表示旋转，需把相机外参的旋转矩阵 `R ∈ ℝ³ˣ³` 经四元数代数转换，以减少表示 `T`（4×4 齐次变换矩阵）所需的数值量
- **生成模型**：训练一个 **cGAN**，输入为配对图像数据（一肢为基于骨骼重建的人物图像）
- **合成**：逐帧把生成的人物合成进 3D 背景，时序上由关键点与视点元数据的演化引导
- **播放**：重建序列送入播放器，低延迟回放

### 设计要点

因为依赖学习到的先验与稀疏表示，GenStream **对带宽骤降、抖动、中间帧丢失天然鲁棒**——它的行为更像一个生成式动画系统，而非经典视频流系统。

## 实验与结果

**数据**：2018 平昌冬奥会 4 场花样滑冰表演中提取的 **48 个场景、40,000+ 帧**，时长 9 s–55 s，**30 fps / 1080p**。共享特征：(i) 同一冰场背景、静止物体与观众为主；(ii) 一名花样滑冰运动员在中心运动。

**主结果**

| 指标 | 数值 |
|---|---|
| 连续数据流带宽 | 134 MB（HEVC）→ **≈110 kB** |
| 削减比例 | **> 99.9%** |

> ⚠️ **口径声明（作者原文明确）**：该计算**仅针对连续数据流**，**不包含**一次性的、流前的 3D 场馆模型与生成模型权重的预分发。这是评估本文真实收益时必须扣除的成本。

**实验强度评估**：本文自述为 **"partially validate（部分验证）"**——仅在单一素材类型（花样滑冰）上验证，未做多数据集、无用户研究、未与 DASH/HAS 端到端系统做 QoE 对比。这正是 EXP 仅给 2 分的原因。

## 创新点与贡献

1. **范式级主张**：明确提出"后编解码器（post-codec）"方向——传输语义内容而非像素保真。
2. **完整的服务端-客户端分工设计**：分割 → 背景修复 → SfM 视点估计 → 关键点提取 → 传输 → 客户端生成 → 合成 → 播放，链路闭合。
3. **量化到字节级**：把 110 kB vs 134 MB 拆到关键点/包围盒/视点三项，便于后续工作逐项优化。
4. **对网络波动的天然鲁棒性**：这是语义传输相对像素传输的结构性优势。

## 局限与风险

- **客户端算力重**：作者把这一点列为"最直接的挑战"，并指出需要面向资源受限设备的轻量生成模型研究。在 XR 头显上尤为致命。
- **泛化性存疑**：仅在单一种类素材（花样滑冰、单人、固定背景）验证。作者自承多演员交互、动态运镜、频繁遮挡是"非平凡的研究问题"。
- **2D sprite 合成无视点一致性**：生成的 2D 人物被合成进 3D 场景，**无法支持自由视点**。作者明确把"从 2D sprite 演进到全体积化、视点一致的表示"列为关键未来方向。
- **一次性预分发成本未计入**：3D 场馆模型 + 生成模型权重的预分发在真实部署中不可忽略。
- 背景建模依赖 COLMAP 等 SfM 工具的多场景特征融合，作者指出其高效求解本身是开放问题。

## 与文献库的关系

- **与 DELUGE（arXiv:2609.19750，S 4.65）的关系**：DELUGE 是**编解码层**的工作（粒子流的分解式熵编码，BD-Rate −73.5%，Apple Vision Pro 端到端 60fps 部署）；GenStream 是**内容表示层**的范式替换（不传像素）。二者层次不同，理论上可叠加。
- **与本期 MoQSplat（arXiv:2609.18624）的关系**：MoQSplat 解决的是 3DGS 场景在**传输层**的队头阻塞与视口自适应；GenStream 解决"根本不传几何"。MoQSplat 保留了视点一致性，GenStream 没有——这是 MoQSplat 代表的新一代方案对本文的实质超越。
- **赛道定位**：库内 `系统与平台` 原最高为 DELUGE 4.65，本文 3.94 未超天花板，但开辟了"语义流式"子方向。

## 可复现性

- 代码：https://github.com/emanuele-artioli/genstream （已开源）
- 数据：2018 平昌冬奥公开转播素材
- 引擎：Unity
- 生成模型：cGAN，需自行在目标素材上训练（**这是复现的主要成本**）

## 行动建议

1. **不要直接用于 XR 头显**：客户端 cGAN 推理 + Unity 渲染的算力负担在头显上不可承受。先做云渲染 + 视频回流，或等轻量生成模型成熟。
2. **值得借鉴的是思路而非实现**：在"背景静止、主体有限"的 XR 场景（虚拟演唱会、体育观赛、远程教学）中，"一次传背景 3D + 持续传骨骼"的带宽结构优势是真实的。
3. **如果要跟进，直接做体积化版本**：作者已指明方向（3D 骨架驱动体积化 avatar、多视点云融合到规范 3D 表示、单目 2D 骨架提升为可靠 3D 关节）。这三条与本期 MoQSplat、库内 SplashSplat/Deluge 的技术栈高度吻合。

# GALILEO：动态场景下带伽利略键传输的几何 RoPE

## 一句话结论
把「运动」从特征层搬到位置编码层：按内容速度把 key 平移到 query 时刻再编码，既不改表示也不做特征 warping：RayRoPE 上 PSNR_dyn +0.9–1.3 dB、URoPE 上 +0.4–0.8 dB，三个数据集全部指标提升。

## 要解决的问题
RayRoPE、URoPE 等几何感知旋转位置编码隐含假设 key 与 query 对应同一时刻：每个 key 都被编码在其内容被观测时的 3D 位置。对时间分离的输入视角，同一运动物体在不同帧占据不同位置，破坏 RayRoPE 依赖的位置一致性，也偏离 URoPE 所用的对极约束，于是物体可能在渲染画面里出现在多个位置，时序上表现为「先停在原地、再突然跳过去」的台阶。常见的补法是加 temporal RoPE 或时间嵌入，但它们只说明 key 何时被观测——同帧所有 key 共享同一时间信号，与各自运动无关——因此无法回答「它的内容在 query 时刻应该在哪」。

## 方法详解
只改 key 的位置，不动 query 与注意力算子。给定 query $a$（相机中心 $\mathbf{c}_a$、旋转 $\mathbf{R}_a$、时刻 $t_a$）与 key $b$（时刻 $t_b$，内容点集 $X_b$），先把 key 的点按估计速度平移到 query 时刻：$\hat{x}=x+v_x(t_a-t_b)$，$x\in X_b$；再用 $T_a(\hat{x})=\mathbf{R}_a^\top(\hat{x}-\mathbf{c}_a)$ 生成 key 的系数与变换矩阵 $\hat{M}_a(b)$，logit 仍为 $\ell_{ab}=(M_a(a)^\top q_a)^\top(\hat{M}_a(b)^\top k_b)/\sqrt{d}$，value 用同一矩阵变换、输出再旋回。key 的相机中心 $\mathbf{c}_b$ 不传输（它表示观测者位置而非内容位置），目标 token 不传输，query 编码不变；当 $v_x=0$ 或 $t_a=t_b$ 时严格退化为原编码。RayRoPE 中每 token 一个速度，URoPE 中每个深度锚点各自速度，因此同一 key 可为不同 query 时刻生成不同编码。速度默认在网内估计：每个输入 token 用 transformer 特征做 token 级粗匹配，再用轻量 CNN 细化到像素精度，匹配限制在同相机相邻帧，随后按相机位姿与编码所用深度提升到 3D，在常速模型下最小二乘拟合。损失为 $\mathcal{L}=\mathcal{L}_{\mathrm{img}}+\mathcal{L}_{\mathrm{match}}+\mathcal{L}_{\mathrm{depth}}$，深度监督用于抑制速度估计中的误差放大（深度误差 $\delta$ 会带来约 $\delta|t_a-t_b|/\Delta t$ 的传输位置误差）。训练前 $s_0$ 步用真值速度，随后按 $v=(1-\alpha)v_{\mathrm{gt}}+\alpha v_{\mathrm{pred}}$ 线性过渡到纯预测速度。理论侧给出两条命题：共观测性（两个观测同一匀速点的 key，传输后都映射到 $T_a(x(t_a))$）与伽利略推进不变性（参考系以 $wt$ 平移时传输坐标不变，而静态坐标偏移 $-\mathbf{R}_a^\top w(t_a-t_b)$）。

## 实验与结果
- RayRoPE + GALILEO（LVSM 骨干，20k 步）PSNR_dyn：Stereo4D 24.61→25.78（+1.16）、Objaverse 16.67→17.96（+1.29）、Syn4D 19.88→20.82（+0.94）
- 作者综述：RayRoPE 上 PSNR_dyn 提升 0.9–1.3 dB，URoPE 上 0.4–0.8 dB，三数据集全部指标均改善（含真实 Stereo4D）
- Syn4D 上 JEDi 1.075→0.380（降约 2/3）；tOF 2.19→1.65；δ_avg 0.639→0.668
- 消融（Syn4D）：RayRoPE 19.88 → +匹配损失 20.11 → 速度作 token 特征 20.10 → GALILEO 20.82；GT 运动 21.26；测试时关掉传输回落到 19.84 或更差
- GT 深度条件下：RayRoPE 21.43 → GALILEO(GT motion) 23.75（+3.87 dB），说明剩余误差主要来自深度与速度估计
- 注意力分析（Stereo4D 80 clips）：RayRoPE 在 static place 占 20.8%、content place 6.9%；GALILEO 反转为 22.2% / 8.8%
- 伽利略推进鲁棒性：漂移 16 px 时 RayRoPE 静态区 PSNR 掉 7.2 dB，GALILEO 仅掉 1.3 dB
- 下游迁移（冻结 ARROW）：EPE 4.99→4.47（between）、7.16→6.68（after）；APD 43.5→46.2、33.8→35.6

## 创新点与贡献
- 把「运动」从特征层搬到位置编码层：既不改表示也不做特征 warping（因此没有 warp 空洞），只按内容速度把 key 平移到 query 时刻再编码，使同一 key 能为不同 query 时间生成不同编码，并与 RayRoPE/URoPE 正交可插
- 理论上给出共观测与伽利略推进两条命题，把「为什么多视角观测能被聚合到一起」和「为什么对参考系漂移鲁棒」讲清楚，并用注意力可视化（static place 与 content place 的份额反转）与 boost 实验直接验证机制而非只报分数

## 局限与风险
- 默认只估计相邻帧间的常速，无法跟随加速或转向的内容
- 虽可用 3D 轨迹或真值运动替代，但该替代需要外部来源
- 速度估计范围有限，深度与运动精度直接限制传输（误差约 $\delta|t_a-t_b|/\Delta t$），且误差主要沿捕获相机视线方向，本视角不易察觉而其他视角明显
- 训练依赖深度与匹配监督，无标注视频不具备
- 并非严格不变：首层在速度产生之前运行，key 相机中心也不传输

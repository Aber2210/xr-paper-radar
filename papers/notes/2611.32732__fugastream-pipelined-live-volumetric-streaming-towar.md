# FugaStream：充分挖掘多视角的流水线式实时体积流媒体系统

## 一句话结论
第一个把「提前提交 + 晚到视角增量并入」做成完整流水线的实时体积流媒体系统，用覆盖增益对等待代价的在线权衡替代固定/中位数等待，并在压缩前而非传输后消掉跨视角冗余：同 150 ms 预算 SSIM +10.9%、IoU +13.7%，p95 到达离散度下仍守尾延迟。

## 要解决的问题
实时体积流媒体要在约 150 ms 端到端预算内把多路 RGB-D 重建为统一 3D 表示以支持 6-DoF，但同步采集的各视角到达服务器的时间并不一致：实测 p99 下首个视角约 30 ms 就绪、最后一个超过 65 ms，最坏 138 ms，已吃掉预算的 92%。于是系统被迫二选一——等齐所有视角则超时，提前重建则缺失视角导致表面空洞与几何畸变，而 6-DoF 下用户一转视角就会看到这些缺失。现有系统（含 MetaStream）把「参与本帧的视角集合」在提交时刻固定，错过的视角直接丢弃。

## 方法详解
提出首个流水线式实时体积流媒体系统：先用已就绪视角提交一个 base 表示并立即下行，晚到视角作为轻量增量在客户端并入同一 TSDF 体素网格，从而解开「重建时机」与「视角利用」的强耦合。关键组件一是 Adaptive Base Commitment Control（ABCC）：对每个相机维护最近 150 个 frame set 的 fusion-ready 时间滑窗并估计经验 CDF F_i，给定当前时刻 t 与额外等待 Δ，缺失视角就绪的条件概率为 p_i(t,Δ)=(F_i(t+Δ)−F_i(t))/max(1−F_i(t),ε)，覆盖增益 G_t(Δ)=(1/N)Σ_{i∈M_g} p_i(t,Δ)；等待代价按指数增长 C_t(Δ)=e^{(t+Δ)/τ}−e^{t/τ}，决策为 Δ*=argmax_Δ [G_t(Δ)−λC_t(Δ)]，当 Δ*=0 时立即提交。组件二是 Base-Referenced Late View Completion：服务器对每个晚到视角的观测 x 计算新颖度 P_g(x)=S(x)(1−C_g(v(x)))，其中 S(x) 为局部深度支撑度（由邻域深度一致性抑制噪声），C_g(v)=min(W_g(v)/|R_g|,1) 为 base 中该体素的归一化覆盖率，低于阈值 θ_p 的观测被判为冗余丢弃；再用每 frame set 的瞬时 overlap map 在晚到视角之间去重，保证每个体素只由一个晚到视角携带。客户端采用 ray-wise 而非 voxel-wise 融合：每到一个晚到视角，沿相机标定重建视线，只遍历视线穿过的 TSDF 截断带更新权重，并在新观测更接近正视时替换颜色，从而把更新代价压到与新增点数成正比。

## 实验与结果
- 在同样 150 ms 预算下 SSIM 提升 10.9%、IoU 提升 13.7%（相对 Fixed / Event / MetaStream 基线）
- p95 视角到达离散度下仍严格满足 150 ms 尾延迟，且重建质量全场最高；Fixed-100 有 26.5% 的连续帧组超预算
- 带宽：晚到视角去重后每 3D 帧 560 KB，Prior Only（仅按新颖度过滤、不去重）最佳工作点为 723 KB，大 29%
- 客户端 ray-wise 精化比 voxel-wise 快 2.14–3.47×，且随晚到视角增多差距扩大
- ABCC 的 idle time 中位数比 cost-only 变体低约 8.5 ms，同时交付帧数基本不变（帧利用率不降）
- 晚到视角单独带来的增益：SSIM 最高 +0.09、IoU 最高 +0.18；但 base 过小时最终上限更低，说明不能无限提前提交

## 创新点与贡献
- 第一个把「提前提交 + 晚到视角增量并入」做成完整流水线的实时体积流媒体系统，用覆盖增益对等待代价的在线权衡替代固定/中位数式等待，并用 base 相对新颖度把跨视角冗余从「压缩前」而不是「传输后」消掉
- ray-wise 增量融合与体素级去重让晚到视角的代价近似与新增点数成正比，使 150 ms 预算下的质量-延迟前沿整体外推

## 局限与风险
- 评估以单用户、受控下行链路为主，未刻画多用户、下行带宽波动与异构客户端算力
- 压缩仍用 Draco，未做带宽自适应或可分级编码
- 系统依赖 TSDF 体素网格，对薄结构、反光与弱纹理表面仍有融合噪声
- ABCC 的超参 λ、τ 需按应用调，缺少跨场景自动标定

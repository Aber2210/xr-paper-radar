# FastD4RT：动态四维重建与跟踪的无训练加速

## 一句话结论
把「无训练推理加速」建立在注意力与输出平滑性分析上，锚点插值与共享 token 解码分别作用于查询数量与单查询成本：全部任务平均约 5×（2.1–6.2×）加速而精度与 D4RT 相当，60 FPS 下可生成 6,653 条全视频轨迹（对 1,342 条）。

## 要解决的问题
以 D4RT 为代表的查询式四维重建先把整段视频编码为全局场景表示，再对每个点查询独立解码，但推理仍按稠密方式执行：稠密深度图需要为每帧每个像素发一次查询，长视频还必须切成大量重叠片段分别编码。作者实测发现，在稠密深度任务中解码器几乎占满全部运行时间，长视频下编码器与解码器开销同时增长。单个查询在每层都要对全部 N 个 token 做交叉注意力，使 C_D 本身也很高。核心约束是：在不重新训练、不改变 D4RT 权重的前提下同时降低片段数 K、查询数 N_q 与单查询成本 C_D。

## 方法详解
先做推理冗余分析，发现三层冗余：输出沿时间与像素平滑、后段解码块对所有查询关注同一小 token 集合、重叠片段带来累积对齐误差。为此提出锚点稀疏推理（anchor-based sparse inference）：轨迹与相机位姿每隔 r 帧取锚点、旋转沿测地线插值，深度/点云在 G×G 粗网格上解码后双线性上采样，编码器按步长 s 抽帧使片段数降为约 K/s。再提出共享 token 解码（shared-token decoding）：每个片段用一小组校准查询统计各头平均注意力，取 top-m 得到共享 token 集 $\mathcal{T}$，第 $l_0$ 块之后仅对 $\mathbf{F}_{\mathcal{T}}$ 做注意力，即 $\mathbf{z}_{l+1}=\mathcal{D}_l(\mathbf{z}_l,\mathbf{F}_{\mathcal{T}})$。两者分别把 $N_q$ 降为 $N_q/\gamma$、把 $C_D$ 从 $\mathcal{O}(L(Nd+d^2))$ 降到 $\mathcal{O}(l_0Nd+(L-l_0)md+Ld^2)$，加速比可相乘。作者给出误差上界：插值误差 $E_{int}\le r^2\alpha/8$（轨迹）与 $E_{int}\le \Delta\ell/2$（深度/点云），共享 token 误差 $E_{sh}\le 2\epsilon V$，其中 $\epsilon$ 为共享集外的注意力质量。整个流程无需训练，按片段依次编码、选 token、锚点解码、插值并对齐相邻片段。

## 实验与结果
- 全部任务平均加速约 5×，加速区间 2.1–6.2×，精度与 D4RT 相当（TAPVid-3D、Sintel、ScanNet、KITTI、Bonn、Re10K）
- 稠密点云/视频深度任务加速 6.1–6.3×；Sintel 深度 AbsRel 0.392 vs D4RT 0.392（scale-only 对齐）
- 单张 H20 上 60 FPS 目标下可生成 6,653 条全视频 3D 轨迹 vs D4RT 1,342 条，约 5.0×
- 1 FPS 目标下 519,872 条轨迹 vs D4RT 107,761 条，4.8×
- ADT 300 帧长视频：AJ 3.0% vs D4RT 2.3%，OA 78.0% vs 77.3%，轨迹加速 5.3×、点云加速 5.8×
- Sintel 相机位姿：ATE 0.141 vs 0.145，RPE-R 0.604° vs 0.724°，加速 6.0×

## 创新点与贡献
- 把「无训练推理加速」建立在可解释的注意力与输出平滑性分析上，而不是剪枝或蒸馏：锚点插值与共享 token 解码分别作用于查询数量和单查询成本，并给出可验证的误差上界
- 长视频上减少片段还顺带降低链式 Sim(3) 对齐的累积误差，使加速与精度同向

## 局限与风险
- 官方 D4RT 权重未公开，全部实验基于社区 OpenD4RT，结论对官方模型的迁移性未验证
- 方法依赖「输出在锚点间平滑/表面近似平面」的假设，剧烈运动或高频几何处误差会上升
- 相机位姿在 ScanNet 上反而退化（ATE 0.152 vs 0.149，RPE-R 3.503° vs 2.159°），说明加速并非对所有任务无损

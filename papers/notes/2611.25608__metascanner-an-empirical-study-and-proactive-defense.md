# MetaScanner：社交 VR 中欺骗性 UI 攻击的实证研究与主动防御

## 一句话结论
在 VRChat 实证四种欺骗性 UI 攻击（83.3% / 86.7% 用户未察觉），并给出 5 s 扫描的静态检测器（攻击 UI 30/30 检出）。

## 要解决的问题
社交 VR 平台（VRChat 峰值用户超 4 万）的 UGC 生态把「世界、化身、交互」三层都交给了普通用户，内容创作者因此可以成为对手。已有 VR 安全研究集中在隐私与感知操纵：从头动数据做按键记录、从性能指标与生命体征推断个人信息、向视野注入误导对象造成受伤或决策错误、以及 WebXR 广告欺诈；VR 社区对「暗黑模式」的讨论也多在商业牟利语境。但欺骗性 UI 在社交 VR 中几乎未被系统研究，而这里的攻击面恰恰更大：平台审核只针对色情、仇恨等显性有害内容，隐形的、重叠的、带隐藏脚本的对象可以顺利过审；用户又因社交沉浸与聊天、游戏的认知负荷而降低警惕，会把伪造的系统告警或化身身上的二维码当作环境线索而非外部威胁。既有 Web 与独立 VR 的 clickjacking 研究只依赖视觉混淆，没有利用社交沉浸与主动交互。风险并非假设：VRChat 已出现过用碰撞体压垮他人的 crasher avatar，平台因此引入 avatar trust and safety 等级，说明 UGC 可被武器化。更细的失效点在于交互语义本身——raycast 被不可见物体挡住时，用户看不到任何提示，只能归因为设备故障，这正是钓鱼可乘之机。

## 方法详解
威胁模型：远程对手以合法用户身份、用官方 SDK（Unity 2022.3.6f1 + VRChat Creator Companion）上传世界或化身，不攻破服务端；审核只看显性有害内容，隐式恶意对象可过。四个攻击从「世界/化身/交互」三层与 Web clickjacking、WebXR 广告欺诈、物理世界 quishing 的类比中推导，并在真实 SDK 上逐一实现：(1) Layered Click Redirection：诱饵对象旁放同尺寸同位置的 clickjacking 对象，利用 Unity 渲染序与交互序的不一致（蓝通道高、红通道低的材质更靠前渲染，可人为控制谁被看见、谁接收点击），三种布点策略为单对象双逻辑（简单但有可感延迟）、透明覆盖（模块化、可复用）、完全重叠（最难察觉；不同用户的 raycast 角度不同会造成「有的人点到诱饵、有的人触发攻击」，且可用网络的同步/异步模式控制单位时间受害人数）；载荷为 Udon 视频白名单域（如 YouTube）内的视频播放，构成广告欺诈或刷量。(2) Raycasting Phishing：把不可见对象附着在用户身上（满足条件时触发，或加入世界即默认附着），挡住 raycast 使可见按钮失去可点状态；再放一块伪造「故障排查」横幅加二维码，把用户导向仿冒平台的钓鱼站；不可见体可只覆盖一只手，让用户以为是单个手柄故障。(3) In-World Input Hijack：在虚拟商城键盘上叠一层透明复制键盘截获密码，数据不发外部服务器，而写入世界内隐藏房间的显示板，从而规避网络侧 IDS 与防火墙，创作者事后自行取回。(4) Avatar Quishing：把恶意二维码嵌进可正常上传的化身，并使其视觉上「脱离身体」，站到世界内良性二维码前完全遮挡，利用社区扫码器（如 VRQR 默认自动打开 URL）不校验 URL 的习惯。用户研究：IRB 批准，30 人（16 人有 VR 经验、14 人从未使用；男 21/女 9；18–31 岁），Meta Quest 2 + Air Link，四个房间对应四场景（叠番茄、记忆游戏、购物付款、扫码），10 分钟适应期，within-subject 固定顺序并以「教学式漫游」包装，事后完整 debrief，二项检验与卡方拟合优度，开放式回答双人独立编码（κ=1.0）。防御 MetaScanner：在**上传期**静态分析包，四模块——object scanner 用 Unity 的 FindObjectsOfType/GetComponents 加反射读 alpha、位置、scale、prefab，判据为 alpha=0 或包围盒 IoU≥0.95（默认容忍 5% 偏差，另检 MeshCollider+Rigidbody 的透明触发体）；library scanner 对每个脚本算哈希与可信库比对，捕捉供应链投毒（含 Unity Package Manager 缓存与 manifest 两种布局）；script scanner 用字符串匹配危险 API（Application.OpenURL、System.Net.Sockets）；QR scanner 用 Zebra Crossing 解码 Asset 内图片并把 URL 交平台白/黑名单。检测策略由平台下发以适配不同平台规则，输出结构化报告与进入前警告；同时采用「object 粗筛 + script 复核」的两级验证压低误报。

## 实验与结果
- 30 人用户研究中四个攻击全部生效：E1 有 83.3% 未察觉两个按钮的差异（p<.001，Cohen g=0.33）
- E2 有 86.7% 未察觉隐形墙（p<.001，g=0.37），且 37.9% 愿意扫描伪造横幅上的二维码（χ²(2)=13.52，p=.001）
- E3 中 100% 被试认为透明复制键盘完全合法，83.3% 无法猜出输入被截获的实现方式（p<.001，g=0.33），其中还包括修过 VR 开发课程的人
- E4 中 100% 被试未发现化身附带的二维码覆盖了原二维码，83.3% 承认扫码前从不质疑真伪（χ²(2)=34.20，p<.001，w=1.07）
- 有/无 VR 经验组间无显著差异（E1 p≈.74，E2 p≈.22）
- 检测覆盖：30 个世界中 Layered Click Redirection 与 In-World Input Hijack 均 30/30 检出，IoU=1.00 与 0.95 时 0 误报
- 阈值敏感性：把 IoU 放宽到 0.80 仍 30/30 检出，但 67 个良性组件被误报，精度降到 31%
- 而这些误报多为草丛、砖块、蘑菇等密集装饰，且 0.80 时攻击本身已因按键错位而失效
- Raycasting Phishing：规则 1–2（透明 + MeshCollider/Rigidbody）得 30/30 但误报 12 个良性隐形墙，精度 71%
- 加入规则 3（世界中存在关联二维码）后误报归零、精度 100%
- Avatar Quishing：10/10 检出、0 误报
- 但把二维码碎片化到多张纹理时 0/10 检出，截获界面与合法界面形状差异大时 0/30 检出
- 扫描开销：38 个 Unity Asset Store 世界平均 5 s
- 最大世界 Real New York City Vol. 2（32660 个对象、74283 个组件、225 张图）需 45 s，其中 QR 扫描约 29 s，库/对象/脚本各占 13.1%/1.7%/7.3%，QR 扫描平均 3.9 s 是主要瓶颈

## 创新点与贡献
- 首个面向社交 VR UGC 生态的欺骗性 UI 威胁模型，且四个攻击都满足「平台原生、无需恶意程序、无需提权、面向多用户社交场景」——与既有需要改客户端或开发者模式的 VR 攻击形成明确区分。
- 把 clickjacking 从纯视觉混淆推进到利用社交沉浸、渲染序与交互序差异、以及网络同步模式来按用户选择性施害，使受害者体验不一致、难以集体举报。
- In-World Input Hijack 提出「世界内隐藏房间」作为渗出通道：不产生任何外部网络流量，因此网络侧监控天然失效，这是社交 VR 独有能力的武器化。
- Avatar Quishing 把攻击载体做成可随身携带、可空间遮挡良性码的化身，绕开「世界内容不可改」的限制。
- 上传期的多模块静态扫描（对象几何判据 + 库哈希完整性 + 危险 API 字符串 + 二维码 URL）配合平台策略化规则与两级验证，给出可嵌入现有 SDK 流程的主动防御形态。

## 局限与风险
- 作者自述：静态分析无法覆盖纯运行时逻辑、社会工程与语音欺骗
- 透明与重叠本是 Unity 常规手法，误报无法彻底消除
- 二维码碎片化、以及「多个物体视觉对齐才成码」的视角依赖构造可绕过
- 客户端运行时动态生成的界面（平台设置、导航菜单）不在世界包内，天然逃逸
- 只验证 URL 提取，不判定 URL 本身是否恶意，需依赖平台名单或 Google Safe Browsing
- 从实验设计看：只在 VRChat + Unity 上实测，Rec Room、Spatial、Decentraland 仅以可行性表格推断（如 Rec Room 不允许普通用户上传化身、Spatial 用圆形交互区替代 raycast），未真正部署
- 38 个评测世界全部来自 Unity Asset Store 而非 VRChat 真实世界（后者不可下载），生态代表性有限，且「平均仅 6% 对象、2% 组件命中策略」是基于自定的 dummy 策略
- 攻击实现依赖特定 Unity 版本的渲染序，升级可能失效，作者自己也提示重叠对象在某些版本会闪烁
- 用户研究 30 人、单一机构、70% 男性、18–31 岁，外部效度有限，且固定场景顺序虽称无学习效应但仅以问卷自评支撑
- 检测评估每个世界只注入 3 个变体，未做「对手已知规则后自适应规避」的博弈分析，而碎片化 QR 的 0/10 已说明静态规则脆弱

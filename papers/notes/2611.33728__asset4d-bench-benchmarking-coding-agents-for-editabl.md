# Asset4D-Bench：面向可编辑 3D 与 4D 重建的编码智能体基准

## 一句话结论
在可被独立重开的 Blender 工程上把几何、运动、关系分开记分，并用 30 对共享参考/目标/评分卡的 partial-asset 控制资产变量——114 条件，full-asset 视频均值 Sol 13.00 / Astra 21.79，两者 6.50 分差中 5.15 来自 relations，dynamics 满分的任务里 relations 全零达 3/14 与 8/14。

## 要解决的问题
让编码智能体从图像/视频写出可编辑的 Blender 程序，难点不在「物体动到哪」，而在「动的同时关系是否成立」：一辆小车可以严格沿参考轨迹运动，而货物始终悬在车厢上方。现有基准各测一半——Code4Scene 查场景编辑后的引擎状态、PhySimCode 查物理参数、Video2World 查能否执行任务、4DCodeBench 查动态过程可执行性——但没有在同一份被独立重开的工程里同时给几何、运动、关系分别记分。作者据此构建 114 个条件、四个 track 的基准，并在 24 个 from-scratch 任务上发现：两个模型都能在 14 个任务上拿满 dynamics 分，其中 Sol 有 3 个、Astra 有 8 个 relations 得 0 分。

## 方法详解
任务定义为 $p_{i,a,m}=\mathcal{M}_m(O_i,\mathcal{A}_{i,a},q_{i,a})$：给定观测 $O_i$、起始资产包 $\mathcal{A}_{i,a}$ 与指令，智能体输出可被重开的 Blender 工程。四个 track 分别是图像编辑、full-asset 视频、partial-asset 视频（30 对共享参考/目标/评分卡，仅资产包不同）与独立挑选的 from-scratch。准入分 $A=40\sum_g w_g f_g+40\sum_g w_g v_g+5\sum_{j=1}^{4}k_j$，要求 $A\geq 80$ 且四项二元检查全过（如 MV02V/F 得 89.14）。评测端由 Blender adapter 在 $t=\mathrm{PTS}\times\mathrm{timebase}$ 处重开工程、读帧与子帧状态，按维度预算把分数分到语义组与准则：$b_\ell=W_d/(|\mathcal{G}_d||\mathcal{L}_g|)$。单条准则的得分率是分段线性函数 $q(e;\tau)=\max(0,\min(1,(3\tau-e)/(2\tau)))$，误差 $\le\tau$ 满分、$2\tau$ 半分、$\ge 3\tau$ 零分，二元谓词只给 0/1。图像编辑的保真度为 $B=T+P+C$（目标 60、保持 25、相机 15），并要求严重变换失败时用 $\rho_g=2\min_{\ell\in\mathcal{F}_g}q_\ell$ 压制目标分。证据不确定时分数以区间传播：未知证据贡献 $[0,b_\ell]$，加权覆盖率 $\kappa=\sum b_\ell z_\ell/\sum b_\ell$；只有区间坍缩且证据确定才发布单一分数。严格完成另需 $B^-\geq 80$、$\kappa\geq 0.95$ 与全部关键准则满分。以 IN02 为例，货箱轨迹占 8.75 分（33 个公开采样点、$\tau=0.06$），两条各 12.5 分的关系准则用 192 个源状态检查「释放先于接触」与「全程保持支撑」。

## 实验与结果
- 条件总数：114 个（图像编辑 / full-asset 视频 / partial-asset 视频 / from-scratch 四个 track），归档分数 228 条
- 图像编辑均值：Sol 72.36、Astra 75.09（满分 100）
- full-asset 视频均值：Sol 13.00、Astra 21.79；partial-asset：Sol 30.58、Astra 21.58
- from-scratch（Z24）恢复保真度均值：Sol 66.29、Astra 59.78；中位数 75.00 / 71.67
- 关系项贡献：Sol 与 Astra 的 6.50 分均值差中 5.15 分来自 relations
- 关系全零比例：在 dynamics 满分的 14 个任务中，Sol 3/14、Astra 8/14 的 relations 为 0
- 视频条目零分：120 条中 46 条为 0，其中 44 条是原始执行失败、2 条是实测场景分
- 准入阈值：$A\geq 80$ 且 4 项检查全过；MV02V/F 的准入分为 89.14

## 创新点与贡献
- 相对 BlenderGym（只评对给定场景的编辑）、4DCodeBench（只评动态过程可执行）、VibePrevisBench（渲染代理 + 原生检查），Asset4D 把几何、运动、关系拆成独立预算，并在同一份被独立重开的工程里按原始事件时刻测量，因此能区分「终点对但过程错」
- 配对 full/partial 起始资产让「同一参考、不同可恢复量」成为受控变量
- 版本化评分卡 + 证据覆盖率区间则把「测不出」与「测出错」分开，避免未知证据被当成零分

## 局限与风险
- 作者自述：归档运行之间执行与恢复策略不一致，因此不能把 full/partial 的均值差解释为起始资产效应的因果估计
- 评测只覆盖规定的回放，不测交互式玩法、反事实物理或迭代反馈收益
- 包围盒、基网格顶点与事件谓词不能证明力、任意隐藏状态或用户编辑后的行为
- 我们另看出：只有两个模型配置，且归档未记录统一的评审模型、人工评分人数与一致性，跨模型排名可比性有限
- 30 对资产对的 60 个 model-by-reference 组合中只有 41 个绑定了同一批输入

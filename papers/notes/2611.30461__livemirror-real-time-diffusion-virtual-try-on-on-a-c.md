# LiveMirror：消费级 GPU 上的实时扩散虚拟试衣及其对印度民族服饰的自监督适配

## 一句话结论
把「显示时钟」与「生成时钟」解耦，用光流 warp + 交叉淡化让 400 ms/帧的扩散模型支撑相机帧率：720p 25 FPS（RTX 4080），IndoFashion 留出 LPIPS 0.137→0.077，长裤失败率 33%→4.2%，并给出「哪些加速会破坏印花」的实测清单。

## 要解决的问题
扩散虚拟试衣（VTO）能从单张商品图生成可信换装，但每张需数百毫秒到数秒，部署要么离线上传等待，要么退回 AR 镜子叠加需逐商品制作 3D 资产的绑骨服装。真人站在镜前时每一帧都在动，同步跑模型会把显示降到 2–3 FPS，直接把结果贴到当前帧又会滞后跳动。另一问题是文化覆盖：主流模型在 VITON-HD/DressCode 上训练，类别只有上衣、下装、连衣裙；南亚长款 kurta/sherwani 是「长上衣盖在长裤外」的轮廓，用标准上半身掩码会被截成衬衫，用全身掩码会触发连衣裙先验露出裸腿，用中间掩码则把大腿带填成皮肤，且无法靠推理时设置修复。

## 方法详解
核心是异步关键帧试衣：扩散生成器在独立线程对人物裁剪块生成关键帧，显示循环在每一相机帧上运行且从不等待生成；每个显示帧都是「最新关键帧 → 当前帧」的稠密光流（OpenCV DIS，CPU ultrafast）前向 warp；新关键帧只通过 6 帧交叉淡化进入，且每个被跟踪人物固定扩散种子以减小相邻关键帧差异；hold 模式下仅在服装变化、人物移动超过裁剪宽度 1/4 或用户请求时才重生成。管线为 YOLO11n + ByteTrack 锁定单人，3:4 裁剪加 15% 边距缩放到 384×512；SCHP ATR/LIP 与 DensePose 构建 clothing-agnostic 掩码，按服装选择 long/upper，长款再在上一关键帧下摆下方 40 px 处切出 hem-aware 两遍掩码；CatVTON 使用 Run B 注意力权重 + LCM-LoRA、6 步、无 CFG、完整 VAE 解码；解析器后处理移到 GPU 使掩码阶段从 240 ms 降到 70 ms。适配部分构造 24.9k 自监督三元组：以人物照的 parser 抠图作为 garment card、原照作为 target，经质量过滤后与 VITON-HD 混合，只微调 CatVTON 的自注意力层（49.6M），两阶段共 3.2 GPU-hours。

## 实验与结果
- 720p 显示 25 FPS，新试衣关键帧每 370–490 ms 到达（RTX 4080 16 GB）
- IndoFashion 200 对留出：LPIPS 0.137→0.077；Atlas：0.135→0.073
- 长裤失败率从 33%/32% 降到 17%/16%（Run B），加 hem-aware 两遍掩码后降至 4.2%/2.5%
- 下摆带保真 LBF 从 0.389/0.417 升到 0.547/0.558，加 hem 后 0.713/0.715
- VITON-HD 西式上衣 LPIPS 0.130→0.117，PSNR/SSIM 基本不变
- FASHN VTON 1.5 在 Atlas LPIPS 0.152、IndoFashion 0.119；Run B 为 0.073/0.077，推理 0.4 s vs 8.5 s（约 20×）
- 掩码阶段 240→70 ms（99.97% 标签一致）；训练峰值显存 7.1 GB、总 3.2 GPU-hours
- Run A 仅 501 对过采样已把 Atlas LPIPS 降到 0.083，Run B 的 23.6k 对再降 0.010–0.011

## 创新点与贡献
- 把「显示时钟」与「生成时钟」解耦，用光流 warp + 交叉淡化让 400 ms/帧的扩散模型支撑相机帧率的镜子，并给出逐阶段时延预算与哪些加速会破坏印花的实测
- 数据侧用 parser 抠图自动构造自监督配对，绕开民族服饰缺少 flat-lay 配对数据的瓶颈
- 长掩码与 hem-aware 两遍掩码分别解决「能否表达长衣盖裤」和「下摆以下长裤被重绘」两个不同失败

## 局限与风险
- 作者承认闪烁/ warp 对比是在合成视频上测的，仅含小角度旋转，侧视、交叉手臂、快速转身未测
- 关键帧切换仍有 8–13 个灰阶的可见变化
- 长掩码遮住大腿带，模型只能猜长裤颜色，两遍掩码后仍有 3–4% 失败，首帧换装仍用全掩码
- 评测是自配对重建（重构本人已穿的衣服），比跨服装迁移容易，未测印花/版型忠实地转移，也无人类偏好研究
- sherwani 与 Nehru jacket 样本仅 14/41 对
- 卡片域差异（训练用 in-pose 抠图、部署常用 flat-lay）未量化
- 纱丽、lehenga、dhoti 未覆盖
- 代码仅「可应要求提供」

# ProactEgoMem：流式第一视角视频的主动记忆基准

## 一句话结论
ProactEgoMem 是流式第一视角主动记忆基准：IC/ST/LT 三任务族 × Notification/Intervention 两级主动性，干预级要求 start-maintain-stop 工具生命周期，Hungarian matching 按时序+语义联合评分；Daily/Sci 双轨 300/100 clips + 1000/500 QA。实验室轨道最好通知 F1 仅 10.8%、最好干预重叠 10.2% mIoU，30 个 model-task cell 中 7 个零有效通知、10 个零有效干预。

## 要解决的问题
可穿戴多模态助手要替用户跨长时程记住环境，就不能被动等 prompt，而应主动获取并维持有用记忆：需要识别什么重要、实时理解场景、在后台启动记忆维护而不打断用户活动。既有评测全部缺一环：离线套件对完整片段做查询驱动问答；流式基准仍在自选时间戳 prompt 模型；流式情景记忆基准虽测连续流回忆但由系统提供问题；快速增长的主动线去掉查询却只记单个 respond-now 决策。无人同时覆盖流式第一视角输入、无查询主动性、工具生命周期与下游记忆验证——这正是 ProactEgoMem 的定位。

## 方法详解（含关键公式/架构，保留原文术语）
基准由三任务族与两级主动性定义。任务族：IC（Information Capture，保留瞬态而密集的视觉信息）、ST（State Tracking，跟踪物体状态变化）、LT（Location Tracking，记录物体移动）。两级主动性：Notification 级要求单次及时通知以满足用户意图；Intervention 级要求 agent 通过 start-to-stop 工具生命周期主动替用户维持记忆，即评测其「启动—维持—停止」的边界是否正确，工具接口见附录 C。Table 5 基准对比显示：离线套件（Video-MME/LongVideoBench/MLVU/EgoSchema/HourVideo/EgoLifeQA）四属性全无；流式 QA（StreamingBench/OVO-Bench）仅部分主动；流式情景记忆（EgoStream/S-EMBER）有 Mem.QA 但无主动与生命周期；主动线（OmniMMI/ProAssist/ProactiveVideoQA/EgoServe/EgoPro-Bench）只记单个 respond-now 决策——ProactEgoMem 是唯一 Proactive、Multi-Level、Tool Lifecycle、Mem. QA 四项全标的基准。流式协议：FPS=1，每步给定统一 prompt + JSON assistant context + 视频帧窗口，模型每步输出一个 JSON 对象，所有基线用完全相同的流式设置，模型特化代码只负责包进各自 chat template。匹配与指标：两级预测分别以 Hungarian matching（Kuhn 1955）与 ground truth 匹配，要求 LLM-judge 语义相似度超阈值且时间偏移落入匹配窗口，admitted 边中最小化代价 α(1−sim)+(1−α)(|Δ|/W)^p；干预预测先转 interval 按时间重叠匹配。三组共享指标：Timing（Start@τ，主结果 Start@0.2，200 ms 容忍对应标注者对通知时机的残存分歧）、Abs Error（|Δ_s| 与 σ）、Detection（Prec/Recall/F1）；干预级专有：Overlap（mIoU，未匹配机会记 0，另报 IoU@τ）与 QA（Acc，ProactEgoMem-QA 用下游问题检验自获取记忆的质量）。数据：ProactEgoMem-Daily 300 clips + 1000 问，ProactEgoMem-Sci 100 clips + 500 问（摘要口径）。

## 实验与结果（表格化关键数字）
基线覆盖四类：专有（Gemini 2.5 Flash、GPT-5.4-mini）、通用开源（Gemma4-31B、Qwen3.8-27B、Qwen3.6-27B、Qwen3.5-9B）、视频语言（VideoLLaMA3-7B、LLaVA-OV-1.5-8B、MiniCPM-o-4.5）、流式（MMDuet、VideoLLM-Online、Inkling-Small、JoyAI-VL），全部以相同流式设置（FPS 1、统一 prompt、JSON 输出）评测，预测在两级主动性下分别匹配与评分（5.1），QA Acc 检验主动获取记忆的下游可用性。实验结构：5.1 指标与基线、5.2 流式评测协议、5.3 主结果、5.4 主动记忆获取效应、5.5 从日常到实验室、5.6 失败模式；附录 G 给两级分别结果、E 析主动性时序阈值效应、H 给定性失败案例，digest 未抓取其数值。日常轨道（Daily）：摘要称即使最强模型也无法同时及时且准确地捕获记忆；digest 未含日常轨道逐模型分数表。实验室轨道（Sci）结果（结论段口径）：最好通知 F1 跌至 10.8%（Gemma4-31B on LT），最好干预重叠 10.2% mIoU（Gemma4-31B on ST）；30 个 model–task cell 中 7 个发不出任何有效通知、10 个发不出有效干预。专有 vs 开源（跨模型与任务平均）：通知 recall 32.3% 对 22.9%，但 notification precision 4.1 对 7.1、干预重叠 1.9 对 2.9 mIoU、干预 recall 7.2 对 12.1、记忆 QA 32.6 对 37.8——专有模型群『买来覆盖而非能力』。

## 创新点与贡献
- 基准四属性首个齐备：流式第一视角输入、无查询主动性、start-maintain-stop 工具生命周期、下游记忆 QA 验证（Table 5 对比中唯一四项全标）
- IC/ST/LT 三任务族把『什么值得主动记』落地为可评的环境信息类型（瞬态密集信息/状态变化/物体移动）
- Notification/Intervention 两级主动性协议：干预级以生命周期边界（启动-维持-停止）评分，替代单点 respond-now 决策
- Hungarian matching + 代价 α(1−sim)+(1−α)(|Δ|/W)^p 实现时序与语义联合评分，Start@0.2 主指标对齐标注者时间分歧
- Daily→Sci 跨域设计放大并暴露所有模型的联合失效模式（F1 跌至 10.8%）

## 局限与风险
- 实验室轨道规模小（100 clips/500 QA），最好成绩仅约 10%，接近地板效应，区分度有限
- 评测依赖 LLM-judge 语义相似度与人工标注时机，本身含标注者分歧（200 ms 容忍度）
- 30 个 model–task cell 中 7/10 个发不出有效输出，部分模型在该 JSON 流式协议下无法完成基本交互
- digest 未含日常轨道逐模型分数表与两级结果明细（附录 G 未抓到）

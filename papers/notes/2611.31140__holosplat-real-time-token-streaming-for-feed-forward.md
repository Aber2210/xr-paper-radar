# HoloSplat：面向前馈人体重建的实时 token 流式传输

## 一句话结论
把码率控制点从 Gaussian 属性前移到 Gaussian head 之前的 token 空间，并用零膨胀逆自回归熵编码：4×RTX 5090 上 32.2 FPS @ 50 Mbit/s，笔记本 3050 Ti 解码单帧 22.1 ms，Pro 档 208.2 kB/帧仅为未压缩 float32 的 1/22.8，是首个把「自由视点人体流式」三级 33 ms 预算全部跑满的端到端系统。

## 要解决的问题
人体自由视点视频直播要求每帧实时重建、在严格带宽内传输、并在轻量客户端 GPU 上解码。现有逐帧优化或前馈推理方法都会产生海量 3D Gaussian 载荷，远超实际流式带宽；激进压缩又会严重损害渲染质量。三级流水线各自有 33 ms（30 FPS）预算：服务器重建、100 Mbit/s 级下行、客户端解码为可渲染高斯。

## 方法详解
HoloSplat 在冻结前馈重建器（PointSplat）的 Gaussian head 之前切分网络，做多码率 token 流式编解码。服务器端：先用轻量 predictor $g_\phi$ 回归 16 个 slot 的 opacity logits，按 $q_i=\max_k\sigma(g_\phi(f_i)_k)\ge\delta$（$\delta=0.075$）做 opacity-guided token pruning；再对首帧 token 拟合会话级 PCA，$c_i=U_r^{\top}(f_i-\mu)$、$\hat{f}_i=\mu+U_r\hat{c}_i$，每帧传每维一个 range 并在其中均匀量化到 $b$ bit，按 component-major 顺序 Zstd 压缩，Lite/Pro/Ultra 分别为 $(r,b)=(32,4),(48,6),(80,6)$；anchor 坐标走无损体素编码（坐标表 + 3×3×3 occupancy 32-bit mask + slot index）。客户端：把逆 PCA 解析地折进 head 首层线性映射 $y=(WU_r)\hat{c}+(W\mu+b_0)$，避免显式展开 1024 维；再用残差 hypernetwork $\tilde{f}_i=\hat{f}_i+H_\theta(\hat{f}_i,X_i-\bar{X}_i,\frac18\sum_{j\in\mathcal{N}_i}\hat{f}_j;r,b)$ 恢复被丢弃分量，$H_\theta$ 直接以 $\|W(f_i-\tilde{f}_i)\|_2^2$ 对未压缩 token 训练，无需渲染，且用 tier embedding 生成 FiLM 参数使一个网络服务所有码率。Neural Session Calibration 在 warm-up 的 30 帧上用输入视角自监督微调 head，损失 $0.8\ell_1+0.2(1-\mathrm{SSIM})+0.1\mathrm{LPIPS}$，更新参数化为三层 per-slot MLP 的 rank-5 增量 $\Delta W_\ell=A_\ell B_\ell$（仅 20,480 个 FP16 参数），一次性下发，零每帧开销。帧间独立编码，服务器按帧并行、CUDA MPS 多 worker、reorder buffer 按采集序发包，支持随机接入与无误差传播。

## 实验与结果
- 4 张 RTX 5090 上平均 32.2 FPS @ 50 Mbit/s；1/6 张时分别为 8.0 / 51.3 FPS
- RTX 3050 Ti 笔记本 GPU 上每帧解码为 3D Gaussians 仅 22.1 ms
- Pro 码率 208.2 kB/帧 vs 未压缩 float32 4,753.1 kB/帧，数据量少 22.8×
- Pro PSNR 27.219 dB vs PointSplat512 26.169 dB；Lite 94.8 kB 仍有 26.840 dB
- 校准解码（hypernetwork + NSC）使 Pro 提升 1.050 dB；hypernetwork 单独恢复 80.4% 压缩损失（+0.483 dB）
- NSC 在 HiFi4G / ActorsHQ 上额外 +1.419 / +1.436 dB；12 参数颜色仿射仅 +0.076 / +0.119 dB
- opacity-guided pruning 去掉 23.6% token 组而不损 PSNR，Ultra 包减小 23.5%
- 最小 Gaussian 格式 Draco 需 723.0 kB/帧，是 Pro 的 3.47×；CodecSplat 最高 23.1 dB 且解码 199 ms

## 创新点与贡献
- 把码率控制点前移到 Gaussian head 之前的 token 空间：token 是低维、紧支撑的中间表示，对量化扰动远不如指数尺度的 Gaussian 属性敏感，因此同码率下质量显著更高
- 用「逆 PCA 折进首层 + 残差 hypernetwork 折进输出层」实现恢复过程零显式 token 展开，使客户端解码落在 22.1 ms
- NSC 只用 warm-up 一秒的输入视角、以 rank-5 低秩增量在线校准 head，解决新相机参数与采集条件漂移，且不增加每帧开销

## 局限与风险
- 作者承认：帧间不跟踪 Gaussian 身份，以放弃时序对应换取无栅栏并行、逐帧随机接入与零误差传播
- 会话建立需在四卡上 24 s 才能上线
- 从正文看，方法绑定单一前馈重建器（PointSplat）与固定 8 视角 rig，换 rig 需重新 warm-up 校准
- 在极低码率（低于一视图 token 量）质量快速下降而渲染时间几乎不降，因为每个 target token 仍要过完整 decoder
- 对带宽远低于 50 Mbit/s 的场景未给可用工作点

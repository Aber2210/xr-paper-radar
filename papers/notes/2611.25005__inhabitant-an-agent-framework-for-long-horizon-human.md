# Inhabitant：具备空间控制与定量反馈的长时序人-场景交互智能体框架

## 一句话结论
给长时序人-场景交互智能体补上「空间控制」与「定量反馈」两个缺失接口：75 个任务完成 74（98.7%），最佳基线仅 26.7%。

## 要解决的问题
长时序人-场景交互（HSI）要求语言模型智能体在三维场景里规划并执行一串交互（把方块放进篮子、把球踢到桌下），且每步都由全身动作完成。现有智能体在此类场景大面积失败，论文用「从台面抓方块」这一失败链说明：智能体先试着抓，手掌在离方块几厘米处闭合，抓空；它无法纠正，因为文本提示说不清手该到哪个坐标，渲染帧也只告诉它失败了而不告诉差多少；于是改写措辞，再抓空一次。第一类原因是控制太高层：只能给技能加一个参数（HumanCLAW）、给每步一句文本（Motion-Agent、InteractAgent），或给少量接触/目标点（UniHSI、BiBo），无法指定精确的位置、路径与姿态。第二类是反馈缺失或只有定性：多数方法规划一次就不再看执行结果（UniHSI、World2HOSI、GEMS），另一些只看渲染帧（InteractAgent），能看出失败却无法量化偏差。误差因此沿链条累积：一次没抓准，后续所有交互的初始条件都被污染。现有 HSI 基准又多是一次交互、静态目标（走到家具前坐下），具身家务基准虽长时序却靠 navigate/pick/place 等预定义技能，绕开了「身体是否真的够到并搬动」这一问题。

## 方法详解
形式化：序列 Σ=(s_0,…,s_N)，s_t 含身体、物体与铰接家具位姿；智能体以「段」为单位，段 τ_k 是数秒片段；给定指令 I、初始状态 s_0 与隐藏成功规则 G，目标是 G(Σ)=1。框架无训练，三部件由两接口相连。控制侧：智能体直接写预训练生成器 Kimodo 的控制规范 c，m=G(c;h)，h 为上一段末几帧转成的全身约束；c 含带时长的文本提示时间线、空间约束集合 K、采样参数（种子与文本/约束引导权重）。K 有三类：root waypoints（固定根节点地面位置与朝向）、end-effector targets（固定某手或脚到目标位置）、full-body keyframes（固定全部关节）。智能体与 Kimodo 之间无中间表示，可用正向运动学问「该姿态下我的手在哪」再决定是否使用。生成骨架与仿真骨架骨长不同，执行前用 ρ 迁移并保持脚离地高度、解 IK 得关节旋转。反馈侧：半物理仿真器 E 从上一段末状态执行 ρ(m) 与交互事件 e，τ=E(s_{t_k},ρ(m),e)；身体被家具阻挡时会偏离生成动作，物体只经接触被动运动，抓取用掌心距离规则抽象。每次 try 后自动收到定性反馈：成功规则是否满足 + 8 帧双机位渲染；定量反馈须主动调 measure(q)，返回 M(q,τ)，q 指定测什么、测谁与谁、哪帧或区间，共 7 类（部位位置、部位到物体/表面/把手距离、接触、某帧执行姿态、物体位置、物体间或到区域距离、物体/家具尺度）。四原语为 try(c,e)、measure(q)、commit、rollback(j)：候选段未提交前可反复重试，commit 才追加，rollback 回到早前段末并丢弃其后所有段。测量与控制同坐标系，故可把偏差直接换算成约束修正（手目标按测得距离平移，或把执行过的姿态复用为关键帧）。基准 Inhabit：ReplicaCAD 公寓 31 种布局、75 个任务（30 单目标 low、20 双目标 mid、15 三目标 high、10 目标+姿态 posture），五类目标为放置、1 m 外投掷、用脚推移不抓取、开关抽屉/冰箱、摆姿态；成功规则为各条件合取且对智能体隐藏；episode 预算 150 次 LLM 调用；指标含 Success、Sub-goal、Collisions、Disturbed（非目标位移 >5 cm）、Skate、Tries、Calls、Tokens。

## 实验与结果
- 75 个任务主结果：Claude Opus 5.5 下完成 74/75（98.7%），Sonnet 5.5 93.3%、Gemini 4 Argon 82.7%、GLM-5.3-Flash 44.0%、gpt-6-luna 30.7%
- 同用 Opus 5.5 的最佳基线 InteractAgent 仅 26.7%
- 分层对比：high 层（三目标）Opus 5.5 达 100%，InteractAgent 0.0%、HumanCLAW 6.7%、GEMS 0.0%
- posture 层 90.0% vs 基线最高 20.0%
- 空间控制粒度消融（20 任务子集）：纯文本提示 20.0% → 加 root waypoints 90.0% → 加 end-effector targets 95.0%
- 抓空率 73%→40%，tries 61.0→14.8，calls 134→47
- 反馈粒度消融：无测量时成功 85.0%、碰撞 14.6、tries 22.7
- 全反馈 95.0%、7.8、14.8
- 去掉成功检查后从 95.0% 掉到 85.0%（仅剩帧时 85.0%→70.0%）
- 执行循环消融：Inhabitant 95.0%，Single-Try（每段执行即提交）75.0% 且碰撞 30.4（约 4 倍），Open-Loop（一次写完所有规范、无反馈）0.0%
- 全 75 任务去掉成功检查后仍有 86.7% 成功，自判停止的 10 个 episode 中 9 个确实成功
- 物理可跟踪性：用 PHC+ 控制器在平地复现 Opus 5.5 的序列，未被家具支撑的部分 94% 不摔倒，失败一半集中在以跪/卧姿态结束的任务
- 成本：Opus 5.5 下每个解出任务 $1.7 API 费用，基线为 $4.8–$21.1
- Opus 平均 51 次调用、17.1 次 try、99k token

## 创新点与贡献
- 把长时序 HSI 重构成闭环空间控制问题，明确提出并实现两个缺失接口：以位置/路径/姿态写入动作生成器的空间控制，与以度量而非画面给出的定量反馈。
- 提出 try/measure/commit/rollback 四原语，使「未提交的候选段可反复重试」成为一等公民，从机制上防止一次不准的动作污染整条序列。
- 测量与控制共享坐标系，使测得的偏差可直接换算为约束修正，把语言智能体的纠错从改写提示变成解一个几何残差。
- 构建 Inhabit：75 个任务、31 种布局、每步必须由全身动作（不含手指）完成、成功规则判定物理结果，并同时度量碰撞/扰动/脚滑等动作质量。
- 用五种 LLM 与三组消融把「接口」与「模型能力」的贡献分离，指出弱模型配好接口仍优于强模型配坏接口。

## 局限与风险
- 作者自述四条：需要可反复试错的仿真器，更适合离线动画与数据生成，在线不可逆场景应看 Single-Try 的 75%
- 身体是运动学驱动，无平衡、力矩与手指，抓取靠距离规则
- 智能体被直接告知状态描述与每次 try 的成功检查，换成感知输入是未来工作
- 受预算限制每任务只跑一次、消融只用 20 任务子集，基线为作者自行适配
- 从设计看还有：所有基线共用作者的仿真器、状态描述与预算，适配质量直接影响 26.7%，缺原始实现对照
- 单次运行无方差估计，98.7% 与 93.3% 的差距可能落在噪声内
- 成功规则由作者定义且隐藏，松紧未做敏感性分析
- 75 任务集中在单个公寓的 31 种布局，跨户型泛化未验证
- 半物理下物体仅受接触驱动，无摩擦与形变，真实抓取成功率未知
- 依赖商业 LLM API，成本与版本漂移影响可复现

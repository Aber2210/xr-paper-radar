# WM^MLLM：把多模态大模型变成世界模型

## 一句话结论
把世界状态从生成器里搬出来，由 MLLM 写「全景 + 修订历史」，使回访与局部编辑的一致性按构造成立（摘要自述 Epipolar 91.5 vs ≤74.0）。

## 要解决的问题
一个可交互的世界模型需要三条性质：重访时能看到当初存在那里的内容（return）、局部编辑不改动区域之外的像素（locality）、每一次请求都建立在上一次的结果之上（persistence）。视频世界模型把“世界”放在生成器的上下文里：Genie 3 支持导航与可提示事件，LongLive 在提示变化时更新上下文缓存，Matrix-Game 3.0 做相机感知的记忆检索，HY-WorldPlay 重取历史观测，WorldMem/Context-as-Memory/VMem 按位姿、视场重叠或 surfel 索引检索记忆——但这些都是“以记忆为条件重新合成”，重访时必须再生成一遍，早先的编辑会漂移甚至消失；作者实测一次相机往返后五个视频世界模型基线都停在完全不同的场景（首末帧平均像素差 88.4–101.3，0–255）。显式 3D 世界（HunyuanWorld 的网格、WonderWorld 的 Gaussian surfels、Marble 的区域编辑与天气/季节）可渲染可编辑，但在所有具备显式世界状态的系统里，没有一个同时记录 MLLM 规划器、物体编辑、精确 return 与“编辑进入状态前的检查”这四项能力。控制类世界模型（OpenVLA、π0 之类 VLA 与 V-JEPA 2）只输出动作或嵌入，没有可编辑图像。因此缺口是：如何让世界状态不被任何生成器持有，同时又能被语言/多模态指令持续编辑与验证。

## 方法详解
总体思路：把世界状态放在所有生成器之外，由 MLLM 来写。状态 W_t 是一个全景（panorama）加原生分辨率的 patches，另存场景关系与从图像中观察到的事实（scene graph）、修订历史（revision history），以及本轮用到的 base、composite 与 patches；每个物理改变都推进一次 revision，重访只是选择当前 revision 的某个视角。每一轮：MLLM（GPT-6.1-sol）把用户请求与可选框解析成对该状态的操作，决定局部编辑写到哪里，并在候选提交为下一状态之前做检查；图像生成器只“提议视角”（GPT-Image 出候选），视频生成器（Sol-H3）只呈现转场、不写状态。旋转与重访直接渲染状态、完全不调用图像生成器，因此 return 来自“视图复用”，locality 来自“只在支撑域内合成”，persistence 来自“按 revision 查找”——三者由写入方式在构造上成立（Proposition 1–3），而不是靠生成器的上下文去复现。关键设计是局部编辑的支撑域（support）在生成之后选择：图像生成器可能把主体移出预先预测的区域，事先划定的区域会把变化截断，所以让 MLLM 比较 source 与 proposal，标出物体的旧足迹与新足迹以及必要效应，栅格化为 U_t，再膨胀为掩码 M_t；proposal 先配准到稳定背景 S_t 上，再以权重 β_t 混合；最后由检查确认 A_t 之外的全景像素没有任何改变，未通过则保留原状态（示例中失败的一轮即保持状态不变）。提交时写入 W_{t+1}（scene graph、修订历史、本轮的 base/composite/patches），不同路由（旋转、重访、全局变化如光照/天气/季节、行走、物体编辑、主体放置）只改状态的不同部分；蓝线路由不调用任何图像生成器。为了可核验，作者还从本轮记录重算步骤 4–6。一个会话可连续多轮：8 请求的示例里，房间的新光照在走开再回来后仍在，后续编辑建立在其上；6 号轮逐像素复现 3 号轮的视图，8 号轮只改动红框内 2.1% 的全景像素。

## 实验与结果
- MBench-A 四项环境恢复指标全部取得最高均值：Epipolar 91.5，六个世界模型基线为 0.1–74.0
- 同一 MBench 评测器下对比
- 相机往返完成率 85.3%，基线最高仅 50.9%（区间 0.4%–50.9%）
- 一次往返后首末帧平均像素差 1.1（0–255），五个视频世界模型基线为 88.4–101.3
- CompBench：在 15 个指标列上相对 15 个基线全部最优（best value in all 15 columns）
- 112 个局部编辑盲评：支撑域改为“生成之后选择”使完成率由 34.8%（生成前预测支撑域）升到 83.0%
- 258 个 WBench 与 MBench-A 条目：46 次重访全部精确恢复原视图，97 个通过检查的局部编辑全部保证区域外全景像素不变
- 单世界连续 21 次请求中状态保留每一处早期修改
- 精度示例：某轮局部编辑仅改动红框内 2.1% 的全景像素，其余像素保持不变

## 创新点与贡献
- 范式层面的新意有三点
- 第一，世界状态的归属被改写：不再把世界放进生成器上下文或某个 3D 表征里让渲染器去读，而是把“全景 + 原生分辨率 patches + 场景图 + 修订历史”当成一份可被语言操作的数据结构，MLLM 是这份状态的唯一写者，图像/视频生成器降级为“提议视角”与“播放转场”
- 第二，把 return / locality / persistence 从“希望生成器复现”变成“由写入协议保证”：旋转与重访纯渲染、局部编辑只在支撑域内合成、每轮从上一轮结果起步，因此这三条性质是构造性的（作者给出 Proposition 1–3 并逐条用 46 次重访与 97 次编辑验证），这与依赖记忆检索的视频世界模型是根本不同的路线
- 第三，编辑的支撑域在生成之后由 MLLM 通过比较 source 与 proposal 来选（旧足迹 + 新足迹 + 效应），直接解决了“预先预测区域会截断变化”的问题，使 112 例盲评完成率从 34.8% 跳到 83.0%

## 局限与风险
- 本稿可读部分（摘要、引言、相关工作、图注）没有作者的限制段，但可从设计看出若干约束：整条链路依赖商用闭源模型（GPT-6.1-sol 作规划器、GPT-Image 作提议、Sol-H3 作转场），成本、时延与吞吐均未报告，也无法端到端复现
- 状态是全景 + patches，天然偏向可 360° 成像的室内场景，对超大场景、室外与强动态物体的可扩展性未验证
- return 与 locality 是“构造上精确成立”的主张，但评价集中在 MBench-A/CompBench/WBench 的自动指标与像素级检查，缺少人类对编辑自然度、视觉质量与长会话漂移的主观评测
- 每轮都要 MLLM 解析 + 生成 + 检查 + 配准，交互延迟大概率不适合实时 XR
- 此外，本次抓取的 HTML 缺失方法章（第 3 节）与实验章正文，训练细节、超参、失败案例分类与计算开销无法核验，只能依据摘要、引言与图 1–3 的图注

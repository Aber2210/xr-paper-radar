# digest 生成规范（2026-11-27 批次）

## 任务
对分配的每篇论文，读 `data/fulltext/<id>.txt` 全文，产出**一个 JSON 数组**，每篇一个对象。
中文撰写，领域术语保留英文原文（首次出现给中文），**不得编造**：正文没写的数字一律不写。

## 输出文件
`data/digest_1127_g<N>.json`（UTF-8，`ensure_ascii=False`，缩进 1）。
写完必须自检：`python -c "import json;d=json.load(open(...));print(len(d),[r['id'] for r in d])"`，
条数与本组 id 数一致、id 集合逐字符相符。**不复核就不算完成。**

## 每篇对象的字段（全部必填，不得省略键）

| 字段 | 说明 |
|---|---|
| `id` | base arXiv id，如 `2611.30173` |
| `title` | 英文原题（与正文一致） |
| `title_zh` | 中文译名，格式「中文：副标题中文」 |
| `problem` | 要解决的问题。**必须含正文具体数字/现状**（如某基线在某数据集上的指标），3–5 句，可含 LaTeX 行内公式 |
| `method` | 方法详解。关键公式用 LaTeX（`$...$`）、关键模块名保留英文、给出超参/损失/流程，6–12 句；有架构就写清数据流 |
| `key_numbers` | 字符串数组，每条一个「指标：数值（数据集/设置）」；只写正文表格或正文明确陈述的数字，**不少于 4 条** |
| `ablation` | 消融结论（哪一项贡献多少），无消融则写「无独立消融」并说明有何替代证据 |
| `baselines` | 字符串数组，对比基线名称（≥3 个，正文实际对比的） |
| `datasets` | 字符串数组，数据集/实验平台名称 |
| `novelty` | 创新点，2–4 句，写清「相对谁、新在哪」 |
| `limitations` | 局限与风险，2–4 句；优先用作者自述 + 你从实验设置看出的缺口 |
| `trl_evidence` | 落地成熟度的**事实依据**（是否开源、是否真机/在线、是否产品化、算力与延迟），2–3 句 |
| `code` | 开源情况，如「已开源 github.com/xxx」「承诺开源未给链接」「未提及」 |
| `venue` | 如「arXiv preprint」「IEEE VR 2026」；正文没写就写 `arXiv preprint` |
| `scores` | 7 维整数 1–5：`{"IMP":n,"NOV":n,"TEC":n,"EXP":n,"PER":n,"TRL":n,"REP":n}` |
| `scores_why` | **字符串**（不是 dict！），单行，逐维给依据，格式：`IMP=4：…。NOV=4：…。TEC=4：…。EXP=3：…。PER=4：…。TRL=3：…。REP=4：…。` |

## 打分锚点（务必对齐，不要普遍给 5）

- **IMP**：5 = 领域公认卡脖子（如 SLAM 的尺度漂移、动态场景重建、实时性瓶颈）；4 = 真实但被局部解决的问题；3 = 有价值的工程问题；2 = 边缘问题。
- **NOV**：5 = 新范式；4 = 明显新架构/新监督；3 = 已有路线的实质改进；2 = 组合式增量。
- **TEC**：5 = 理论+系统+消融齐全；4 = 有完整方法与消融；3 = 方法清楚但缺证明/缺消融；2 = 只有想法。
- **EXP**：5 = 多数据集 + 真机/大样本用户实验 + 充分基线；4 = 多数据集充分基线；3 = 2 个数据集或基线偏少；2 = 单一设置。
- **PER**：5 = 相对 SOTA 提升 >30%；4 = 10–30%；3 = 明显但 <10% 或仅特定子集；2 = 提升微弱/有负结果。
- **TRL**：5 = 产品化/可商用；4 = 真机在线系统 + 开源；3 = 可复现原型；2 = 离线实验；1 = 纯理论。
- **REP**：5 = 代码+数据+顶会；4 = 代码开源；3 = 承诺开源/细节充分；2 = 细节不足。

**校准纪律**：库内 4.50+ 的论文（riMESA 4.50 / Open-HumanScale 4.57 / Map2SLAM 4.57 / MoGe-4D 4.57）是「能力级突破」。只有当你认为该篇与这些同档，才允许打出加权 ≥4.5 的组合。绝大多数论文应落在 3.0–4.2。

## 证据等级
若 `data/fulltext/<id>.txt` 头是 `# EVIDENCE: PARTIAL`，正文可能只有摘要，此时：
`problem`/`method` 只能写摘要明确陈述的内容，`key_numbers` 若摘要无数值就只写摘要给出的，
并在 `limitations` 首句写「证据等级 PARTIAL，未获取完整正文，以下为摘要级评估」。
`key_numbers` 至少 1 条即可（不要为凑数编造）。

3.1 Interactive World Representation
Representation. Native 3DGS provides a renderable collection of Gaussians  ( Kerbl et al., 2023 ) , but not the object-level structure needed for task planning, interaction, and state memory. So we introduce the Interactive Scene Package (ISP), a unified structure with persistent object identities. Each object has visual assets, local collision geometry, semantic labels, a world transformation, and physical properties. The scene also maintains a static background, support regions, object relationships, and navigable space. Rendering and interaction use separate representations aligned by shared object transformations. Gaussian assets provide appearance, while geometric proxies support collision checking and path planning:
W = { V , B , ( id i , G i , T i , A i , S i ) i = 1 N , M , R } . W=\left\{V,B,(\mathrm{id}_{i},G_{i},T_{i},A_{i},S_{i})_{i=1}^{N},M,R\right\}.
(1)
Here, V V denotes visual assets, B B scene geometry, id i \mathrm{id}_{i} a unique identifier for each object, G i G_{i} local object geometry, and T i ∈ SE ⁡ ( 3 ) T_{i}\in\mathrm{SE}(3) world transformations. A i A_{i} contains manipulability and physical properties such as mass, S i S_{i} denotes object-local support regions, M M navigation occupancy, and R R object and spatial relationships. Movable objects are separated from the static background, with T i T_{i} applied consistently to their visual, collision, and semantic geometry.
Scene Update. Following object pose changes, the ISP updates support regions and navigation occupancy to condition later tasks. Support regions use object-local coordinates, moving or reorienting a chair recomputes its seat’s world coordinates through T i T_{i} , enabling subsequent sitting without manually reannotating the support surface. Navigation occupancy separates static-background and object-instance layers. Old object occupancy is removed and geometry inserted at the new pose, so path planning uses the updated obstacles.
The ISP underlies subsequent generation and exposes interpretable task conditions, object movability, the supporting object associated with a target region, and whether a location can be approached are all queryable before motion generation. Details on constructing the ISP are provided in Appendix   A.1 .

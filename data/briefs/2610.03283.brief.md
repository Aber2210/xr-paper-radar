Abstract The ability of a device to localize itself within its surroundings is a fundamental prerequisite for spatial computing. Visual-inertial odometry (VIO) has proven to be a cost-effective and accurate solution for this task. Robots, wearables, XR devices, and drones can benefit significantly from efficient implementations of VIO since they allow for cooler, lighter, and cheaper devices with longer battery life and a better user experience. In this work, we propose to enhance the efficiency of a VIO system by leveraging the Hexagon DSP, a commodity co-processor present in many modern smartphones and XR devices. Our approach offloads the visual frontend of a stereo-inertial odometry system to the DSP while keeping the backend on the main CPU. By optimizing the implementation for the DSP architecture, we achieve significant reductions in power consumption and latency compared to CPU-only execution. The scalar core, HVX vector unit and HMX matrix unit share one memory hierarchy. Each hardware thread has its own scalar registers (GRF, predicates P0–P3); each vector context has its own vector registers (VRF, predicates Q0–Q3) and the six functional units that operate on them. The gather instruction, the basis of sparse feature sampling, addresses VTCM only. Computation units The Hexagon V73 compute DSP (cDSP) comprises a scalar core and two coprocessors (Fig. 2 ): HVX (Hexagon Vector eXtensions) for wide SIMD on 1024-bit registers, which we use, and HMX for matrix operations. Every vector instruction occupies one of the four VLIW slots in a thread’s instruction packet, so scalar and vector instructions issue together, subject to the available vector functional units. The six hardware threads attach dynamically to the four vector contexts, and peak vector throughput requires all four active. Memory subsystem The CPU invokes code on the DSP through FastRPC, a remote-procedure-call layer [ 42 ] . We allocate every buffer that crosses the boundary as shared memory, which FastRPC maps into the DSP’s address space instead of copying it. On the DSP side, HVX bypasses the scalar core’s L1 and reads from L2 or from VTCM (vector tightly coupled memory), an 8 MB scratchpad under software control. Alongside ordinary loads and stores, DMA can move bulk data from DDR into VTCM. The vector gather instruction can only address VTCM [ 43 , Sec. 3.3] , so anything sampled at non-contiguous memory addresses must be resident there rather than merely cached.

## 四、全文抓取与障碍/限流处理要点（提炼，回应"尤其是…如何解决"）

将 skill §6 浓缩为可直接照做的清单，供后续运行快速遵循：

1. **执行前必探针**：API（export）最简查询 200 → 用 `fetch_arxiv.py`；406/超时 → 立即转 `fetch_rss.py`。两源连续 3 次 404/406/超时 → 推迟到下一周期重跑（断点续拉不重复计费）。
2. **降级链路（任一级成功即停）**：`L0 arXiv HTML → L1 ar5iv → L2 PDF(需 pdfminer) → L3 OpenReview → L4 Semantic Scholar → L5 摘要降级`。
3. **限流退避公式**：`wait(n)=min(60, 3·2ⁿ)` 秒（n=重试次数）；每请求间隔 ≥3s；单批 ≤1 req/s；**强制串行**（禁并发线程池，防封 IP）。
4. **406 内容协商**：arXiv HTML 常返 406，脚本按 5 次退避重试 + 版本号 `v2→v1→无版本` 试探，最终多命中 L0（今日实测）。
5. **全文缺失**：全部失败则 `L5` 摘要降级，章节顶部显式声明 `evidence=ABSTRACT_ONLY`，**严禁脑补数值/方法细节**。
6. **跑完必核**：`WROTE=N>0`（防命名空间 bug 静默 0 条）；`_manifest.json` 中 Top 候选 `level∈{L0,L1}`、`evidence∈{FULL,PARTIAL}`。
7. **沙箱盘满风险**：C: 盘曾 0 字节致任务失败；跑前查 `shutil.disk_usage`，必要时清 `AppData/Local/Temp`（今日 C: 余 18.9 GB，健康）。

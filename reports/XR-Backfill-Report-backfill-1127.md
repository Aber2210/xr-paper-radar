### 1. GazeVLM：以注视引导中央凹式推理的高效视觉语言模型（2509.16476 · 交互与输入 · 3.55 B）

**一句话结论**：把实测注视投影成注意图、按 gaze mass 取最小前缀包围盒做中央凹裁剪，training-free 地给 VLM 分配算力——Qwen2.5-VL-3B 匹配率 73.54→82.03%、视觉 token 15.55k→2.46k（−84.2%）、延迟 3.20→0.45 s（7.1×）；Qwen3-VL-8B 80.78→83.70%、11.6×。

**要解决的问题**

VLM 把高分辨率图像编码成上千个视觉 token，prefill 成为主要延迟来源：Qwen2.5-VL-3B 在 4032×3024 输入上产生 15.55k 视觉 token、106.5 TFLOPs、单帧 3.20 s（A100），而任务真正相关的往往只是视野中很小一块。AR/VR 设备已普遍集成眼动模块，却没人把实测注视当作推理期的算力分配信号；现有 token 剪枝、稀疏注意力与额外控制模块都带精度-效率折衷，还需要训练。作者同时指出缺少「真实佩戴式眼动 + VQA」的评测集：已有 gaze-VQA 数据多来自实验室或既有图像库，而非真实传感链路。

**方法详解**

GazeVLM 是 training-free、plug-and-play 的两段式流程。第一步把原始 gaze trace 投影到图像平面并用高斯核平滑成注意图 $G\in[0,1]^{H\times W}$，$\sum_{x,y}G(x,y)=1$；第二步按 gaze mass 降序排列像素 $\pi_1,\ldots,\pi_{HW}$，取最小前缀使累计质量达到 $\rho$：$k^\star=\min\{k:\sum_{j=1}^{k}G(\pi_j)\ge\rho\}$，该集合的轴对齐包围盒 $B=(x_0,y_0,x_1,y_1)$ 给出 ROI 裁剪 $I_r=I[B]$。可选 Gaze-2SCALE 分支把原图降采样为全局视图 $I_g$（模拟周边视觉），与 $I_r$（模拟中央凹）一起过同一编码器，再与文本查询拼接 $X=\mathcal{P}(\{I_g,I_r\},T)$。两种模式都不修改 VLM 权重、不训练任何模块，唯一超参是保留的 gaze mass 比例 $\rho$：主表取 0.5，VOILA-COCO 交叉验证取 0.3，敏感性实验扫 0.05–0.60。裁剪后 ROI 以原始分辨率送入编码器，因此同一 token 预算下 ROI 的像素密度远高于整图降采样。

**实验与结果**

- Qwen2.5-VL-3B：答案匹配率 73.54%→82.03%，视觉 token 15.55k→2.46k（−84.2%），prefill FLOPs 106.5T→7.7T，延迟 3.20 s→0.45 s（7.1×）（GazeVLM-VQA，ρ=0.5）
- Qwen2.5-VL-7B：75.63%→78.69%（Gaze-ROI）/77.99%（Gaze-2SCALE），延迟 3.76 s→0.54 s（7.0×）
- Qwen3-VL-8B：80.78%→83.70%，视觉 token 11.84k→1.88k，FLOPs 156.1T→14.7T，延迟 3.60 s→0.31 s（11.6×）
- VOILA-COCO（ρ=0.3，Qwen2.5-VL-3B）：GPT-4o 评分 3.98→4.45（ROI）/4.51（2SCALE），视觉 token 64→15.6
- 同预算对比：Gaze-ROI 比 DOWNSAMPLE 高 15.32/9.19/8.49 pp（3B/7B/8B）
- ρ 敏感性：0.05→0.30 时 3B 从 44.6% 升到 74.8%，ρ=0.30 时 FLOPs 仍比整图低 96.6%
- 数据集规模：268 张 4032×3024 参考图、718 个 QA、12 类场景，5 类问题（空间推理 31.75%、属性 23.82%、OCR 22.84%、存在性 15.18%、语义 6.41%）

**创新点**

- 相对 token 剪枝/稀疏注意力这类在模型内部改算子的路线，GazeVLM 把人体生理信号放到输入端：用实测注视决定裁剪哪块、给多少像素密度，完全不动模型权重
- 相对 VOILA 这类把注视当训练监督的工作，它把 gaze 用在推理期的算力分配上，并配套第一个真实佩戴式眼动的 VQA 基准
- Gaze-2SCALE 把中央凹/周边视觉的两尺度结构显式做进输入拼接，是相对单 ROI 裁剪的架构性补充

**局限与风险**

- GazeVLM-VQA 只有 268 张图、718 个 QA，且由单一被试佩戴 Pupil Labs Neon 采集（正文用单数 the participant），跨被试、跨设备泛化未测
- 准确率用 normalized exact-match，对开放式回答偏严
- 表 II 中 Gaze-2SCALE 的视觉 token 数与 Gaze-ROI 完全相同（2.46k / 1.88k），与「再加一张全局图」的叙述不一致，作者仅以「额外开销至多 0.01 s」解释，缺少 token 账目
- 方法强依赖眼动标定质量，注视漂移或眨眼噪声会直接放大/缩小 ROI，论文未给噪声鲁棒性实验

**可复现性**

- 代码/项目页：未提及代码；声明 public release GazeVLM-VQA 数据集，但正文未给链接或 DOI
- 全文证据：FULL（L0，23,717 字符）

### 2. HPC：面向流式动态高斯泼溅压缩的层次化点式隐表示（2602.00671 · 神经渲染 · 4.22 A）

**一句话结论**：在最新解码的高斯上建层次化点式 latent（3 尺度、每尺度 16 通道），配网络参数压缩做流式动态 3DGS 编码——N3DV 32.36 dB / 39 KB 每帧（iFVC-h 32.35 / 99 KB、4DGC 31.58 / 500 KB、3DGStream 31.69 / 7780 KB），BD-BR 相对 iFVC 平均 −67.8%。

**要解决的问题**

流式自由视点视频要求逐帧传动态 3DGS，但码率仍高到无法实用：N3DV 上 3DGStream 需 7780 KB/帧、4DGC 500 KB/帧、iFVC 63–99 KB/帧、QUEEN 680–750 KB/帧，按 30 FPS 播放对应数十到数百 Mbps。现有 latent 表示分两派：结构化网格（hash-grid、tri-plane）为未占据空间付参数代价，只能降分辨率或容忍哈希冲突；点式（QUEEN）把 latent 贴到每个高斯上避免空洞浪费，却按孤立点建模、忽略邻域相关，且只有单一尺度，对非均匀分布的高斯欠拟合。另一个被忽视的问题是所有在线方法都把逐帧网络参数按 32-bit 浮点原样传输，既浪费码率又让 latent 与网络的位率分配失衡。

**方法详解**

HPC 以最新解码的 Neural Gaussian $\mathcal{NG}_{t-1}$ 为参考，先建层次化点式 latent：从最细尺度 $X^0_{t-1}=X_{t-1}$ 出发，用网格采样递归下采样 $X^{r}_{t-1}=\lfloor X^{r-1}_{t-1}/\epsilon^{r}+0.5\rfloor\cdot\epsilon^{r}$（$L=3$ 尺度，相邻尺度点数比 0.2，每尺度 16 通道），每个位置挂一个可学习 embedding $E^r_t$，解码后与固定位置组成 $Z^r_t=(X^r_{t-1},\hat{E}^r_t)$。紧凑化靠两级聚合：Inner-scale Latent Aggregation（ILA）对每个点做 $k=4$ 的 kNN，用相对位置过 MLP 预测逐邻居权重并 softmax 归一，加权融合邻居 embedding 后再过 MLP，各尺度共享参数、kNN 每帧只建一次；Cross-scale Latent Aggregation（CLA）从粗到细把粗尺度 embedding 复制上采样并与细尺度原生 latent 拼接递归融合。聚合后的 latent 进预测头输出形变参数：特征残差 $\Delta F_t$、锚点平移 $T^X_t$、全局旋转 $R^X_t$、偏移残差 $\Delta o_t$，按 $F_t=F_{t-1}+\Delta F_t$、$X_t=X_{t-1}+T^X_t$、$o_t=R^X_t(o_{t-1}+\Delta o_t)$ 更新，尺度因子 $l$ 保持不变。压缩端对 latent 用 STE 做失真前向、加 $\mathcal{U}(-1/2,1/2)$ 噪声做可微熵估计，配 factorized 熵模型与算术编码，每帧传一对全局 min/max。网络参数端引入 GOP 结构（$T_{GOP}=5$）抑制误差传播：I-frame 对每个参数张量独立做 8-bit 量化并用以高斯分布参数化的 network-free 熵模型；P-frame 用逐层可学习缩放 $\eta_t$ 加逐参数残差 $\Delta P_t$，联合量化区间避免裁剪，重建为 $\hat{P}_t=\eta_t\hat{P}_{t-1}+\Delta \hat{P}_t$。总目标 $\mathcal{L}=\mathcal{L}_D+\lambda\mathcal{L}_R$，$\mathcal{L}_D$ 为 $\mathcal{L}_1+\lambda_{SSIM}\mathcal{L}_{SSIM}$，$\lambda\in\{0.048,0.032,0.016,0.002\}$ 给四个 RD 工作点，后续帧每帧训练 500 次迭代。

**实验与结果**

- N3DV：HPC-h PSNR 32.36 dB / SSIM 0.955 / 39 KB 每帧，对比 iFVC-h 32.35 dB / 0.953 / 99 KB、4DGC 31.58 dB / 0.943 / 500 KB、3DGStream 31.69 dB / 0.948 / 7780 KB
- N3DV：HPC-l 31.91 dB / 23 KB 每帧，为在线方法中最低存储
- BD-BR（对 iFVC）：N3DV −64.9%、Meet Room −70.7%、平均 −67.8%；关闭网络参数压缩（w/o NNC）时平均 −28.0%
- Meet Room：HPC-h 32.57 dB / SSIM 0.961 / 28 KB，HPC-l 31.71 dB / SSIM 0.957 / 18 KB
- 消融（相对完整模型码率增幅）：w/o NNC +131.5%、w/o ILA +22.3%、w/o CLA +26.3%（N3DV/MeetRoom 平均）
- latent 表示对比（N3DV，tri-plane 为锚点）：hash-grid −6.7%、层次化点 −21.8% BD-BR
- 网络量化位深（Meet Room 最高码率点）：32-bit 32.62 dB / 59 KB，8-bit 32.57 dB / 26 KB（latent 16 KB + 网络 10 KB），4-bit 训练发散至 7.31 dB
- 时序编码：参数相关 0.78，经验熵 6.06→4.45 bits/参数（−26.54%）；GOP=5 时量化误差间隙 0.067→0.125 dB，GOP=20 增量间隙 1.899 dB
- 复杂度（RTX 3090，两数据集均值）：总编码 60.94 s/帧、解码 0.22 s/帧、渲染 140 FPS

**创新点**

- 相对网格类 latent（iFVC 的 binary tri-plane、3DGStream 的 hash-grid），HPC 把 latent 完全建在高斯位置上，不给空空间付参数，再用 ILA/CLA 把「点式表示缺局部相关」这个已知短板补上，算是把点式与网格式的优点做了结构级合并
- 相对 QUEEN 这类同为点式的方法，多了多尺度感受野与邻域/跨尺度聚合
- 最关键的新意在于把逐帧网络参数也纳入端到端码率优化：这是流式动态 GS 压缩里此前被显式跳过的一项，配上 GOP 与时序残差编码，让 latent 与网络两侧位率可以联合分配

**局限与风险**

- 编码端仍远非实时：总编码 60.94 s/帧（训练 60.61 s），比 iFVC 的 10.32 s/帧慢约 6 倍，只适合离线或近线打包，与「流式传输」的实时编码需求有落差
- 评测只用两个室内多相机数据集，缺少大尺度室外与长序列
- 重建保真度被作者承认强烈依赖初始帧（HAC）质量，跨数据集比较时初始帧不一致会污染结论
- GOP 固定为 5，作者自己指出内容自适应 GOP 留作未来工作
- P-frame 递归预测的误差传播只在小 GOP 下被压住

**可复现性**

- 代码/项目页：已开源 github.com/USTC-iVC-3D-Group/HPC（正文给出链接）
- 全文证据：FULL（L0，84,036 字符）
- 首发提交日 2026-01-31（本批为 `replace` 再公告）


### 3. 3DSS：用于逆渲染的三维表面泼溅（2605.05876 · 神经渲染 · 3.85 A）

**一句话结论**：用无结构 oriented surfel（切向量编码朝向、刻意不设可学习不透明度）+ T-matrix 光栅化做逆渲染，绕开网格拓扑与体渲染的 alpha 混合语义——Stanford-ORB 新视角 PSNR-H 31.73 / PSNR-L 40.73（RTR-GS 30.10 / 39.17、NVDiffRec 21.94 / 28.44），重打光 23.22 / 30.44。

**要解决的问题**

从多视角图像联合恢复形状、SVBRDF 与光照的可微逆渲染被两类表示夹住。mesh/DMTet 路线（NVDiffRec）受固定拓扑与网格分辨率限制：512×512 训练约 1 小时、1024×1024 近 2 小时，加密四面体网格会迅速放大顶点自由度并引入退化三角形、自交与断裂连通性。体渲染路线（NeRF、3DGS 系）把法线、材质按 alpha 混合，对单位方向量语义不清，混合出的材质也不对应任何真实表面。经典 EWA surface splatting 天然是表面采样，却几乎都是单层：每像素只重建最前表面，可见性不连续处无法正确抗锯齿，轮廓处也给不出可用梯度，因此此前只用于形状拟合/去噪，未被用于基于物理的逆渲染。

**方法详解**

3DSS 用无结构 oriented surfel 集合表示场景，每个 surfel 携带中心 $\mathbf{c}$、两个切向量 $\mathbf{t}_u,\mathbf{t}_v$（编码朝向与各向异性缩放，法线 $\mathbf{n}=\mathbf{t}_u\times\mathbf{t}_v/\|\mathbf{t}_u\times\mathbf{t}_v\|$）、albedo $\boldsymbol{\rho}$、metallic $m$、roughness $r$，刻意不设可学习不透明度。光栅化用 Weyrich 的 T-matrix：$\mathbf{T}=\mathbf{PS}$ 把局部单位球映到 clip space，包围盒、深度跨度 $\varepsilon_z=\sqrt{\mathbf{t}^{\prime 2}_{u,z}+\mathbf{t}^{\prime 2}_{v,z}}\cdot r_{cut}$、射线求交都化成 T 矩阵行上的代数运算；每像素视线与 surfel 平面求交得局部坐标 $(u,v)$，$\rho^2=u^2+v^2$，超出 $r_{cut}$ 丢弃，核权重 $w=\exp(-\tfrac{1}{2}\rho^2)$（省略 $1/2\pi$ 归一化，交给 Shepard 归一）。表面分离改为区间合并：每个 surfel 带深度区间 $[z_{start},z_{end}]$，按 $z_{start}$ 基数排序后把重叠区间并成任意多层，单趟光栅化即可支持每像素多个表面层。合成不用 learnable opacity，而是由层内累计 EWA 权重导出覆盖率 $\alpha$，再按 over 算子从前往后合成，因此轮廓抗锯齿与稀疏覆盖边缘的可见性梯度都来自重建核本身。抗锯齿用 object-space MIP 滤波（AA-2DGS 的切平面 Jacobian 方案），并提出 center-precomputed 近似，把逐像素 Jacobian 摊销掉。着色是 forward shading：先对每个 surfel 做 split-sum IBL 与各向同性 GGX 微表面求值，再进光栅化，避免在混合后反推材质与法线。自适应密度控制用 density-aware splitting（比较 surfel 尺度与局部采样间距，而非固定场景比例）与来自 T 矩阵反向的屏幕空间绝对梯度累积（避免 2DGS 投影梯度在大面片上互相抵消）。损失为 $\mathcal{L}_1+\lambda_{SSIM}\mathcal{L}_{SSIM}$ 加深度凝聚正则、kNN 法线一致性正则与轮廓 IoU 正则；网格导出走 Screened Poisson（octree 11）。

**实验与结果**

- Stanford-ORB 新视角合成：PSNR-H 31.73 dB / PSNR-L 40.73 dB / SSIM 0.991 / LPIPS 0.010，对比 RTR-GS 30.10 / 39.17 / 0.985 / 0.021、NVDiffRec 21.94 / 28.44 / 0.969 / 0.030
- 新光照重打光：PSNR-H 23.22 dB / PSNR-L 30.44 dB / SSIM 0.974 / LPIPS 0.025，对比 NVDiffRec 22.91 / 29.72 / 0.963 / 0.039、InvRender 23.76 / 30.83 / 0.970 / 0.046
- 几何：Depth SI-MSE 0.31、Normal cosine 0.06、Chamfer 0.43（×10⁻³），对比 NVDiffRec 0.31 / 0.06 / 0.62
- 训练成本（RTX A6000，512×512，30k 迭代）：约 20 分钟，NVDiffRec 约 1 小时；1024×1024 为约 30 分钟 vs 近 2 小时
- 光栅化吞吐：512×512 / 50K surfels 约 900 fps，2048×2048 / 2M surfels 仍达 100 fps，均高于 60 fps 交互阈值
- 固定几何验证（1M surfels，仅学材质与光照）：Depth 0.06、Normal 0.00、Chamfer 0.01，NVS PSNR-L 37.49 / SSIM 0.988
- 消融（7 个 object–scene 对，约 100K surfels）：无 densification 重打光 PSNR-H 23.56 vs 完整 24.32；全局尺度阈值 23.58；投影 3D 梯度 23.97

**创新点**

- 相对 DSS（Yifan et al.）把可见性不连续处理在单个 primitives 层面、并用 $O(K)$ 的可见性翻转近似梯度，3DSS 把不连续处理在重建表面层层面，用层内累计 EWA 权重直接导出覆盖率，从而在稀疏覆盖边缘拿到有信息的梯度
- 相对 2DGS/mesh 光栅器，它换掉渲染模型而非几何原语：surfel 没有可学习不透明度，像素覆盖由重建核集体决定，合成走 over 而非 alpha 混合，使法线与材质在混合前就被求值
- 区间合并式多层分离替代经典 extended z-buffering 的二/三元深度测试，是这套渲染模型的使能件

**局限与风险**

- 作者自述三点：split-sum IBL 加各向同性 GGX 只有单次反弹、无互反射/投影阴影/接触暗化/焦散，也不处理掠射角 Fresnel
- 简化着色会把光照误差烘进几何（点云无连通性，只靠两条软正则约束），弱光证据区可能出现局部不连续
- 区间分组的表面判定是几何代理，退化构型会误分层
- 实验侧只有 Stanford-ORB 一个基准（7 对做消融），真实场景与户外大尺度未测
- 固定几何实验用 1M surfels 而完整优化约 100K，两者差距部分来自采样密度而非方法本身，作者也承认这一点

**可复现性**

- 代码/项目页：未提及

### 4. ArtMesh：带运动一致动力学的部件感知铰接网格场（2605.16582 · 重建与SLAM · 4.15 A）

**一句话结论**：用部件感知三角网格场 + 运动一致动力学，从两个关节状态重建铰接物体并直接给出带部件边界的网格——Articulate-100（给 GT 掩码）轴角 3.49°、CD-m 15.01 mm（最强基线 57.45 / 58.66，改善 +42.44 mm），6+ 部件档轴角 6.90°（GaussianArt 33.05°）。

**要解决的问题**

从图像重建铰接物体要同时给出部件级几何、各活动件的关节运动，以及下游可直接消费的显式表面资产。隐式路线（PARIS 等）渲染好，但优化的是体场，网格只能事后等值面提取，关节处边界与拓扑被抹平。3DGS 路线（ArtGS、GaussianArt、ReArtGS++）继承无结构点式几何，没有三角形连通性也没有显式部件边界，只能靠 TSDF 融合补网格，关节处一个跨越抽屉缝的错误连接会同时毁掉几何与运动估计；其监督也弱：图像损失只间接约束关节轴，2D 特征匹配、canonical 高斯匹配在弱纹理家具上不可靠。评测侧同样缺位：多数铰接基准只有两个部件（如 PARIS），部件数一多，拓扑、部件分离与运动一致性才真正吃紧的区间没人测。

**方法详解**

ArtMesh 用两个关节状态 $t_1,t_2$ 的多视角 RGB-D 重建一对部件感知三角网格加每部件刚体运动。网格场 $\mathcal{M}(t)=(V(t),F(t))$ 的每个顶点存位置 $x_i$、SH 颜色 $c_i$、不透明度 $\sigma_i$ 与 $K+1$ 类部件 logits $s_i$（1 个静态基座 + $K$ 个活动件），$w_i=\mathrm{softmax}(s_i)$ 在重建后期硬化为 $p_i=\arg\max_k w_{i,k}$，据此把顶点分成 $V_k(t)$。关键一步是 part-aware restricted Delaunay remeshing：先丢弃顶点跨部件的面 $F_k(t)=\{f=(i,j,l):p_i=p_j=p_l=k\}$，再在每个部件内部独立跑 rDel，$F^\star_k(t)=\mathrm{rDel}(V_k(t),F_k(t))$，最终拓扑取并集，于是每个活动件是一块连通子网格、没有任何跨部件三角形，刚体变换不会剪切拓扑。关节场给每个部件前向刚体 $(R^+_k,P^+_k,T^+_k)$，$g^+_k(x)=R^+_k(x-P^+_k)+P^+_k+T^+_k$；反向运动不做独立学习，取解析逆 $g^-_k(y)=(R^+_k)^\top(y-b^+_k)$，保证双向自洽（revolute 时 $T^+=0$，prismatic 时 $R^+=I$）。监督是双向运动一致性：vertex-wise 项把顶点按所属部件搬运到另一状态，只在同部件子网格 $F^\star_{p_i}(t_2)$ 内找最近三角形，用重心坐标插值目标位置/颜色/不透明度并回归（含有效性掩码 $\eta_i$）；pixel-wise 项把搬运后的网格从目标状态相机渲染，与真实图像做 $\mathcal{L}_1$+SSIM。总目标 $\mathcal{L}_{motion}=\lambda_{VMC}(\mathcal{L}^{1\to2}_{vtx}+\mathcal{L}^{2\to1}_{vtx})+\lambda_{PMC}(\mathcal{L}^{1\to2}_{pix}+\mathcal{L}^{2\to1}_{pix})$。训练分两阶段：先优化顶点位置/辐射/不透明度/部件 logits，硬化后做 per-part rDel，再短训一轮固定拓扑精修；关节阶段冻结几何，只优化刚体参数，用 RGB 与 vertex-wise 一致性监督。部件掩码缺失时用作者微调的 PArtSAM（基于 PartSAM，加入跨状态位移与可动性两通道，零初始化首层）预测。

**实验与结果**

- Articulate-100（给 GT 部件掩码）：Axis Ang 3.49°、Axis Pos 0.03（0.1 m）、Part Motion 3.64、CD-s 18.98 mm、CD-m 15.01 mm，五项聚合全部最优
- CD-m 相对最强基线改善 +42.44 mm（15.01 vs 57.45/58.66 mm），2/3/4-5/6+ 部件分桶增益分别 +19.27/+29.57/+35.23/+27.69 mm
- 多部件退化：6+ 部件桶 Axis Ang 6.90°，对比 GaussianArt 33.05°、ArtGS 14.37°、ReArtGS++ 22.02°
- 无 GT 掩码（Ours-PArtSAM）：Axis Ang 12.26°、CD-m 60.69 mm，2 部件仍与 GT 掩码档持平
- PARIS 合成集：Axis Ang 0.68°、Axis Pos 0.02、Part Motion 0.54、CD-s 19.59 mm、CD-m 12.44 mm；真实集 2.37° / 0.07 / 0.66 / 27.25 / 50.84
- 消融（Articulate-100）：去反向传播最伤，Axis Ang 3.49→10.79°、CD-m 15.01→29.06 mm；去顶点颜色一致性 6.02°、去顶点不透明度一致性 6.87°、用全局 Delaunay 7.10°
- 网格质量：自穿透深度 SPD 0.0224（占包围盒对角线比例），Gaussian 类基线无直接网格（N/A，需 TSDF 提取）

**创新点**

- 相对 ArtGS/GaussianArt 这类在无结构高斯上做铰接的工作，ArtMesh 把几何、拓扑与关节绑成互相约束的一体：per-part rDel 让每个活动件成为真正连通、无跨部件面的刚体网格，训练用的表面就是导出用的表面，不需要事后 TSDF
- 相对 PARIS 这类隐式路线，关节直接在三角网格顶点与渲染像素两个层面被监督，反向运动取解析逆而非另学一张网络
- 相对最接近的 StructureGS（加部件有向包围盒与接触约束），它给出的是可导出的连通拓扑而非结构化先验
- 附带贡献是 Articulate-100：100 个物体、16 类、部件数从 2 到 6+，把「多部件才吃紧」的区间显式测出来

**局限与风险**

- 输入被限定为两个离散关节状态，连续关节角度、多状态序列与运动轨迹都未覆盖，prismatic/revolute 之外的关节类型（如螺旋、球窝复合）未处理
- 部件数 $K$ 需预先给定，主要数字依赖 GT 部件掩码
- 用 PArtSAM 时 3–5 部件桶的 Axis Ang 反超 ArtGS（19.79° vs 15.42°），说明分割噪声会直接污染运动估计

- 每个物体都要跑两阶段优化，不是前馈推理

### 5. 基于多 GPU PyTorch 后端的大规模高斯泼溅（2606.11390 · 系统与平台 · 4.00 A）

**一句话结论**：把多卡拼成统一虚拟地址空间（kDGX dispatch + stream-ordered 异步 UM 分配器），让分布发生在算子内部而非切模型——Gettysburg 268M splats / 153 张 7088×5314 / 13 km² / 8×A100 用 3.086 h 达 PSNR 27.450，十亿级 splats 超 Grendel-GS 最大规模 25 倍，$B=N$ 平均加速 3.15×。

**要解决的问题**

3DGS 的重建规模与分辨率被单卡显存卡死：高分辨率航拍或多相机阵列下，参数量与每视角投影参数很快超过一张 A100。现有多卡方案各有代价：gsplat 里的 Grendel-GS 只分发 3D 高斯参数，每个视角的投影参数必须整块留在一张卡上，在 8×A100、最小支持 batch $B=8$ 时只要 132M 高斯就 OOM；域分解（分块重建再缝）引入与 GPU 数成正比的边界开销；DTensor 这类通用方案要求事先显式声明每个张量的 sharding 与复制，改造成本高。结果是「十亿级高斯 + 街景细节」这类重建在公开系统上做不到。

**方法详解**

torch-dgx 是一个多 GPU PyTorch 后端：注册新的 dispatch key kDGX 与设备名 dgx，用 CUDA unified memory 把多卡拼成统一虚拟地址空间（可选 NVLink 做高吞吐 all-to-all），因此 device=dgx 的张量可被任意卡寻址，算子自动派发到多卡实现。为避免 host 同步开销，作者实现了 stream-ordered 的完全异步 unified-memory 分配器，分配与执行都不阻塞主机。分布发生在算子内部、沿各算子天然的并行轴：有的按张量元素切、有的按行切，且可依运行期输入变化，模型代码因此不需要任何显式通信或 sharding 注解；反向传播或用专用多卡 kernel，或经 PyTorch autograd 分解。落到 GS：球谐求值与投影按高斯切分，每卡处理一个不相交的高斯区间并对所有相机求值，反向用卡内 atomic 累加各相机的梯度贡献；高斯-瓦片求交、深度排序、光栅化按全宽 tile 行切分输出像素，统一内存让本卡能读到别的卡上的投影高斯；一个投影高斯可能命中多卡 tile，于是各卡先在本地梯度缓冲（stacked grids）累加，再走 reduce-scatter 汇总并回送给高斯所属卡，避免系统级 atomic。前向与反向保持同一划分以复用数据驻留；图像损失按光栅化的 tile 归属计算。与 gsplat 的关键差别是支持 $B$ 与 $N$ 独立：既不是单视角铺满所有卡（$B=1$），也不强制一卡一视角（$B=N$），因此单个视角也能用上聚合显存。

**实验与结果**

- 十亿级压力测试：城市尺度重建超过 1 billion splats，是 Grendel-GS 已报告最大规模（40M）的 25 倍以上
- Gettysburg：268M splats、153 张 7088×5314 航拍、13 平方公里，8×A100、$B=1$、400 epochs、3.086 h，PSNR 27.450 dB / SSIM 0.8734
- 对照：gsplat 的 Grendel-GS 在 8×A100、$B=8$ 下 132M 高斯即 OOM
- $B=N$ 平均加速（相对各自单卡）：2/4/8 卡为 1.68×/2.50×/3.15×，峰值 3.60×；gsplat 为 1.77×/3.33×/6.30×，峰值 7.30×
- $B=1$ 平均加速：2/4/8 卡为 1.44×/1.85×/2.18×
- 单卡上 dgx 后端相对 PyTorch 原生 CUDA 后端的平均速度为 98.5%，PSNR/SSIM/高斯数基本一致
- batch 从 1 增到 8 使七场景平均 PSNR 降 0.051 dB、SSIM 降 0.0001（room 场景 gsplat 从 31.463 dB 掉到 29.671 dB）
- Morton 排序带来 5–10% 性能提升

**创新点**

- 相对数据并行/张量并行/流水并行这类与模型强耦合的方案，torch-dgx 把分布下沉到算子：模型代码只改一个 device 参数，不动通信与 sharding，这是系统抽象层面的新做法
- 相对 Grendel-GS 的逐高斯逐像素并行，它的关键差别是把「每视角投影参数」也分布出去，因此单视角可用聚合显存，容量上限从 132M 推到 1B 以上
- 相对 unified-memory 溢写到主存的方案（借助 host 内存扩容），它是聚合多卡显存与算力、把主机内存参与降到最低

**局限与风险**

- 加速比明显不如 gsplat 的 $B=N$ 路线（8 卡 3.15× vs 6.30×），作者自己也承认小规模/多卡时并行度不足
- 真正的卖点是容量而非吞吐
- 统一内存的页迁移与 reduce-scatter 让性能对张量规模、NVLink 拓扑敏感，只有在 NVLink 全互联的 A100/H100 上测过，PCIe 或跨节点未验证
- 十亿级重建按 8×A100→8×H100→4×B200 分段渐进训练，属于工程可行性演示而非可复现的单一配置
- 评测只有重建 PSNR/SSIM 与时间，缺少渲染端时延、多卡扩展效率曲线与故障恢复

**可复现性**

- 代码/项目页：已开源（正文声明 open-sourced torch-dgx 及其评测算子，未给仓库链接）
- 全文证据：FULL（L0，66,623 字符）

### 6. LightFuse：多扫描融合与二维高斯光线追踪的可重打光交互式场景重建（2608.29269 · 神经渲染 · 3.62 A）

**一句话结论**：把几何与 PBR 材质跨状态共享、状态间只差物体刚体变换与光照，用 2D 高斯 surfel + 光线追踪做多扫描融合——新状态重打光 PSNR 25.89 / SSIM 0.873（比最强基线 IRGS 高 6.01 dB），真实场景 24.35 dB（ReCap +1.55）但 SSIM 略低（0.821 vs 0.903）。

**要解决的问题**

交互式场景重建要从不同物体摆位的多次扫描中建出可编辑 3D 模型，使新布局能在新光照下渲染。现有 GS 路线（IGFuse、RecurGS、LTGS）把外观直接从图像优化进高斯，材质与光照纠缠在一起，导致两种失败：不同状态的外观被烘进同一份共享表示，产生光度不一致；新布局下烘死的阴影、高光与间接光跟着物体走，物理上不成立。逆渲染路线（IRGS、ReCap、GauUpdate）能做材质-光照分解，却假设所有拍摄共享同一份静态几何，无法关联「同一表面在不同状态、不同位置、不同光照下被观测」这件事。量化差距很明显：新状态重打光下 IGFuse 只有 14.88 dB、ReCap 15.39 dB、IRGS 19.88 dB。

**方法详解**

LightFuse 用 2D Gaussian surfel 表示共享背景 $\mathcal{B}$ 与 $M$ 个可动物体 $\mathcal{O}_o$，每个 surfel 存 $(\mu_i,\mathbf{q}_i,\mathbf{s}_i,\alpha_i,\mathbf{a}_i,m_i,r_i,\mathbf{f}_i)$：前三项是几何，后三项是 PBR 材质，$\mathbf{f}_i$ 只是逆渲染前的辅助 splatting 颜色。几何与材质跨所有状态共享，状态 $k$ 之间只差物体刚体变换 $\mathcal{T}_{k,o}$ 与环境图 $E_k$（$256\times128$ HDR），即 $\mathcal{S}_k=(\mathcal{B}\cup\bigcup_o\mathcal{T}_{k,o}(\mathcal{O}_o),E_k)$。第一阶段在参考状态用 RGB 加几何监督重建，用 SAM 3 掩码与 GaussianCut 分出背景与物体，把参考状态的物体位姿定为 canonical frame，再估其他状态的 $\mathcal{T}_{k,o}$。跨状态补全只借几何证据：把每个组件在每个状态的每个视角渲染出来，凡渲染深度落后观测深度超过 $\tau_D$ 的像素 $\mathcal{H}=\{p:\hat{D}(p)-D^*(p)>\tau_D\}$ 视为被遮挡，用观测深度与法线反投影成新 surfel、经 $\mathcal{T}^{-1}_{k,o}$ 回到 canonical frame，颜色先填 $\mathbf{f}_i$。第二阶段做面向光线追踪的几何优化：surfel 作为有限支撑的有向求交原语，有效不透明度 $\tilde{\alpha}_j=\alpha_j\exp(-\tfrac{1}{2}\|\boldsymbol{\xi}_j\|^2)$ 截断在 0.99，按平面交点深度排序后前向合成 $T_j=\prod_{\ell<j}(1-\tilde{\alpha}_\ell)$、$w_j=T_j\tilde{\alpha}_j$，同一套权重同时给出位置/深度/法线/材质的合成值，保证几何与材质对齐；再加覆盖率正则 $\mathcal{L}_\alpha$（补洞）与尺度正则 $\mathcal{L}_s$（限制 surfel 尺寸，避免补洞后虚假遮挡自由空间射线），然后用追踪器本身做 refinement。第三阶段固定几何，做多状态逆渲染：可微单次反弹路径追踪，每条路径一次 NEE 环境采样加一次 BSDF 续接并用 MIS 合并，至多一次二次命中加四次环境采样，共享材质与逐状态 $E_k$ 联合优化，spp 从 8 逐步升到 16（第 7500 迭代）与 32（第 12000 迭代），共 15000 次迭代、每次从一张图采 16384 像素。编辑时对目标刚体变换重跑追踪，阴影与互反射随新布局重算。

**实验与结果**

- 新状态重打光（4 个合成场景 × 11 张未见环境图）：PSNR 25.89 dB / SSIM 0.873，比最强基线 IRGS 高 6.01 dB 与 0.131 SSIM
- 同设定下 IGFuse 14.88 dB / 0.714、ReCap 15.39 dB / 0.713、IRGS 19.88 dB / 0.742
- 真实场景新状态合成（Captured 1/2）：PSNR 24.35 dB 最高，比 ReCap 高 1.55 dB，但 SSIM 0.821 低于 ReCap 的 0.903
- 几何消融（4 合成场景）：AO MAE 0.0434→0.0272（加跨状态补全），PSNR 23.28→24.21 dB；再加 $\mathcal{L}_s$ 到 25.51 dB，最后光线追踪 refinement 到 25.90 dB / SSIM 0.875，法线 MAE 降到 1.695°
- 逆渲染消融（固定几何）：去间接光 25.90→22.54 dB，去 MIS 降到 19.86 dB
- 采样策略：固定 32 spp 25.97 dB / 3.01 h，渐进 8→16→32 为 25.90 dB / 1.59 h，固定 8 spp 25.66 dB / 1.08 h
- 环境图规模 256×128，逆渲染 15000 迭代、每次 16384 像素，单卡 RTX 4090

**创新点**

- 相对 IGFuse/RecurGS 这类「融合但不分解」的交互式重建，LightFuse 把材质与光照从外观里拆出来，且共享材质、逐状态环境图，编辑后重算可见性与光传输
- 相对 IRGS/ReCap 这类逆渲染，它允许几何在不同扫描间被重排：同一份 surfel 材质被多个状态的不同光照共同约束，这既是补全几何的证据，也是缓解材质-光照歧义的约束
- 面向追踪的几何正则（覆盖 + 尺度）与 refinement 是针对「splatting 优化出的表面在追踪下漏光/虚遮挡」这一具体缺陷设计的

**局限与风险**

- 只有单次反弹，长路径全局光照、焦散、透射与镜面链都无法忠实恢复
- 追踪与优化仍昂贵（逆渲染 1.59 h），所谓 interactive 指的是可重排可编辑，不是实时帧率
- 几何分解依赖多视角掩码与 GaussianCut，分割错误会经冻结几何直接传到材质与光照，作者列为第一条局限
- 真实场景只有 2 个、且因真实光照无 GT 只评合成不评重打光
- 真实场景 SSIM 还低于 ReCap，作者归因于蒙特卡洛噪声与去噪模糊，但这意味着在解析着色基线面前感知质量并未全面占优

**可复现性**

- 代码/项目页：未给代码仓库，仅有项目主页 zhn202.github.io/LightFuse
- 全文证据：FULL（L0，49,972 字符）

### 7. EgoCaptioner：面向全面细粒度第一视角视频描述（2611.26380 · 感知与认知 · 3.72 A）

**一句话结论**：把第一视角描述拆成 video-level overview + 带起止时间的有序 steps 两层，并造 50,000 条 coarse-to-fine 训练样本——PhysCapBench 78.84（主干 51.24，+27.6，超过 Gemini 3.1 Pro 75.06），EgoTempo 38.40（21.60），EgoHome 步分割 PSJ 75.51（46.90）。

**要解决的问题**

第一视角视频的描述需要同时满足细节与时间定位，而现成 MLLM 常漏掉短暂动作、弄错顺序、误解佩戴者自身的运动（身体只部分可见，只能从场景变化反推行进方向，头部运动与身体运动不一致时会误导）。格式上也有硬缺口：密集段落说不清每个动作何时开始结束，带时间戳的描述又往往一句话概括一个事件。数字上差距很大：Qwen3.5-9B 主干在 PhysCapBench 只有 51.24，Gemini 3.8 Flash 为 82.77；EgoTempo 准确率 21.60，EgoHome 上 PSJ 仅 46.90。现有第一视角描述器还偏向手-物操作，导航与社交类活动覆盖不足。

**方法详解**

EgoCaptioner 把描述拆成两层：video-level overview 交代地点、环境、光线/时间/天气、佩戴者与其他参与者、相关物体及其相对位置、以及整体在做什么与目的；steps 则把视频切成互不重叠的事件，每个事件再切成有序 step 并给起止时间，关键瞬间写成 At [t] 加一句发生了什么。两层结构支撑三个任务：全视频描述、仅 overview、以及 event-conditioned（指令给事件名但不给时间，模型需先定位再描述）。数据侧用 coarse-to-fine 标注流水线造 50000 条训练样本，覆盖 8 个第一视角来源：结构阶段由 Gemini-3.1-Pro 写 overview、Seed2.1 pro 切事件边界与类型并给 step 提纲；细节阶段 Gemini 按事件类型的叙述侧重（manip / locomote / social / attend 四类各有强调项）把提纲扩成带时间戳的 step 与关键瞬间，事件裁剪窗口前后各留至多 1 s 上下文，超过 30 s 的视频按 30 s 分片、0.5 s 重叠后再合并时间线；最后 Seed2.1 pro 对完整视频复核动作、时间与事件间一致性并就地修正。有位姿/轨迹记录的片段按 MotionScript 转成离散 motion facts，作为独立于参考描述的额外事实。训练先做 SFT（全视频/overview/事件条件三类等比例混合，视频至多 120 s），再用 GRPO 强化：事实奖励是判官给出的精确率与召回率的 F1（含位姿派生的运动事实），时间奖励按时间 IoU 贪心匹配预测与参考 step，风格奖励惩罚被判为碎片化或冗余的 step，overview 则用内容奖励加格式奖励；另有格式与有效性检查。

**实验与结果**

- PhysCapBench Overall 78.84，主干 Qwen3.5-9B 为 51.24（+27.6），高于 Gemini 3.1 Pro 的 75.06，低于 Gemini 3.8 Flash 的 82.77
- EgoTempo 准确率 38.40（主干 21.60，+16.8 pp），Score 2.066
- EgoHome 步分割 PSJ 75.51，为主干 46.90 的 +28.6，开源模型中第一
- Minerva-Ego（caption-to-QA）Acc 18.57，主干 0.00，Gemini 3.1 Pro 4.29
- EgoMe-Overview：BLEU-4 4.03 / METEOR 20.40 / ROUGE-L 23.59；EgoMe-Steps：METEOR 12.26 / SODA-c 8.04 / SODA-d 56.38
- SFT 数据规模：10k 时 PSJ 67.79、25k 68.63、50k 71.63（SODA-d 42.20→53.25）
- 奖励消融：去事实奖励 PSJ 67.97、去时间奖励 66.81、去风格奖励 73.22，完整 75.51
- 标注流程对比（同数据量）：单遍标注 PSJ 62.89、EgoTempo 26.60、Minerva 7.14；coarse-to-fine 为 71.63 / 36.40 / 18.57

**创新点**

- 相对通用描述器（覆盖场景但不绑定佩戴者动作）与第一视角专用描述器（短叙述或只做手-物操作），它把「视频级 overview + 带起止时间的 step + At [t] 关键瞬间」定义成统一输出格式，并用三个任务把定位与描述绑在一起
- 相对单遍标注，coarse-to-fine 让事件结构先于细节确定，这是数据侧的主要新意
- 强化侧把事实、时间、风格三类奖励分开设计，其中位姿派生的运动事实是与参考描述独立的证据源，缓解了「用模型判模型」的循环

**局限与风险**

- 训练标注完全由 Gemini-3.1-Pro 与 Seed2.1 pro 生成、再由 Seed2.1 pro 复核，同族模型自审会继承系统性偏差
- 判官打分的奖励同样依赖模型评审，存在奖励黑客风险
- 评测里 caption-to-QA 用 Gemini 3.8 Flash 答题并判分，答案质量受该模型能力上限约束
- 五个基准中三个（EgoMe、EgoHome、PhysCapBench）为官方指标，另两个（Minerva-Ego、EgoTempo）是作者改造的协议，跨论文可比性有限
- 结论主要相对开源模型，仍落后 Gemini 3.8 Flash（82.77 vs 78.84）
- 训练视频限 120 s，长视频一致性未验证

### 8. G0.7：用长上下文扩展快速世界动作模型（2611.31822 · 世界模型与仿真 · 4.43 A）

**一句话结论**：把世界动作模型的长上下文做成预训练期的一等能力（可变长多 chunk 自回归 + chunk-causal attention），并用双专家把语言条件逐层注入共享的 vision/action expert——五个仿真基准均值 70.8（OpenWAM 43.9、π0.5 33.9），RMBench 86.2%（单帧基线 < 12%），LIBERO-Plus 92.5%，零样本真机抓放 48% / 54%。

**要解决的问题**

世界动作模型（WAM）把预训练视频生成器改造成机器人策略，但部署时有三处硬伤：每个控制步都要先生成未来帧，单个 16 步 action chunk 的 IDM 推理要 457 ms（BF16 eager，单卡 RTX 5090），闭环会被拖停；多数策略只看 1–2 帧最近观测，在部分可观测与长程任务上没有记忆；公开 WAM 预训练语料相对视觉多样性需求仍偏小。RMBench 这类依赖记忆的基准上，单帧基线成功率低于 12%，说明上下文长度而非模型容量是瓶颈。

**方法详解**

沿用双专家 WAM：language expert 在每一层对共享的 vision/action expert 做条件注入，后者在因果 video VAE latent、本体状态与 16 步 action chunk 上工作，action 与 video 的频率比为 4:1，用标准 video-action 联合 conditional flow matching 训练，并对干净历史 latent 施加 chunk-causal attention。长上下文：预训练即按多 chunk 序列自回归，序列长度 K 可变并按 rank 平衡 batch 以均衡算力，配合随机 positional chunk offset 让 RoPE 外推到更长 rollout；推理时用滑窗 KV cache 只存真实相机观测的干净 latent，窗口可扩到 5 分钟，无需额外 memory 模块。双模推理：teacher-forcing 阶段对每个样本做随机 attention mask（$p_{IDM}=0.5$），action token 要么看当前 chunk 的未来视频 latent（IDM 路径），要么只看历史与当前观测（Fast 路径），视频预测始终有监督；推理时 Fast 模式从缓存上下文用 5 步直接去噪 16 步 chunk，FP8 下单 chunk 60 ms，并可直接接 real-time chunking（RTC）在当前 chunk 执行时去噪下一块。数据：机器人遥操作（Galaxea R1 Pro/Lite、DROID、RoboMIND、BridgeData）加第一视角人类 ego 视频，遥操作按整段/子目标/原子动作三级语言标注并做运动质量过滤；人类视频用 3D 手部姿态提取，把手腕 6-DoF 位姿对齐到 R1 夹爪的 TCP 约定（+Z 沿手指）并加五个指尖 3D 位置，作为额外 embodiment 与机器人数据共享同一视频-动作目标。

**实验与结果**

- 五个公开仿真基准均值 70.8，OpenWAM 43.9、G0.5 39.2、π0.5 33.9
- RMBench 86.2%，单帧基线均低于 12%
- RoboTwin 2.0 79.4% 对 OpenWAM 69.0%；VLABench 63.3% 对 58.9%
- LIBERO w. OOD 83.5%（π0.5 76.9%），其中 LIBERO-Plus 92.5% 对 85.7%、LIBERO-Para 88.3% 对 71.4%
- RoboDojo 41.46，最强基线 G0.5 为 18.95
- 零样本 pick-and-place：R1 Pro 12/25=48%，R1 Lite 27/50=54%；去掉 ego 数据的 G0.7-Robot 在 R1 Lite 仅 6/50=12%
- Fast 模式 60 ms 每个 16 步 chunk（FP8，单卡 RTX 5090），比 IDM 快 7.6×；BF16 eager 下 156 ms 对 457 ms（2.9×）
- In-context learning：shell game 93.3% ID / 80.0% OOD，sorting by example 93.3% / 66.7%；加 ICL mid-training 后合并 96.7% / 93.3%
- 真实后训练 7 个任务平均任务进度 86.9%（G0.5 64.3%、π0.5 41.7%、OpenWAM 18.6%）

**创新点**

- 相对 Fast-WAM（单帧观测、benchmark 级小规模研究），G0.7 把「测试时不必生成视频」这一结论推到工业规模：上下文从单帧扩到 5 分钟滑窗 KV 并写进预训练，同一份权重同时支持 Fast 与 IDM 两条推理路径，且把人类 ego 视频用 TCP 对齐的末端执行器动作表示并入同一联合目标
- 相对 Long-WAM 等靠 memory 模块或长上下文工程的路线，它不引入额外记忆头，只靠滑窗干净 latent 就获得回合记忆与视频示例式 ICL

**局限与风险**

- 这是工业报告而非受控研究：没有 Fast/IDM 的单因素消融、没有上下文长度（1 帧 / 1 分钟 / 5 分钟）的受控对比，长上下文收益与数据规模收益混在一起
- 预训练语料、模型权重与推理栈均闭源，外部无法复核 70.8 与 86.9% 这些数字
- ego 视频依赖 3D 手部追踪，作者承认手部追踪噪声大的片段只用于视频预测
- 真实后训练每任务约 5 小时数据、少样本工具仅 20 次示范，任务数与 trial 数都偏少，且 RoboDojo 绝对分只有 41.46，说明长程任务仍远未解决
